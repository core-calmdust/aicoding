# ウゴルキ 学習した評価関数（NNUE 風）の学習ツール（Mac）

ウゴルキ AI の評価関数を、自己対局から学習した小さなネットワークにするための一式です。
先生は**サイトのウゴルキ AI 自身**（`ugolki/core.c` の探索 v3 と手作りの評価）で、外部のエンジンは使いません。
自己対局の各局面について「読んだ評価値」と「その対局の勝敗」を記録し、読まなくても同じ判断ができるように学習させます。
ネットはルール（3×3・3×4・4×4・斜めあり）ごとに1つです（陣地の形・手の向き・40手ルールの手数がルールで違うため）。

## 使い方

```bash
cd ~/Documents/GitHub/aicoding
bash ugolki/tools/nnue/run.sh
```

自動で次の順に進みます（途中で止めても、もう一度同じコマンドを実行すれば続きから）。

1. ツールのビルド（`ug`：自己対局・確認・対局、`train`：学習器。どちらも C、追加のインストール不要）
2. 自己対局で学習データ作り（既定 合計 約2000万局面＝1ルール約500万局面。全コアを使用）。40局×コア数ごとに保存
3. 学習（4ルールを同時に、各10エポック）
4. 確認：差分計算の検査（探索中のすべての評価で、手ごとに更新した値と盤全体から計算した値が一致するか）と、
   今の評価関数（手作り）との対局（各ルール 200局、1手 0.1秒、探索 v3 どうし）
5. 勝ち越したルールのネットを `採用` に置いて完了：`~/ugolki-nnue-work/r1/adopt/net-<ルール>.bin.gz` と `RESULT.txt`

必要なもの：Xcode Command Line Tools（`xcode-select --install`）、空き容量 1GB ほど（2000万局面で約 480MB）。

## データを外付けディスクに置く

```bash
WORK="/Volumes/Orico A 8TB/ugolki-nnue" bash ugolki/tools/nnue/run.sh
```

途中から再開するときも同じ `WORK` を指定してください。

## 時間の目安（Mac mini M4 Pro・14コア）

| 段階 | 目安 |
|---|---|
| 自己対局（2000万局面、1手 8千局面読み） | 約 2〜3 時間（1コアあたり毎秒 約200〜300局面） |
| 学習（1ルール 500万局面 × 10エポック、4ルール同時） | 約 10〜20 分 |
| 確認の対局（4ルール × 200局、1手 0.1秒） | 約 10〜15 分 |

ほかの作業で CPU を使うときは `JOBS=8` のように同時に動かす数を絞れます。急ぐときは `POSITIONS=8000000` など。

## 設定（任意）

```bash
POSITIONS=40000000 NODES=12 JOBS=10 bash ugolki/tools/nnue/run.sh
```

| 変数 | 既定 | 内容 |
|---|---|---|
| `WORK` | `~/ugolki-nnue-work` | 作業フォルダ（データ・ネット・ログ） |
| `POSITIONS` | 20000000 | 自己対局の局面数（全ルールの合計。増やして再実行すると追加で作る） |
| `RULES` | `c33 c34 c44 diag` | 学習するルール（例：`RULES=c33`） |
| `NODES` | 8 | 1手に読む局面数（千単位。多いほど教師が正確で、時間がかかる） |
| `JOBS` | 全コア | 同時に動かす数 |
| `EPOCHS` | 10 | 学習の周回数 |
| `LAMBDA` | 0.7 | 教師値の配分（読んだ評価値 × λ ＋ 実際の勝敗 × (1−λ)） |
| `ROUNDS` | 1 | 周回の数。2 以上にすると、前の周の採用ネットを先生にして次のデータを作り（全周のデータで学習）、前の周のネットに勝ったら採用 |
| `MATCH_GAMES` / `MATCH_MS` | 200 / 100 | 確認の対局の局数（ルールごと）と 1手の時間（ミリ秒） |
| `EXTRA` | なし | 学習器への追加オプション（例 `EXTRA="--lr 0.0005 --batch 2048"`） |

周回（ネットで次のデータを作る）の例：1周目が終わったあとで

```bash
ROUNDS=2 bash ugolki/tools/nnue/run.sh
```

1周目はそのまま（終わっていれば飛ばして）、`r2/` に2周目のデータ・ネット・採用ファイルを作ります。

## 終わったら

`$WORK/r<最後の周>/adopt/` の `net-<ルール>.bin.gz` と `RESULT.txt`、`train-<ルール>.log` の最後の数行を Claude に渡してください。
`ugolki/net-<ルール>.bin.gz` に置き、`ugolki/engine.js` の `NETV` にそのルールの版（例 `'1'`）を入れるだけで有効になります
（版が空のルールは今まで通りの手作り評価）。使うのは探索 v3 のレベル（天上）と分析・ヒント・コーチです。

## 採用の基準

- 差分計算の検査で不一致が 0 件（`nncheck`）。
- 同じ持ち時間（1手 0.1秒）の対局で、相手（1周目は手作り評価、2周目以降は前の周の採用ネット）に勝ち越し、
  勝率の片側 95% の下限が 50% を超える（`RESULT.txt` の `-> adopt`）。
- サイトに入れる前に、Claude が WebAssembly（1スレッド・マルチスレッド）で同じ確認をします。

## ファイル

| ファイル | 内容 |
|---|---|
| `run.sh` | 全部まとめて実行 |
| `ug.c` | `ug datagen`（自己対局と記録：序盤 2〜9手はランダム、途中 2% もランダムな手）、`ug nncheck`（差分計算の検査）、`ug match`（対局）、`ug bench`（速さ） |
| `eng.c` | `ugolki/core.c`（サイトの探索そのもの）をネイティブ用に名前を分けて読み込む（2つのエンジンがそれぞれ自分の置換表を持つ） |
| `train.c` | 学習器（入力 140＝自駒64＋相手駒64＋40手ルールまでの残り手数8段階＋手数上限まで4段階、の2視点 → 64 ×2 → 16 → 1、clipped ReLU。正方形の陣地のルールは a1–h8 の対角線で折り返した局面も学習） |

記録の形式（1局面 24バイト）：白の駒 u64、黒の駒 u64、読んだ評価値 i16（手番側から）、手数 u16、結果 i8（手番側から +1/0/−1）、ルール u8、手番 u8、印 u8（評価値が勝ち負けの確定値なら 1）。

ネットのファイル（`UGN1`）：`UGN1`、u16 入力数 140・隠れ層 64・16・ルール、i32 K（評価の尺度：手作り評価と同じ単位に戻す係数）、
続いて int16 W1・B1・W2、int32 B2、int16 W3、int32 B3（すべて整数。WebAssembly とネイティブで同じ値になる）。
