# Model Card: ウゴルキ AI（探索 v3 と学習した評価関数 `net-<ルール>.bin.gz`）

ウゴルキの AI は、探索エンジン `core.c`（WebAssembly：1スレッドの `core-wasm.js`、複数スレッドの `core_mt.wasm`）の αβ 探索に、
形勢の評価を組み合わせています。評価は今は**手作りの評価**（遠い隅までの距離の和・遅れた駒・自陣の残り）で、
**学習した評価関数（ルールごとの小さなネット）の仕組み**を 2026-11-20 に入れました（ネットの学習本番はこれから。下の「Mac での学習」）。

- **ゲーム**: https://core-calmdust.github.io/aicoding/ugolki/
- **バージョン**: 探索 v3（2026-11-20）。学習した評価：ネット未配置（`engine.js` の `NETV` がすべて空＝手作り評価）
- 仕様の詳細：`claude/ugolki-spec.md`「探索 v3・学習した評価の仕組み・定跡の拡充」

人が遊ぶレベル（Lv.1〜23）の強さは変えていません（同じ手・同じ局面数になることを 4ルール・2,700回の探索で確認）。

## 探索 v3
v2（ヌルムーブ・LMP・LMR・フューティリティ・ヒストリー・IIR、2026-11-13）に足したもの：
- 探索をまたいで残る置換表（4項目のバケツ・世代つき。前は60万件で全部消していた）
- ルートの PVS と aspiration window（±40、外れたら2倍）

局面数固定では全ルールで勝ち越し（3×4 は引き分けが多く誤差の内）。時間固定でも勝ち越すが差は小さく、読みが深いほど縮む。
部品ごと（1手2万局面）：置換表 +7、aspiration +35（どちらも誤差の内）。天上の基準値は据え置き（ネットを入れたら測り直す）。

## 学習した評価関数（仕組み）
| 項目 | 内容 |
|---|---|
| 入力 | 140＝自分の駒64＋相手の駒64＋40手ルールまでの残り手数（8段階）＋手数の上限まで（4段階）。白の目と黒の目（盤を180°回して同じ隅を目指す形）の2組 |
| 構造 | 140 → 64（2視点、手番側が先）→ clipped ReLU → 16 → clipped ReLU → 1。ルールごとに1つ（陣地の形・斜めの手・40手ルールの手数が違うため） |
| 数値 | すべて整数（int16 の1層目、int32 の和）。WebAssembly とネイティブで同じ値。1層目は差分更新（指した手の2マス分だけ足し引き） |
| 出力 | ロジット × K（K はデータから求める評価の尺度。手作り評価と同じ単位になり、探索の枝刈りの幅がそのまま使える） |
| ファイル | `UGN1`（約22KB、gzip 後 約10KB 前後）。`ugolki/net-<ルール>.bin.gz` に置き、`engine.js` の `NETV` に版を入れると有効 |
| 学習データ | このエンジン自身の自己対局（探索 v3・手作り評価、1手8千局面、序盤2〜9手ランダム・途中2%ランダム）。外部のエンジンは使わない |
| 教師 | 0.7 × σ(探索値 / K) ＋ 0.3 × 勝敗。正方形の陣地のルール（3×3・4×4・対角）は a1–h8 の対角線で折り返した局面も学習 |
| 学習器 | `tools/nnue/train.c`（C、Adam、検証用 3%） |

### 作業機での仮ネットの確認（採用しない）
3×3 の自己対局 約20万局面（1手5千局面）で 12エポック学習した仮ネット。**サイトには置いていません**（学習本番は Mac）。
| 確認 | 結果 |
|---|---|
| 差分更新と盤全体からの計算の一致（`ug nncheck`、探索中の全評価） | 不一致 0（130万回以上） |
| 量子化（整数）と float の差 | 平均 4.4（評価の単位。歩1マス＝34） |
| 勝敗の予測（検証局面の交差エントロピー） | 仮ネット（読まずに）0.524、先生の探索値 0.565 |
| 仮ネット 対 手作り評価（探索 v3 どうし、1手2万局面、100局） | +96 −3 =1（+576 Elo） |
| 同じ持ち時間（1手50ms、40局） | +37 −1 =2（+512 Elo） |
| Node（wasm）の対局（1手2万局面、10局） | +9 −1 |
| ブラウザ（headless Chrome、分離あり・2スレッドの core_mt.wasm）で天上Ⅰの手・分析 | 動作（`nn: 1`）、エラーなし |

小さなデータでもこれだけ差が出るので、Mac の本番（約2000万局面）のネットは天上と分析を大きく強くする見込み。

## 推論の高速化（2026-11-20、値は同じ）

- **wasm SIMD の `nnEval`**（`core.c`）：1層目は中間層＋2つの手数の行を int32 のレーンで足し（前の int の和と同じ）、0〜127 に切って int16 に詰め、2層目の 16 個の和を `i32x4.dot_i16x8` で（整数なので同じ）。ネイティブは前のループ。差分更新は前からコンパイラが SIMD にしている。
- **確認**：`ug nncheck`（差分更新の一致、仮ネット c33）、旧版と新版の探索（v3＋ネット、局面数で決める探索、12局面×3）が一致、`tools/check_ab.js`（旧版と core-wasm.js・core_mt.wasm 1スレッドの848探索がネットなし・ありで一致）、ブラウザ（headless Chrome、仮ネットを置いて）で Lv.21 が1スレッド・マルチスレッドともネットで動作。
- **速さ**（wasm SIMD、同じ探索を旧・新交互に同じプロセスで、CPU 時間）：ネットあり **約 1,230k → 1,870k 局面/秒（+50%）**、ネットなしの約 0.53 倍 → 0.80 倍。ネットなしは同じ。
- **時間固定の対局**（wasm、1手50ミリ秒、v3＋仮ネット対 v3 手作り評価、c33、仮ネット＝自己対局 約2.4万局面）：仮ネットが強すぎて両方ほぼ全勝（旧 +37 −0 =3、新 +39 −0 =1、各40局）で差は測れない。同じ時間での平均の深さは 8.87 → 9.23 手。

## Mac での学習（`ugolki/tools/nnue/`）
```bash
bash ugolki/tools/nnue/run.sh                                   # 既定：約2000万局面（1ルール500万）
WORK="/Volumes/Orico A 8TB/ugolki-nnue" bash ugolki/tools/nnue/run.sh   # データを外付けに
ROUNDS=2 bash ugolki/tools/nnue/run.sh                          # 2周目（1周目のネットを先生に）
```
ビルド → 全コアで自己対局 → 学習（4ルール同時）→ 確認（差分更新の検査、手作り評価との対局）→ 採用ファイル（`$WORK/r1/adopt/`）。
途中で止めても続きから。時間の目安（M4 Pro 14コア）：自己対局 約2〜3時間、学習 約10〜20分、確認 約10〜15分。手順の詳細は `tools/nnue/README.md`。

## 採用の基準
1. 差分更新の検査で不一致 0。
2. 同じ持ち時間（1手 0.1秒、探索 v3 どうし）で今の評価（1周目は手作り、2周目以降は前のネット）に 200局で勝ち越し、勝率の片側95%の下限が 50% を超える（`run.sh` が `-> adopt` と書いたルールだけ）。
3. サイトに入れる前に WebAssembly（1スレッド・core_mt.wasm）で読み込み・対局を確かめ、天上の基準値（`RT_LV` の 24〜26、大百科の RATING）を測り直す。トップページの紹介文に「NNUE搭載」と学習量を書く（共通ルール）。
