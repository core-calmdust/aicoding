# リバーシの定石（book.bin）を Mac で大きく作る手順

`book-gen.js` は、初期局面から定石の木を広げながら、各局面のすべての手を深い探索（ゲームと同じ `engine.wasm`、Multi-ProbCut あり）で読み、
最後に木をたどって評価値を negamax で戻して `reversi/book.bin` を作ります。

- 1局面ずつ置換表を空にして、時間制限なしの固定深さで読むので、**同じ設定なら何度やっても同じ結果**になります（`verify` で確認できます）。
- 読み終わった局面は1行ずつ `book-work/nodes.jsonl` に書き足すので、**いつ止めても同じコマンドで続きから再開**できます。
- 1手目から順に（幅優先で）広げます。最善から `--window` 石以内の手の先を読み、片方の手番の損の合計が `--err` 石を超える変化は打ち切り、
  1手ごとの局面数は `--cap` まで（損の少ない順）。本線ほど深く（`--max-ply` まで）、脇道は浅くなります。
- 今の book.bin（このリポジトリにあるもの）は、作業環境（2コア・他の作業と共用）で `--depth 16 --max-ply 22 --cap 200` で作った小さめのものです。

## 1. 準備（最初の1回）

```sh
node -v          # v18 以上（なければ: brew install node）
cd ~/Documents/GitHub/aicoding
git pull         # （GitHub Desktop の Fetch / Pull でも可）
cd reversi/tools
```

## 2. 生成を始める

おすすめ（M4 Pro / Mac mini、一晩〜数日）：

```sh
caffeinate -i node book-gen.js run --depth 20 --max-ply 26 --cap 3000 --err 4 --window 3 --keep 3
```

- `caffeinate -i` は実行中に Mac がスリープしないようにするコマンドです（ふたを閉じる MacBook は電源につないだまま）。
- スレッド数は自動（CPU コア数 − 1）。ほかの作業もしたいときは `--threads 8` のように減らしてください。
- 画面に「◯手目: 読んだ数/その手目の数、1局面あたりの秒数、その手目の残り時間」が出ます。
- 作業フォルダは `reversi/tools/book-work/`（`--dir` で変更可）。設定は `book-work/config.json` に保存されます。

### 時間の目安

1局面の時間は深さ2手ごとに約3倍になります。この作業環境（2コアを共用）では深さ16で1局面あたり約3秒/スレッドでした。
M4 Pro の1コアはおよそその2〜3倍速いので、深さ20で 1局面 約10〜20秒/スレッド、12スレッドで1時間に約2,000〜4,000局面が目安です。

| 設定 | 局面数の目安 | M4 Pro（12スレッド）の目安 |
|---|---|---|
| `--depth 18 --max-ply 24 --cap 1000` | 約2万 | 2〜4時間 |
| `--depth 20 --max-ply 26 --cap 3000`（おすすめ） | 約6〜7万 | 1〜2日 |
| `--depth 22 --max-ply 26 --cap 3000` | 約6〜7万 | 4〜6日 |

最初の数十分の「1局面あたりの秒数」から全体の時間を見積もれます。浅い手目ほど局面が少ないので、最初は速く進みます。

## 3. 止める・再開する

- **止める**：`Ctrl-C`（読み途中の局面だけ次回やり直し。もう一度押すとすぐ終了）。ターミナルを閉じても、Mac を再起動しても大丈夫です。
- **再開**：同じフォルダで同じコマンドをもう一度。終わった局面は読み直しません。
- **途中で広げる**：`--max-ply` `--cap` `--err` `--window` は再開のときに大きくしてかまいません（読んだ局面はそのまま使い、足りない局面だけ読みます）。
  `--depth` と `--keep` は途中で変えられません（変えるときは `--dir book-work-d22` のように別のフォルダで）。
- **進み具合**：`node book-gen.js status`（局面数・手目ごとの数・使った時間）。

## 4. book.bin を作って確かめる

```sh
node book-gen.js build          # → reversi/book.bin（途中でも作れます。容量・局面数・初期局面の評価を表示）
node book-gen.js verify --n 8   # 8局面を読み直して、結果が完全に一致するか確認
```

`build` の表示の「gzip ◯ KB」が Web で読み込む大きさの目安です（2MB 以下を目安。超えるときは `--out-window 2` で狭くできます）。

## 5. 結果を送る

どちらか1つで大丈夫です。

1. **GitHub Desktop**：`gzip -k book-work/nodes.jsonl` を実行してから、GitHub Desktop で新しいブランチ（例 `book-run-1`）を作り、
   `reversi/tools/book-work/nodes.jsonl.gz`・`reversi/tools/book-work/config.json`・`reversi/book.bin` をコミットして Push。ブランチ名を教えてください。
   （`nodes.jsonl` そのものは .gitignore で除外しています。`nodes.jsonl.gz` は数MB程度です）
2. **Hugging Face**：`nodes.jsonl.gz` と `config.json` をアップロードして URL を教えてください。

`nodes.jsonl.gz` があれば、こちらで book.bin を作り直したり（窓の幅を変える等）、対局で強さを測ったりできます。
`nodes.jsonl.gz` を作業フォルダに置いたまま `run` すると、その続きから読み進めます。

## 参考：そのほかのオプション

| オプション | 既定 | 意味 |
|---|---|---|
| `--depth` | 22 | 中盤の読みの深さ（固定） |
| `--exact` | 0 | 残りこのマス数以下は完全読み（定石の範囲では通常不要） |
| `--keep` | 4 | 最善からこの石数以内の手の評価値を正確に求めて保存（それより悪い手は捨てる） |
| `--window` | 3 | 最善からこの石数以内の手の先を定石に加える |
| `--err` | 4 | 片方の手番の損の合計がこの石数を超えたら打ち切り |
| `--cap` | 3000 | 1手ごとの局面数の上限 |
| `--max-ply` | 24 | 何手目まで広げるか |
| `--seed` / `--seed-ply` | なし / 99 | 必ず含める局面（JSON の定石。例：旧 book.json）とその手数の上限 |
| `--threads` | コア数−1 | 同時に読むスレッド数 |
| `build --out-window` | 3 | book.bin に入れる手の幅（最善からの石数。定石の局面へ進む手は幅の外でも入れます） |

AI は最善から 0.8 石以内の手から選ぶ（Lv.15〜20・PRO の定石オン）ので、定石の中でも毎回同じ手順にはなりません。
分析は、定石の局面では定石の評価値（深い読みを木で戻した値）を表示します。

対局での比較（新旧の定石・同じエンジン・同じ設定、初期局面から）：
`node book-match.js ../book.bin <比べる定石> 100 out.jsonl 15`（100組＝200局、先後入れ替え）。
