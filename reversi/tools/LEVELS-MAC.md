## 1. ベンチ（reversi/bench.html）
- 対局ページと同じ仕組み（`sw.js` の Document-Isolation-Policy で分離、`mt-worker.js` ＋ `engine_mt.wasm` の YBW 分割探索）で、1・2・4・8・10・14 スレッドの速さを測ります。
- 中盤：残り36マスの8局面を1局面3秒ずつ読み、nps（全スレッドの合計）・届いた深さ・**全スレッド数が届いた共通の深さまでの時間**・その深さでの最善手の一致（1スレッドと比べて）。
- 終盤：残り24マスの8局面の完全読みの時間と石差（どのスレッド数でも一致するはず）。
- 画面の上に `crossOriginIsolated`（true でないとスレッドを使えない）と、実際に起動したスレッド数が出ます。

## 2. レベル対局（reversi/tools/levelmatch.js、Node）
- 対局ページの AI と同じ読み方を Node の worker_threads で再現します。**Lv.17〜29 は全スレッド**（Lv.17〜28 は深さが決まっているので、スレッドは速さだけに効く）（`engine_mt.wasm` を共有メモリで、補助スレッドは主の分割点の残りの手を取る YBW。対局ページの `MT_CFG` と同じ）、**Lv.14〜16 は1スレッド**（対局ページも1スレッドのワーカーで打つため）。先手・後手それぞれが自分のスレッドの組と置換表を持ちます。
- 既定は **2局を同時 × 1局あたり7スレッド**（14コアを使い切る。対局ページは8スレッドなので、ほぼ同じ条件）。ページとまったく同じ8スレッドで1局ずつにしたいときは `--conc 1 --threads 8`（時間は約2倍）。
- 開始局面：定石（`book.bin`）をランダムにたどって（各手は最善から0.8石以内、レベルが実際に打つのと同じ）、**定石が終わった局面**から。20局面 × 先後入れ替えの2局。どの対局の組も同じ20局面を使います。
- `--plan full`（各40局）：
  - 隣どうし：Lv.14↔15 … 19↔20、20↔21 … 28↔29
  - 時間2倍の梯子（Lv.20 の形のまま目安の時間だけ 2秒↔4秒、4↔8、8↔16）→ **本番の時間で時間2倍あたり何 Elo か**
- `--plan depth`（2026-11-11、各40局）：Lv.16↔17 … 28↔29 の隣どうし13組と Lv.26↔28・27↔29。`--plan top`：Lv.25↔26 … 28↔29 の4組と Lv.26↔28・27↔29。
- 自分で設定を試すとき：`D<深さ>m<深さ2>e<完全読み>w<勝敗読み>n<百万局面>` の選手（例 `--plan L28:D30e24w26,D30e24w26:L29`。`m` は局面の半分ほどを深さ2で読む＝`engine.js` の `mix`）。`n` の局面数の上限は主スレッドの局面数だけで数えます（補助スレッドの分は足されない）。
- 1局ごとに結果を追記し、毎局その時点の表（勝敗・Elo ±1σ・1手の平均と最長の秒数・深さ・nps）を表示します（`report.txt` にも保存。どちらも Git には入りません）。
- report の最後に **「ladder (Lv.14 = 1810)」** の行が出ます：Lv.14（固定の基準）から隣どうしの結果を積み上げた各レベルの Elo と、そこから計算したレーティング戦の基準値の案（R = 50 + 0.77 × Elo）。

### 時間の目安（14コアの Mac、2局同時）
| コマンド | 内容 | 見込み |
|---|---|---|
| `node tools/levelmatch.js --plan depth` | Lv.16〜29 の隣どうし13組＋1つ飛ばし2組（各40局） | 約3〜5時間 |
| `node tools/levelmatch.js --plan top` | Lv.25〜29 の隣どうし4組＋1つ飛ばし2組 | 約1.5〜3時間 |
| `node tools/levelmatch.js --plan full` | Lv.14〜29 の隣どうし15組＋時間2倍3組 | 約6時間 |
| `node tools/levelmatch.js --plan ladder` | 時間2倍の梯子だけ（2↔4、4↔8、8↔16秒） | 約3時間 |

見込みは最初は1手あたりの想定時間から、対局が進むと実際にかかった時間から出し直します。`--plan L27:L29,T4:T16` のように組を自分で並べることもできます（L14〜L29、T<秒>、D…）。

### --scale について
`--scale 0.5` は全レベルの目安の時間と上限（`time`・`max`）を同じ割合で縮めます（Lv.17〜28 は深さで止まるので、遅い端末向けの見張りの時間が縮むだけで、ふつうは変わりません）。中盤の読みはおおむね同じ比で縮みますが、終盤の完全読み・勝敗読みの深さ（マス数）はそのままなので、終盤の比重が少し変わります。**できれば 1.0（本番）**。倍率の違う結果は別々に集計されます（混ざりません）。
