# リバーシ 上位レベルの計測（Mac・全スレッド・実際の持ち時間）

Lv.14〜25 の強さ（レーティング戦の基準値 `RT_LV`・大百科の `RATING`）を、作業環境（2コア共用）の短い対局からの外挿ではなく、Mac の全コア・本番の持ち時間で測って決め直すための手順です。
2026-11-10 版：対局ページと同じ **YBW の分割探索（`engine_mt.wasm` v4.1）** で対局し、Lv.14〜20 も含めた梯子全体を一度に測れるようにしました（`--plan full`）。
Lv.1〜13 は運で打つレベルなので、この作業環境で `tools/match.js` 系の対局で測っています（MODEL_CARD.md「やさしいレベル」）。

## 1. ベンチ（reversi/bench.html）
- 対局ページと同じ仕組み（`sw.js` の Document-Isolation-Policy で分離、`mt-worker.js` ＋ `engine_mt.wasm` の YBW 分割探索）で、1・2・4・8・10・14 スレッドの速さを測ります。
- 中盤：残り36マスの8局面を1局面3秒ずつ読み、nps（全スレッドの合計）・届いた深さ・**全スレッド数が届いた共通の深さまでの時間**・その深さでの最善手の一致（1スレッドと比べて）。
- 終盤：残り24マスの8局面の完全読みの時間と石差（どのスレッド数でも一致するはず）。
- 画面の上に `crossOriginIsolated`（true でないとスレッドを使えない）と、実際に起動したスレッド数が出ます。

## 2. レベル対局（reversi/tools/levelmatch.js、Node）
- 対局ページの AI と同じ読み方を Node の worker_threads で再現します。**Lv.17〜25 は全スレッド**（`engine_mt.wasm` を共有メモリで、補助スレッドは主の分割点の残りの手を取る YBW。対局ページの `MT_CFG` と同じ）、**Lv.14〜16 は1スレッド**（対局ページも1スレッドのワーカーで打つため）。先手・後手それぞれが自分のスレッドの組と置換表を持ちます。
- 既定は **2局を同時 × 1局あたり7スレッド**（14コアを使い切る。対局ページは8スレッドなので、ほぼ同じ条件）。ページとまったく同じ8スレッドで1局ずつにしたいときは `--conc 1 --threads 8`（時間は約2倍）。
- 開始局面：定石（`book.bin`）をランダムにたどって（各手は最善から0.8石以内、レベルが実際に打つのと同じ）、**定石が終わった局面**から。20局面 × 先後入れ替えの2局。どの対局の組も同じ20局面を使います。
- `--plan full`（各40局）：
  - 隣どうし：Lv.14↔15、15↔16、16↔17、17↔18、18↔19、19↔20、20↔21、21↔22、22↔23、23↔24、24↔25
  - 時間2倍の梯子（Lv.20 の形のまま目安の時間だけ 2秒↔4秒、4↔8、8↔16）→ **本番の時間で時間2倍あたり何 Elo か**
- 1局ごとに結果を追記し、毎局その時点の表（勝敗・Elo ±1σ・1手の平均と最長の秒数・深さ・nps）を表示します（`report.txt` にも保存。どちらも Git には入りません）。
- report の最後に **「ladder (Lv.14 = 1810)」** の行が出ます：Lv.14（固定の基準）から隣どうしの結果を積み上げた各レベルの Elo と、そこから計算したレーティング戦の基準値の案（R = 50 + 0.77 × Elo）。

### 時間の目安（14コアの Mac、2局同時）
| コマンド | 内容 | 見込み |
|---|---|---|
| `node tools/levelmatch.js --plan full` | 梯子全体（隣どうし11組＋時間2倍3組、各40局） | 約9時間 |
| `node tools/levelmatch.js --plan full --games 20` | 同じ組を各20局（誤差は約1.4倍） | 約4.5時間 |
| `node tools/levelmatch.js --plan low` | Lv.14〜20 の隣どうしだけ（6組） | 約1時間 |
| `node tools/levelmatch.js` | 前回と同じ（Lv.20〜25 の隣どうし＋時間2倍） | 約8時間 |
| `node tools/levelmatch.js --plan adjacent` | Lv.20〜25 の隣どうしだけ | 約6.5時間 |

見込みは最初は1手あたりの想定時間から（多めに出ます。前回の実測は Lv.20 で1手平均1.0秒）、対局が進むと実際にかかった時間から出し直します。`--plan L23:L25,T4:T16` のように組を自分で並べることもできます（L14〜L25 と T<秒>）。

### --scale について
`--scale 0.5` は全レベルの目安の時間と上限（`time`・`max`）を同じ割合で縮めます。中盤の読みはおおむね同じ比で縮みますが、終盤の完全読み・勝敗読みの深さ（マス数）はそのままなので、終盤の比重が少し変わります。**できれば 1.0（本番）**。倍率の違う結果は別々に集計されます（混ざりません）。
