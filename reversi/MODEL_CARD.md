# Model Card: Reversi V4 Pattern Evaluation (`weights.bin.gz`)

Reversi V4 の AI が局面の良し悪しを判断するための評価関数（学習済み重み）です。
探索エンジン `engine.js` と組み合わせて、ブラウザ上で動作します。

- **ゲーム**: https://core-calmdust.github.io/aicoding/reversi/
- **作成**: core-calmdust（AIコーディングによる制作）
- **バージョン**: v3（2026-10-18）

## モデル概要

| 項目 | 内容 |
|---|---|
| 種類 | パターンベースの線形評価関数（Logistello / Edax 系の古典的手法）＋着手可能数特徴 |
| 入力 | 手番側から見た盤面（自石 / 相手石 / 空き の3値 × 64マス） |
| 出力 | 手番側から見た予想最終石差（1/32 石単位の整数） |
| パターン | 15種類・対称形を含め計62インスタンス（下表。v3で10マスのパターンを4種追加） |
| 追加特徴 | 手番側の着手可能数、相手の着手可能数、両者の潜在的着手可能数（空きマスに接する相手石・自石の数）。各0〜63をテーブル引きで評価 |
| フェーズ | 手数に応じて30段階（2手ごと）に重みを切り替え |
| パラメータ数 | 30 フェーズ × 403,718 = 12,111,540（Int16） |
| ファイルサイズ | 約24.2MB（gzip圧縮後 約7.8MB） |

### パターン一覧

| 名前 | マス | 対称形の数 |
|---|---|---|
| corner3x3 | a1 b1 c1 a2 b2 c2 a3 b3 c3 | 4 |
| corner2x5 | a1 b1 c1 d1 e1 a2 b2 c2 d2 e2 | 8 |
| edge2x | a1〜h1 + b2 g2 | 4 |
| hv2 / hv3 / hv4 | 2・3・4段目の横一列 | 各4 |
| diag8 〜 diag4 | 長さ8〜4の斜め列 | 2〜4 |
| triangle（v3） | a1 b1 c1 d1 a2 b2 c2 a3 b3 a4 | 4 |
| cornerBlock（v3） | a1 c1 d1 e1 f1 h1 c2 d2 e2 f2 | 8 |
| diag8c（v3） | a1〜h8の対角線 + b1 a2 | 4 |
| narrowTri（v3） | a1 b1 c1 d1 e1 a2 b2 a3 a4 a5 | 4 |

評価値 = Σ（各インスタンスの状態に対応する重み）+ バイアス。
対称形どうしは同じ重みテーブルを共有します。

## 学習データ

1. 局面と評価値のペア（Egaroucid 7.4.0 / 7.5.1 Lv.17）：**約2,551万局面**。評価値をそのまま教師値に使用
2. 対局棋譜（Egaroucid 7.8.0 Lv.11 対 Edax 4.5.5 Lv.11、ランダム序盤8〜20手）：**約195万局**から、ランダム部分を除いた局面の25%を抽出（**約2,235万局面**）。終局時の石差を教師値に使用

合計 **約4,786万局面**。

- データの利用規約に従い、データそのものはこのリポジトリに含めていません（再配布禁止のため）。
- 公開しているのは、データから学習した重みのみです。
- 素晴らしいデータを公開してくださっている Egaroucid 作者の山名琢翔さんに感謝します。

## 学習方法

- フェーズごとに、前後1手を含む局面（各フェーズ最大約400万局面）で最小二乗回帰。
- 特徴ごとの出現回数で正規化した勾配法を300反復。学習率は誤差が増えたら減衰。
- 2% の局面をテスト用に除外。
- 序盤の最初の3フェーズ（0〜5手）はデータが極端に少ないため、6〜7手目のフェーズの重みを流用。

### v4（2026-11）：対局棋譜を大幅に追加
v3 の重みから始めて、`tools/train/rvtrain`（C、マルチスレッド）で学習し直しました。
- データ：局面と評価値のペア 約2,550万（上と同じ）＋ 対局棋譜 **約5,200万局**（Egaroucid 7.8.0 Lv.11 対 Edax 4.5.5 Lv.11、ランダム序盤8〜59手。ランダム部分を除き、各局の局面を2割抽出）。1フェーズあたり最大約4,200万局面（前後1手を含む）。
- 検証誤差（RMSE、石）：v3 → v4 で、例えば 16〜19手 8.11→8.01、32〜35手 7.26→6.86、40〜43手 6.71→6.30、52〜55手 6.06→5.79。
- Egaroucid for Web（最強のレベル15）との自動対局（序盤2手ランダム・先後入れ替え48局、同じ序盤）：v3 は 24勝6分18敗 → 2セット合計で勝率61.5% だった条件で、**v4 は 32勝6分10敗（勝率73%、平均+3.0石）**。

### 対戦評価（v3 と v2 の比較）

同じ探索エンジン（Multi-ProbCut あり）で、ランダムな8手の序盤から先後入れ替えて対戦。

| 条件 | 対局数 | v3 の勝率 | 平均石差 |
|---|---|---|---|
| 1手0.3秒 | 120 | 54.2% | +1.5 |
| 1手1秒 | 60 | 55.0% | +0.5 |

テスト誤差（RMSE）は同じフェーズで約0.1石改善（例：31〜32手目 6.84→6.74、45〜46手目 6.64→6.53）。

### 対戦評価（v2 と v1 の比較）

v1（15フェーズ・パターンのみ・局面ペアのみで学習）と、同じ探索エンジンで対戦（ランダムな8手の序盤から先後入れ替え）。

| 条件 | 対局数 | v2 の勝率 | 平均石差 |
|---|---|---|---|
| 探索深さ4固定 | 200 | 57.0% | +1.9 |
| 1手0.15秒 | 120 | 48.8% | −0.6 |
| 1手0.6秒 | 60 | 57.5% | +1.4 |

追加特徴の計算で1局面あたり約2割遅くなるため、持ち時間が極端に短いと差が出ませんが、読みが深くなるほど評価精度の向上が効いてきます（ゲームの Lv.17〜20 は1手1.5〜5秒）。

比較のために学習した派生版の結果も記録しておきます。
- 局面ペアのみ・追加特徴あり・30フェーズ：v1 に対し 1手0.15秒で 51.7%
- 局面ペア＋棋譜・追加特徴なし・30フェーズ：v1 に対し 1手0.15秒で 56.3%、v2 に対し 1手0.6秒で 44.2%

## 探索の高速化（2026-11）
中盤の探索（PVS・パターン評価の差分計算・Multi-ProbCut・置換表）と終盤の完全読みを C に移し、WebAssembly で動かすようにしました（`engine.c`、`tools/build-wasm.sh` で `engine-wasm.js` / `engine.wasm` を生成）。
盤面は64ビットのビットボード、着手可能手と裏返る石はシフト演算でまとめて求めます。手の順番・置換表・時間切れの判定まで engine.js と同じ処理なので、読む局面と結果は従来と完全に一致します（ランダムな14局面 × 3設定、深さ指定・完全読みを含めて一致を確認）。
速さはブラウザで約2.5倍（初期局面・深さ11：121ms → 48ms）、Node で約2.6倍。時間で区切るレベル（Lv.15〜20）と検討は、同じ時間でより深く読みます。WebAssembly が使えない環境では従来の JavaScript の探索で動きます。
終盤はさらに、確定石による上限の枝刈り・残り1マスの専用計算・相手の石に接しないマスの除外を入れ、完全読みが約25%速くなりました（結果は同じ）。
Lv.17〜20 は完全読みの手前（Lv.20 は残り22マス、Lv.17〜19 は20〜21マス）で勝ち・引き分け・負けだけを判定する読みを行い、勝てる手があればそれを打ちます（同じ持ち時間の範囲内）。

2026-11 にさらに高速化しました（読む局面と結果は変わらず、局面数まで一致）：着手可能手の計算を Kogge-Stone 法にし、WebAssembly の SIMD で盤とその上下反転を1命令で並べて6方向を同時に計算。裏返る石は方向ごとのマスクと繰り上がり・先頭ゼロの計算でループなしに求め、最後の1マスは行・列・斜めの4本を8ビットに集めた表引きで数えるだけにしました。パターンの添字は16ビットで持ち、子局面へのコピーをベクトル単位に。象限ごとの空きマスの偶奇は折りたたみで一度に計算します。Node の CPU 時間で中盤（深さ15）約1.4倍、終盤の完全読み（残り19マス）約1.2倍速くなりました。SIMD に対応していないブラウザ（Safari 16.3 以前など）では従来の JavaScript の探索で動きます。

Egaroucid for Web（最強のレベル15、定跡あり）との自動対局（Node、1スレッド。序盤6手ランダム・先後入れ替え48局）：Lv.20 は 29勝2分17敗 → 改良後 27勝4分17敗（どちらも勝率60%）。序盤2手ランダム（定跡がほぼ効く条件）では 24勝6分18敗（56%）。

## 最強解析（複数スレッド、2026-11）
- `pro/`：PC の複数の CPU コアで同時に読む解析ページ。対局ページの棋譜欄の「最強解析」ボタンから、表示中の局面を新しいタブで開きます（標準の初期配置からの対局は手順ごと、それ以外は局面だけ）。
- エンジンは同じ `engine.c` を `-DMT` で作った `engine_mt.wasm`（`tools/build-wasm.sh` の最後の行）。共有メモリの上で、置換表・重み・表を共有し、探索の作業領域はスレッドごと（`TLS`）。探索の外側（反復深化・ルートの手の並べ替え）は各スレッドの `engine.js` が受け持ちます。通常版の `engine.wasm` は変わりません。
- 共有メモリ（SharedArrayBuffer）にはページの「クロスオリジン分離」が必要です。GitHub Pages ではヘッダーを設定できないため、`pro/coi-sw.js`（Service Worker）が `pro/` の中だけ COOP / COEP を付けます。対局ページ（オンライン対戦・ログイン）は対象外で影響しません。分離できないブラウザでは、通常のエンジン（1スレッド）で動きます。
- 補助スレッドはルートで別の手から読み始めます（`opts.rot`）。全スレッドが同じ順で読む素朴な方式では速くならず（深さ16までの時間 1.01倍）、1手深く始める方式も効果なし。ルートの手をずらすと 2スレッドで深さ16まで約1.29倍速くなりました（ランダム10局面、Node）。
- 設定：中盤は深さ制限なし・残り22マスで完全読み・24マスで勝敗読み（レベル20より少し早め）。評価値は黒から見た石差。


## 本編のマルチスレッド（2026-11-08）
- 対局ページでも `engine_mt.wasm` の複数スレッドを使います（共通部品 `shared/mtengine.js`・`shared/mt-sw.js`、addendum「本編のマルチスレッド」）。オフライン用の `sw.js` に組み込み、ページに `Document-Isolation-Policy` を付けます（Chrome / Edge の PC は COOP なしで分離、ログイン・オンライン対戦はそのまま）。Safari・Firefox などはオプション「マルチスレッド」で COOP / COEP モード（その間ログイン・オンライン対戦は停止）。スマホはオンにするまで1スレッド。
- 各スレッドは `mt-worker.js`（`engine.js` を共有メモリの `engine_mt.wasm` の上で動かす。主スレッドは通常のワーカー API、補助はルートの別の手から読む `opts.rot`）。
- 対象：分析・ヒント、コーチの深い読み（Lv.17）、検討ボックス、AI の Lv.17〜20（時間で考えるレベル）を**レート戦以外**で。レート戦はこれまでどおり（Lv.17〜20 は4コア以上でルート分割の並列探索、それ以外は1スレッド）。
- 計測（この作業環境：2 vCPU の Linux・headless Chromium 153。独立した2ワーカーでも合計速度は1.37倍どまりのため、深さの伸びはほぼ出ない）：Lv.20・残り38マスの1手で 1スレッド 約312万 nps → 2スレッド合計 約318万 nps（深さ 20 / 19）。複数コアの PC での効果は上の最強解析の計測（2スレッドで深さ16まで約1.29倍速）が目安です。

## レーティング戦（ひとりで遊ぶレート対局）のレーティング表

新しい対局の「レーティング戦」では、各AIレベルに固定のレーティングを割り当て、プレイヤーのレーティング（端末ごとに保存、`localStorage` の `reversi-rated-v1`）とのElo計算で増減させます。オンライン対戦のレーティングとは別物です。

AIの強さは20段階です（v4.1 で10段階から細分化。旧 Lv.1〜10 は新 Lv.4・7・9・11・13・14・16・17・19・20 と同じ設定で、保存済みの設定は自動で移行します）。

### レベル同士の対戦による実測Elo

レーティング戦のRは、実測Eloを 50 + 0.77 × Elo に換算した値です（旧10段階のときの値 400〜1800 とおおむね同じ尺度になるよう合わせています。人間のレーティングとの対応は目安です）。

- プレイヤーの初期値は 1000。K = 48（最初の10局）、以降 K = 24。期待勝率は 1 / (1 + 10^((相手R − 自分R) / 400))。
- 相手の選び方：目標 = 自分のR + ずらし幅（80%は ±100 以内、10%は +150〜+300 の格上、10%は −150〜−300 の格下）に最も近いレベル。開始時に相手のレベルとR（格上／互角／格下）を表示。
- ルール：黒白ランダム・持ち時間はプレイヤー側のみ10分＋秒読み30秒（AIの思考時間は計測しません。パスで手番が戻ったときは新しい1手として秒読みがリセット）。待った・ヒント・コーチ・形勢表示・分析は終局まで使用不可（「待った」ボタンは「投了」になります）。投了・時間切れ・中断（対局中に別の対局／レッスン／詰めオセロ／棋譜読込／オンラインへ移る）は負け、引き分けは0.5。再読み込みすると続きから再開し（時計は再読み込み中も進み続けます。棋譜を戻して見ている間も止まりません）、結果は対局IDで1回だけ記録されます。
- Lv.15〜20 は思考時間で強さが決まるため、端末の速さによって実際の強さが多少上下します。

## 制約・注意点

- 線形のパターン評価のため、ニューラルネット系の最強クラスAI（Egaroucid、Edax の上位設定など）には及びません。
- 序盤の最初の数手はデータが少なく、評価がやや粗くなります。
- 評価値はあくまで推定で、終盤の完全読み以外は正確な石差を保証しません。

## ファイル形式と読み込み方

- `weights.bin.gz`: gzip 圧縮された Int16（リトルエンディアン）の配列。
  フェーズ順に `PHASE_SIZE`（v3 = 403,718）個ずつ並ぶ。各フェーズ内は「パターンの重みテーブル（403,461）→ 追加特徴4種×64 → バイアス1」の順。エンジンは1フェーズあたりのサイズから v1/v2/v3 を自動判別します。
- `weights.json`: `{"nphase": 30}` などのメタ情報。
- 各パターンの重みテーブル内の位置は、マスの状態（空き=0 / 手番側=1 / 相手=2）を3進数として読んだ値です。

```js
const buf = await (await fetch('weights.bin.gz')).arrayBuffer();
const raw = await new Response(new Blob([buf]).stream().pipeThrough(new DecompressionStream('gzip'))).arrayBuffer();
ReversiEngine.setWeights(new Int16Array(raw), 30); // 1フェーズあたりのサイズから v1/v2 を自動判別
```

詳しくは同じフォルダの `LICENSE` を参照してください。

## 対局設定の Pro モード（2026-11-08）
対局設定の「AIの強さ」の PRO ボタン（`shared/proset.js`、addendum「対局設定の Pro モード」）。項目：思考の制限（時間 0.1〜60 秒／深さ 1〜30）、スレッド数（時間制限のとき、マルチスレッドがオンのとき）、完全読み（残り 0〜28 マスから）、勝敗読み（0〜30、0 で使わない）、定石、手のばらつき（Lv.1〜13 の既定はそのレベルの noise。変えると variety：最善から 小 1.5石／大 4石 以内の手から選ぶ）。値は engine.js `think` の `opts.cfg`（LEVELS と同じキー）・`opts.book`／`noBook`・`variety`／`varietyMargin` で渡す（ページの `LEVELS_UI` は engine.js LEVELS の写し）。PRO のときは根分割の並列探索（PAR_LEVELS）は使わない。レート戦では使わない。戦績は `ai:pro`。
