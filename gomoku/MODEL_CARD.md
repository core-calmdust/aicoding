# Model Card: Gomoku / Renju evaluation (`nn_renju.bin.gz`, `eval_std.bin`)

学習済みの形勢評価は2つあります。連珠ルールでは小さなニューラルネット（`nn.c` → `nn.wasm`）、標準・自由ルールでは線形のパターン評価を使います。
探索エンジン `engine.js`（αβ探索＋四追い・三四の読み切り）と組み合わせ、ブラウザ上（Web Worker）で動きます。

- **ゲーム**: https://core-calmdust.github.io/aicoding/gomoku/
- **バージョン**: v2（2026-10-21：連珠ネット v4・標準ネット v2）

## 連珠：ニューラルネット評価（v4, 2026-10-21）
| 項目 | 内容 |
|---|---|
| 構造 | 空点ごとに4方向×前後4マスの並び（左右反転を同一視して3,321通り）を、手番側・相手側の目で読み、埋め込みベクトル（48次元、役割×色ごとの表）を合計。黒の禁点には専用ベクトルを加算 → clipped ReLU → 全空点で合計 → 32 → 1 の全結合層 → 手番側の勝率のロジット |
| パラメータ数 | 約64万（埋め込みは int16、Q=256。gzip後 約820KB） |
| 実装 | `nn.c` を `-DH=48` で WebAssembly SIMD にビルド（`nn48.wasm`）。PyTorch の学習結果と一致を確認（ロジット誤差 平均0.03） |
| 学習データ | 約50万局面（うち約41万が Rapfi 採点）。v3 のデータ（Gomocup 連珠リーグの局面とその派生局面）に、**Rapfi どうしの自己対局**（26珠型から開始、1割強の手を候補手からランダムに選んで多様化）の局面 約17万を追加。自己対局では1手ごとの Rapfi の探索評価（1万ノード）をそのまま教師値にした |
| 学習 | PyTorch、Adam、8通りの盤の対称で水増し、8エポック |
| 評価 | 同じ探索・同じノード数（1手2万ノード）、互角の局面（学習に使っていない Gomocup 局面）から先後入れ替えで v3 と対局：133勝105敗2分（240局、勝率56%、約+41 Elo）。同じ構造で32次元のネットは +20 Elo、64次元は検証の一致率が伸びなかった。探索速度は v3 とほぼ同じ（約4%遅い） |
| 履歴 | v3（2026-10-20、32次元）：手作り評価比 約+68 Elo |

## 標準ルール：ニューラルネット評価（v2, 2026-10-21）
連珠と同じ構造のネット（32次元、`nn_std.bin.gz`）。Gomocup の標準・自由ルールの局面と派生局面に、Rapfi どうしの自己対局（標準ルール）約6万局面を加えた 約52万局面（うち約17万が Rapfi 採点）で学習。Rapfiの判定との一致率 82%。前版 v1 と同じノード数で対局：67勝52敗1分（約+44 Elo）。自由ルールは線形評価のまま（v1 の時点でネットが勝てなかったため）。

## 自由ルール（と旧・標準）：線形のパターン評価
| 項目 | 内容 |
|---|---|
| 種類 | 線形の評価関数（パターン重みの合計）。差分更新で計算 |
| 特徴量 | 空点ごとに、①4方向の並びの種類の組み合わせ（715通り＋禁点）、②その点の黒・白の形の組（100通り）、③各方向の前後10マスの並びそのもの（左右反転を同一視して29,646通り）。それぞれ「手番側／相手側」×「黒／白」で別の重み |
| パラメータ数 | 121,650（Int8、gzip後 約44KB） |
| 出力 | 手番側から見た評価値（600 ≒ 勝率のロジット1。エンジン内部では16倍して従来の評価と同じ尺度にしている） |

## 学習データ
- [Gomocup](https://gomocup.org/)（世界コンピュータ五目並べ選手権）2017〜2025年の15路盤の対局棋譜（標準・自由ルール 約3.3万局）。棋譜そのものはリポジトリに含めていません。
- 局面の約2.6万を、オープンソースの強豪エンジン [Rapfi](https://github.com/dhbloo/rapfi)（GPL-3.0）の評価値（1万ノード探索）で採点し、教師値にしました。Rapfiは採点のためだけに手元で使い、コードもネットワークもこのリポジトリには含めていません（Rapfiのネットワーク重みは CC0）。

## 学習方法
1. 勝敗（手番側の勝ち＝1）を目標にロジスティック回帰（Adam、L2正則化、対局単位で1割を検証用）。
2. その重みから始めて、Rapfiの勝率（評価値/200 のシグモイド）を目標に追加学習。

## 評価
同じ探索・同じノード数（1手2万ノード）で、互角の局面（Rapfi評価±120以内）から先後を入れ替えて対局：

| 比較 | 結果 |
|---|---|
| 学習評価 vs 手作り評価（標準ルール） | 69勝49敗2分（勝率58%、約+58 Elo） |

連珠ルールでは線形評価では有意な差が出なかったため、上のニューラルネット評価を使っています。

## 探索の高速化（2026-11-08）
- 石を置く／除く差分更新（`_put`）で、方向パターンの4ビットが変わらなかった空点は `cellUpd` を呼ばない（その点の分類・点数・学習和はパターンだけで決まるので結果は同じ）。
- ネット評価のとき（連珠・標準）は、評価に使われない線形の学習和（`lw` / `lw2`）を持たない。自由ルール（線形評価）の窓コード和は局所変数で足してから一度に加える（整数和なので同じ値）。
- 検証：各ルール40局面・レベル12（9000局面）と15（38000局面）で最善手・評価値・深さ・局面数・VCF局面数が完全一致。CPU時間で **連珠 約1.3倍、標準 約2.3倍、自由 約1.4倍**（node、例：標準 2.4万→5.4万局面／秒）。

## 制限
- 線形モデルなので、ニューラルネット評価の強豪エンジンには及びません。
- 勝ちを読み切る部分（四追い・三四の追い）は別の探索が受け持ち、この評価は使いません。

## 対局設定の Pro モード（2026-11-08）
対局設定の「AIの強さ」の PRO ボタン（`shared/proset.js`、addendum「対局設定の Pro モード」）。項目：思考の制限（時間 0.1〜30 秒／深さ 1〜20／局面数 1千〜500万）、勝ち筋の読み（VCT：0〜21 手。既定はレベルの `vct`）、手のばらつき（時間で考えるときだけ。弱い段の既定はその段のノイズ）。序盤の定石（openingMove）はレベルのまま。engine.js `think` の `cfg`（LEVELS と同じキー）。レート戦では使わない。戦績のキーは `ai:pro…`、相手名に「PRO」。PRO の「スレッド数」（本編のマルチスレッドがオンのとき、どの思考の制限でも。既定は1）。

## 本編のマルチスレッド（2026-11-08）
addendum「本編のマルチスレッド」（全タイトル対応）。探索は JavaScript（`engine.js`）のまま、置換表だけを共有メモリに置く：`mt.c` → `engine_mt.wasm`（置換表 2^20 件と `shared/mtengine.js` の求めるスレッドの関数だけ。ビルドは `mt.c` の先頭）。主スレッドは `engine.js?…&mt=1`、補助は同じ `engine.js?…&mt=2`（評価ネットは各スレッドが自分で持つ）。共有の置換表は同じ探索の深いものを残す（深さ優先の置き換え。世代は `ctl[12]`）。スレッドなしのときの探索は今までと1手も変わらない（3ルール×4局面×3レベルで手・評価値・深さが一致）。
- **解析（`rootList`：分析・ヒント・コーチの採点・検討ボックス）**：深さごとに候補手（12手）をスレッドで分け合う（原子的なカウンタ `ctl[15]` で取り合い、各候補を全幅で読む。値は `ctl` に書き、主スレッドが集める）。同じ深さまでに主スレッドが読む局面数 1スレッド 21.6万 → 2スレッド 12.6万（10局面、**局面数換算 1.72倍**、全スレッドの合計は1.13倍）、最善手は 10/10 一致。
- **1手の読み（コーチの深読み Lv.14、PRO のスレッド数）**：Lazy SMP（補助は同じ局面を1つおきに1手深く始めて読み続ける）。四追い・三四の読み（`Solver`）と幅の制限が探索の大半で、置換表の共有の効きは小さい（同じ深さまでの主スレッドの局面数 1.07倍、9/10 一致）。
- AI のレベルは局面数で決める（6級〜五段、時間はその上限）ので1スレッドのまま（レート戦も）。最上位レベルは足さない：五段は1スレッドで28万局面（PC で約5〜10秒）とすでに重く、時間を2倍ずつ伸ばすと上限の約20秒を超えるため。
- 計測（作業環境：共用2コア、負荷が高く時間の比は当てにならない）。正式な効果はユーザーの Mac で `gomoku/bench.html`（1・2・4・8…論理コア数、1手の読みの局面数／秒・深さ・最善手の一致、解析の同じ深さまでの時間）を測る。
