# Model Card: チャンギ（韓国将棋）エンジン（`engine.wasm`）

チャンギのAIは、探索エンジン `engine.c`（WebAssembly、ブラウザの Web Worker で実行）と手作りの評価関数で動いています。
探索の土台はシャンチー（`xiangqi/MODEL_CARD.md`）と同じで、ルール・評価・序盤ブックはチャンギ用です。仕様の細目は `claude/janggi-spec.md`。

- **ゲーム**: https://core-calmdust.github.io/aicoding/janggi/
- **版**: 探索 v2（2026-11-13）＋ NNUE（2026-11-22 に1周目のネットを採用、Lv.19・20 と解析）＋ 学習ツールの見直し・序盤ブックの拡充（2026-11-20）

## 仕組み

| 項目 | 内容 |
|---|---|
| ルール | 9×10・九宮の斜め線・包は1枚を跳ぶ（包は越えず取らず）・パスは動ける手がないときだけ・詰みで勝ち、同一局面3回か200手は点数判定（漢+1.5）。探索中の繰り返しは引き分け扱い（判定は画面側） |
| 探索 | 反復深化 PVS・アスピレーション窓・置換表 2^20・王手延長・ヌルムーブ・LMR（対数の表）・LMP・フューティリティ／逆フューティリティ・IIR・キラー手とヒストリー（カットしなかった静かな手は減点）・静止探索（取り＋王手回避、足切り）・置換表の値による静的評価の補正。詳しくは `claude/janggi-spec.md`「探索 v2」 |
| 評価 | 手作り：駒の価値（卒2・士3・象3・馬5・包7・車13 ×100）、卒の前進、馬・象・車の動ける数、包は駒が減るほど弱く、将の位置、士が将のそば、九宮に入った敵の駒（危険度）。手番 +12 |
| 速さ | ネイティブ 約150万局面／秒（作業機の1コア）、WebAssembly 約158万局面／秒（2026-11-08 の測定） |
| マルチスレッド | `engine_mt.wasm`（Praline：YBW の分割探索＋busy marks、共有の置換表）。分析・ヒント・コーチ・Lv.19・20 |
| 序盤ブック | `book.json`：16通りの初期配置ごとに、このエンジンの深い分析で作った手（下の「序盤ブック」） |
| NNUE | 受け皿のみ（形はシャンチーと共通 (1260→256)×2→1、SCReLU）。ネットを置けば探索レベル・解析・コーチが使う（下の「NNUE」） |

## レベル（engine.js `LEVELS`、レートは app.js `RT_LV`）

| レベル | 設定 |
|---|---|
| Lv.1〜12 | 全部の手を固定の深さ（1〜4、小数は確率）で読み、ノイズ（±300〜20）と悪手の確率で弱くする。探索 v2 の前の探索のまま（`svOff`） |
| Lv.13〜18 | 1手 2,400 ／ 1万1,500 ／ 3万6千 ／ 9万 ／ 21万 ／ 48万 局面（端末によらない） |
| Lv.19・20 | 1手 250万／700万局面・最大 8／12秒（時間の上限があるのでマルチスレッドで深く読む）。序盤ブックを使う |

レート（`RT_LV`）は Lv.1 = 100 〜 Lv.20 = 2500（addendum「AIレートの共通の目盛り」）。2026-11-20 の作業では**強さが変わっていない**（探索 v3 は不採用、NNUE は未採用）ので、レベル表とレートは変えていない。

## 探索 v3（2026-11-20、試したもの：不採用）

シャンチーの「探索 v2」の項目（LMR の対数表・LMP・ヌルムーブの深い縮小・逆フューティリティ 深さ6・フューティリティ 深さ4・IIR・ヒストリーの減点・静止探索の足切り・置換表の値での静的評価の補正）は、チャンギにも**全部同じコードで入っている**（`engine.c` の `SV_*`。同じ日に両方へ入れたもの）。足りないものはなかったので、その先として将棋の「探索 v3」で効いたものを試した。

| 候補（`engine.c` のスイッチ） | 内容 |
|---|---|
| `SV3_CH` | 継続ヒストリー（1手前・2手前の手の駒と行き先 × この手の駒の種類と行き先、重力式の上限つき）を手の並べ替えと LMR に、カウンター手（相手の直前の手への応手）をキラーの次に |
| `SV3_PC` | ProbCut：深さ5以上・PV 以外で、取った駒だけで β+250 に届く取りを静止探索 → 深さ −4 で確かめ、届けば打ち切る（SEE は無いので取った駒の価値だけで選ぶ） |

計測（`tools/duel.py`、前のビルド（`jg_base`）相手、ランダムな상차림＋序盤4手ランダム、同じ序盤を先後入れ替え。作業機・ネイティブ・1スレッド。作業機は他の作業と共用で負荷 5〜10）：

| 条件 | 結果（新しい方から見て） | Elo |
|---|---|---|
| 両方、同じ局面数 1手1万（300局） | +154 −146 | +9（−30 .. +49） |
| 両方、1手4万（200局） | +102 −98 | +7（−41 .. +56） |
| ProbCut だけ、1手4万（200局） | +99 −101 | −3（−52 .. +45） |
| 継続ヒストリーだけ、1手4万（200局） | +106 −94 | +21（−27 .. +70） |
| 継続ヒストリーだけ、**同じ時間** 1手0.06秒（280局） | +128 −152 | **−30**（−71 .. +11）、深さ 6.46／6.67 |

- どれも勝ち越しがはっきりせず、継続ヒストリーは同じ時間では負けた（表を引く分だけ1局面が遅く、深さが浅くなる）。**どちらも不採用**（既定 `SV3_CH 0`・`SV3_PC 0`。`-DSV3_CH=1` などで再計測できる）。
- 既定のビルドの読みは前と同じ（`tools/check_wasm.js` の12局面・深さ9：wasm 各版の最善手・評価値・局面数が前の `engine.c` のネイティブと全一致）。

## NNUE（学習は Mac：`tools/nnue/`）

### 方針
- 先生は**このエンジン自身**（外部エンジンは使わない。サイトのコンセプト「自力で作る」）。自己対局の各局面の「探索の評価値」と「対局の勝敗」から学ぶ。
- 周回（自己強化ループ）：1周目の先生は手作りの評価、2周目からは前の周のネット（チェッカーの net-43・タフルの周回と同じ考え）。
- 形・ファイル（"NUEX"）・学習器（`xiangqi/tools/nnue/train.c`）はシャンチーと共通。チャンギ固有：パスではアキュムレータをそのまま引き継ぐ。

### 教師データ（`jg datagen`、2026-11-20 に見直し）

| 項目 | 前（11-14） | いま | 理由 |
|---|---|---|---|
| 量（1周） | 10万局 ≒ 900万局面 | **2000万局面**（`POSITIONS`） | ユーザーの経験（約2000万局面で目に見えて強くなる） |
| 先生の読み | 1手 8千局面 | **1手 1万6千局面**（`NODES`） | 1手あたり約1手深い。Mac（全コア）なら 2000万局面が 3〜4時間で収まる（作業機1コアで 8千局面・毎秒約200局面） |
| 教師値 | 0.6 × 探索 + 0.4 × 勝敗 | **0.75 × 探索 + 0.25 × 勝敗**（`LAMBDA`） | 自分が先生の周回をしたチェッカー・タフルと同じ配分。シャンチーは強い先生で 0.8 |
| 評価値 → 勝率 | 手作り 430点 = 1ロジット | 同じ。**ネットの出力の尺度 `XQ_K` を 220 → 430** に | 220 はシャンチーの線形評価の尺度をそのまま写したもの。探索の余裕（フューティリティ・ヌルムーブ・アスピレーション窓など）は手作りの評価（430点/ロジット）で決めてあるので、ネットも同じ尺度にしないと余裕の意味が約2倍にずれる。2周目以降の先生の評価値も同じ尺度で勝率に直る |
| 序盤 | 初期配置16通り＋ランダム 2〜9手 | 同じ | 毎局違う局面。偏った局面は ±3000 以上で学習から外れる |
| 使う局面 | 王手・最善手が取り・±3000 以上を除く | 同じ（学習器） | 静かな局面だけ。左右反転で2倍 |
| 打ち切り | なし | **同じ側が ±3000 以上を8手続けたら勝ち**（`JG_ADJ`） | 長い勝ち切りの終盤を読む時間を省く。その局面は学習に使わないので失うデータはない |

### 学習後の確認（`run.sh` が自動で）
1. 差分更新と全計算の一致（`jg nncheck`、パスを混ぜたランダムな局面）。不一致なら止まる。
2. 手作りの評価との対局：**同じ局面数**（1手2万）と**同じ時間**（1手0.1秒）、各400局（`duel.py`、`JOBS` 本並列）。2周目からは**前の周のネットとの同じ時間の対局**も。
3. 全部で勝ち越したら `~/janggi-nnue-work/adopt/`（`nnue.bin.gz`・`report.txt`）を作る。

### Mac で回すコマンド
```bash
cd ~/Documents/GitHub/aicoding && git pull
bash janggi/tools/nnue/run.sh                                                    # 1周
ROUNDS=3 DATA="/Volumes/Orico A 8TB/janggi-data" bash janggi/tools/nnue/run.sh   # 3周、データは外付け
```
止めても同じコマンドで続きから。時間の目安（Mac mini M4 Pro・全コア）：1周目 データ 3〜4時間＋学習 数十分＋対局 30分〜1時間。2周目以降はネットが先生なのでデータが 1.5〜2倍。詳しくは `tools/nnue/README.md`。

### NNUE を採用するとき（Claude の作業）
1. `adopt/nnue.bin.gz` を `janggi/nnue.bin.gz` に置き、`janggi/engine.js` の `NET` と `janggi/pro/pro.js` の `NETV` に同じ版を入れる（空の間はネットを取りに行かない）。
2. `node janggi/tools/check_wasm.js janggi/nnue.bin.gz 8 /tmp/jg`（wasm 各版とネイティブの一致）、ブラウザで対局・解析・最強解析（`pro/`）。
3. ブラウザ（wasm SIMD）でのネットの速さ（局面数／秒）を手作り（`engine.wasm`）と比べ、Lv.13〜18 の局面数を「前と同じ強さ」に合わせ直す（`duel.py` で新 N 局面 対 旧 M 局面）。Lv.19・20 は時間の上限のまま強くなるので `RT_LV` を測った差 ×0.7 ほど上げる。Lv.1〜12 は手作りのまま（`wNN`）。
4. `bench.html` の説明文「手作りの評価」、この MODEL_CARD、`claude/janggi-spec.md` を直す。

### 採用の基準
同じ持ち時間・同じ局面数の両方で手作りの評価に勝ち越すこと（2周目以降は前の周のネットにも同じ時間で勝ち越すこと）。

### 作業機での確認（2026-11-20、仮ネット：採用しない）
- `run.sh` を小さな設定で2周（1周 2万5千局面・1手2千局面・2エポック・対局4局、作業フォルダとデータの置き場に空白を含むパス）：データ → 学習（2周目は1周目のネットから・2周分のデータ）→ 一致検査 → 対局 → 判定まで止まらずに進む。仮ネットはデータが少なすぎて手作りに全敗（判定は「不採用」で正しく止まる）。
- 差分更新：`jg nncheck` 不一致 0（約2万6千局面、うちパス 1,626）。
- wasm：`tools/check_wasm.js`（12局面・深さ 7〜8）で `engine.wasm`・`engine_simd.wasm`（手作り・ネット）の最善手・評価値・深さ・局面数がネイティブと全一致、`engine_mt.wasm`（1スレッド）の評価値も一致。

## 序盤ブック（`book.json`）
- 2026-11-15：`shared/tools/genbook.js janggi --starts all`（16通りの配置それぞれ、初手から3手、上位3手、1局面8秒、最善から12点以内の手）。
- 2026-11-20：`tools/genbook_ext.js` で各配置の木を伸ばした（4手目は上位2手、5手目は最善手の先を、1局面5秒の分析。1,538局面を新たに分析、作業機2プロセスで約1.5時間）。917 → **2,455局面**（手の数 13,915、全部合法を確認）、116KB → 342KB。キーは `<開始FEN>|手,手,…`、使い方は前と同じ（Lv.19・20 と PRO の book が10手目まで。無い局面は普通に読む）。
- Mac でさらに深く：`node janggi/tools/genbook_ext.js --plies 8 --k 3,2,2,1,1 --ms 8000 --workers 12`（作ってある局面は読み直さない。止めても続きから）。2026-11-20 から workers は本当に並列（1コア1局面、既定はコア数−1。前は1スレッドで順番＝「2プロセス」も実は1コア）。

## 限界
- 評価は手作り（NNUE は Mac の学習待ち）。人間の棋譜・定跡書は使っていない（序盤ブックもエンジンの読み）。
- 探索中の繰り返しは引き分け扱いの簡略化（画面側で点数判定）。
- Lv.19・20 は時間で区切るので端末の速さに少し左右される。
