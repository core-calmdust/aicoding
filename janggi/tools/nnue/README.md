# チャンギ NNUE 学習ツール（Mac）

チャンギAIの評価関数を NNUE にするための、学習データ作り・学習・確認・採用ファイル作りの一式です。
先生は**サイトのチャンギAI自身**です（外部のエンジンは使いません）。自己対局の各局面について「探索した評価値」と「その対局の勝敗」を記録し、読まなくても同じ判断ができるように学習させます。
周回（`ROUNDS`）を重ねると、前の周のネットを先生にして次の周のデータを作ります（自己強化ループ）。

ネットワークの形・ファイル形式・学習器はシャンチーと共通です（`xiangqi/tools/nnue/train.c`）。

## 使い方

```bash
cd ~/Documents/GitHub/aicoding
git pull
bash janggi/tools/nnue/run.sh                                   # 1周（約2000万局面）
ROUNDS=3 DATA="/Volumes/Orico A 8TB/janggi-data" bash janggi/tools/nnue/run.sh   # 3周、データは外付けに
```

途中で止めても（Ctrl+C・再起動）、**同じコマンドをもう一度**実行すれば続きから進みます（データは 100局×コア数 ごとに保存。学習の途中で止めた場合はその周の学習をやり直し）。`ROUNDS` を増やして再実行すれば、続きの周を足せます。

各周で自動で進むこと:

1. 自己対局で学習データ作り（`POSITIONS` 局面に届くまで。全コア）
2. 学習（直近 `WINDOW` 周分のデータ。2周目からは前の周のネットから続けて学習）
3. 差分更新の一致検査（`jg nncheck`。不一致があればそこで止まる）
4. 手作りの評価との対局：**局面数固定**（1手 `MNODES` 千局面）と**時間固定**（1手 `MTIME` ミリ秒）、各 `MGAMES` 局。2周目からは**前の周のネットとの対局**（時間固定）も
5. 判定：4 の全部で勝ち越したら `~/janggi-nnue-work/adopt/` に **`nnue.bin.gz`（採用ファイル）と `report.txt`（結果のまとめ）** を作る

## 時間の目安（Mac mini M4 Pro・全コア）

| 段階 | 目安 |
|---|---|
| データ（手作りの評価が先生、1手1万6千局面、2000万局面） | 3〜4時間（作業機の1コアは 1手8千局面で毎秒約200局面） |
| データ（2周目以降：ネットが先生） | 1周目の 1.5〜2倍 |
| 学習（10エポック） | 数十分 |
| 確認の対局（400局 × 2〜3種） | 30分〜1時間 |

進み具合は画面と `~/janggi-nnue-work/log.txt` に出ます（局面数・毎秒の局面数・残りの見込み）。CPU を他に使うときは `JOBS=6` のように絞れます。

## 設定（環境変数、どれも任意）

| 変数 | 既定 | 内容 |
|---|---|---|
| `WORK` | `~/janggi-nnue-work` | ネット・ログ・判定の置き場 |
| `DATA` | `$WORK/data` | 学習データの置き場（1周 2000万局面で約1.1GB。学習中は一時的にその WINDOW 周分の大きさのファイルも作る）。外付けなら `DATA="/Volumes/Orico A 8TB/janggi-data"`（空白を含むパスは "" で囲む） |
| `ROUNDS` | 1 | 周回の数（2周目からは前の周のネットが先生） |
| `POSITIONS` | 20000000 | 1周あたりの局面数 |
| `NODES` | 16 | 先生が1手に読む局面数（千単位）。多いほど教師が正確で、時間がかかる |
| `JOBS` | 全コア | 同時に動かす数（データ作りと対局） |
| `EPOCHS` | 10 | 学習の周回数 |
| `LAMBDA` | 0.75 | 教師値の配分（探索の評価値 × λ ＋ 実際の勝敗 × (1−λ)） |
| `LR` / `LR2` | 0.001 / 0.0005 | 学習率（1周目 / 前のネットから続ける2周目以降） |
| `WINDOW` | 2 | 学習に使う直近の周の数 |
| `NET` | なし | 1周目の先生にするネット（既存のネットから周回を始めるとき） |
| `MNODES` / `MTIME` / `MGAMES` | 20 / 100 / 400 | 確認の対局：局面数固定（千）／時間固定（ミリ秒）／局数 |
| `EXTRA` | なし | 学習器への追加オプション |

## 教師データの作り方（`jg datagen`）

- 初期配置 16通り（상차림 4×4）からランダムに選び、序盤 2〜9手はランダムな合法手（毎局違う局面から始める）
- その後は1手 `NODES` 千局面の自己対局。各局面の探索の評価値（勝率に直す：手作りの評価は 430点 = 1ロジット、`jg scale` で測定。ネットが先生のときはネットの尺度＝同じ 430）と、対局の勝敗（詰み、または点数判定）を記録
- 学習に使うのは**静かな局面だけ**：王手されている局面・最善手が駒取りの局面・勝負の決まった局面（評価値 ±3000 以上）は学習器が除く。左右反転でデータを2倍に使う
- 決着の見えた対局は打ち切る（同じ側が ±3000 以上を8手続けたらその側の勝ち。`JG_ADJ=0` で無効）。長い勝ち切りの終盤を読む時間を省く（その局面は ±3000 以上で学習に使わないので、失うデータはない）

## 終わったら

`~/janggi-nnue-work/adopt/report.txt` の中身（と `log.txt` の最後）を Claude に渡し、`adopt/nnue.bin.gz` をリポジトリに入れてもらってください。採用の作業は `janggi/MODEL_CARD.md`「NNUE を採用するとき」。
`adopt/` ができなかった（勝ち越せなかった）ときも `log.txt` を渡してください（周回を増やす・`NODES` を増やすなどを判断します）。

## ファイル

| ファイル | 内容 |
|---|---|
| `run.sh` | 全部まとめて実行 |
| `../native.c` | `jg datagen`（自己対局と記録）、`jg nncheck`（差分更新の一致）、`jg serve`（対局用）、`jg iobest`（wasm との照合）、`jg scale` |
| `../duel.py` | 2つのエンジンの対局（`jg@net.bin` でネット付き。`JOBS=N` で並列） |
| `../check_wasm.js` | wasm 各版（engine.wasm・engine_simd.wasm・engine_mt.wasm）とネイティブの一致検査 |
| `../../../xiangqi/tools/nnue/train.c` | 学習器（(1260→256)×2視点→1、SCReLU） |
| `../../../xiangqi/tools/nnue/xq.h` | 記録の形式（1局面 56バイト）と入力特徴 |
