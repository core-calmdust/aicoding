# Model Card: Shogi evaluation (`weights.bin.gz`)

将棋 SHOGI の AI が局面の良し悪しを判断するための評価関数（学習済み重み）です。
探索エンジン `engine.js` と組み合わせて、ブラウザ上（Web Worker）で動作します。

- **ゲーム**: https://core-calmdust.github.io/aicoding/shogi/
- **ライセンス**: Apache License 2.0（リポジトリの `LICENSE` を参照）
- **作成**: core-calmdust（AIコーディングによる制作）
- **バージョン**: v1（2026-10-18）

## モデル概要

| 項目 | 内容 |
|---|---|
| 種類 | 玉位置つき駒配置（KP）＋持ち駒の線形評価関数（Bonanza系の KKP/KP に近い古典的手法） |
| 入力 | 先手玉・後手玉それぞれの視点から見た、全駒の配置と持ち駒 |
| 出力 | 手番側から見た評価値（センチポーン相当。勝率 ≒ sigmoid(評価値/600)） |
| パラメータ数 | 115,921（Int16、1/8センチポーン単位） |
| ファイルサイズ | 約232KB（gzip圧縮後 約150KB） |

評価値 = Σ（先手玉視点の特徴の重み）− Σ（後手玉視点の特徴の重み）＋ 手番ボーナス。
後手玉視点は盤を180°回転して先手と同じ表を共有し、さらに玉が右半分にいるときは左右反転して表を共有します。

### 入力特徴（玉位置つき駒配置）

各手番側の視点（後手番は盤を180°回転）で、さらに自玉が盤の左半分に来るよう左右反転して正規化します。

| 特徴 | 内容 | 数 |
|---|---|---|
| KP | 自玉の位置（45通り）× 駒の種類（自分/相手 × 14種）× 升（81） | 102,060 |
| KH | 自玉の位置 × 持ち駒（自分/相手 × 7種 × 枚数を温度計表現で最大18） | 11,340 |
| P | 駒の種類 × 升（玉位置に依らない） | 2,268 |
| H | 持ち駒（玉位置に依らない） | 252 |

## 学習データ

[コンピュータ将棋対局場 Floodgate](https://wdoor.c.u-tokyo.ac.jp/shogi/) で公開されている棋譜（CSA形式）を使いました。

| 年 | 対局数（両者R3000以上） | 学習局面数 |
|---|---|---|
| 2021 | 54,852 | 4,704,050 |
| 2022 | 43,522 | 3,623,853 |
| 2023 | 56,228 | 4,783,001 |
| 2024 | 48,018 | 4,292,581 |
| 2025 | 59,893 | 4,847,586 |
| 合計 | **262,513** | **22,251,071** |

- 結果が投了・千日手・入玉宣言・時間切れで決着した対局のみ。開始5手までの局面は除外。

- Floodgate の棋譜には、対局したエンジン自身が出力した**評価値**（`'**` コメント行）が多くの指し手に記録されています。これを教師値として利用しました（先手から見た値であることを、最終的な勝敗との一致率 98.7% で確認）。
- 教師値 = 0.7 × sigmoid(評価値 / 600) + 0.3 × 最終的な勝敗。
- 取る手の直前の局面と、王手がかかっている局面は除外（静かな局面のみ）。
- Floodgate の棋譜には明示的な利用ライセンスの表記がないため、**棋譜データそのものはこのリポジトリに含めていません**。公開しているのは、棋譜から学習した重みと、序盤の指し手の頻度統計（`book.json`）だけです。
- 貴重な対局場と棋譜を長年公開してくださっている Floodgate の運営者の皆様、参加エンジンの作者の皆様に感謝します。

## 定跡（`book.json`）

両者レート3500以上の対局の序盤30手から、局面ごとの指し手の頻度と勝率を集計したものです（出現12回以上の局面、勝率38%以上の手のみ）。棋譜そのものは含みません。

- 集計対象: 2025年の両者R3500以上 39,514局 → 6,088局面（約600KB、gzip後 約100KB）

## 学習方法

- 損失: 予測勝率 sigmoid(評価値/600) と教師値の交差エントロピー。
- 最適化: Adam（特徴ごとの疎な更新）、ミニバッチ256、6エポック（後半2エポックで学習率を減衰）。
- 初期値: 駒の価値だけの評価（歩90〜龍1395）。
- 検証: 各年の末尾2%の局面（＝学習に使っていない対局）で検証。

| モデル | 検証KL（低いほど良い） |
|---|---|
| 駒の価値のみ（初期値） | 0.210 |
| 線形KP（2024〜2025年のみで学習） | 約0.12 |
| **線形KP（2021〜2025年、採用版）** | **0.1175** |
| 小型NN（同じ特徴→32×2→32→32→1、参考） | 0.1117 |

小型NN（NNUE風）は精度ではわずかに上でしたが、JavaScript では1局面の評価が約10倍遅く、同じ持ち時間の対局では線形モデルに勝率25%と負け越したため、採用していません。

## WebAssembly 版の探索

ブラウザでは、`engine.js` の探索部分を C に移植して WebAssembly にした `engine.wasm`（ソース `engine.c`）を使います。移植時には、指し手・評価値・読んだ局面数まで JavaScript 版と完全に一致することを48局面で確かめました。その後の探索の改良（上記）は WebAssembly 版だけに入っているため、現在は JavaScript 版より強くなっています。同じ持ち時間で約1.6倍の局面を読めます。WebAssembly が使えない環境では、自動的に JavaScript 版で動きます。

## レーティング戦（ひとりで遊ぶレート対局）のレーティング表

新しい対局の「レーティング戦」では、AIの各段階に固定のレーティングを割り当て、プレイヤーのレーティング（端末ごとに保存、`localStorage` の `shogi-rated-v1`）とのElo計算で増減させます。オンライン対戦のレーティングとは別物です。

尺度は将棋倶楽部24に近い形で、1級ごとに100点（15級 = 400〜499 … 1級 = 1800〜1899、初段 = 1900〜2099、以降200点ごとに1段）としました。各段階の値はその段級位の帯の中央です（入門150・初心300・15級450 … 1級1850・初段2000・二段2200。一覧は上の「段級位表示の19段階」の表）。

以下は Lv.1〜10 時代の旧表です（参考）。

| AI（旧） | レーティング | 24換算 |
|---|---|---|
| Lv.1 | 150 | 15級未満 |
| Lv.2 | 300 | 15級未満 |
| Lv.3 | 450 | 15級前後 |
| Lv.4 | 650 | 13級前後 |
| Lv.5 | 850 | 11級前後 |
| Lv.6 | 1050 | 9級前後 |
| Lv.7 | 1250 | 7級前後 |
| Lv.8 | 1450 | 5級前後 |
| Lv.9 | 1650 | 3級前後 |
| Lv.10 | 2100 | 初段〜二段（技巧 深さ4＝24初段に69%） |

- プレイヤーの初期値は 900（24 10級前後）。K = 48（最初の10局）、以降 K = 24。期待勝率は 1 / (1 + 10^((相手R − 自分R) / 400))。
- 相手の選び方：目標 = 自分のR + ずらし幅（80%は ±100 以内、10%は +150〜+300 の格上、10%は −150〜−300 の格下）に最も近い段階（19段階）。開始時に「今回の相手：9級（R 1050・互角）」のように表示（差が150を超えると格上・格下）。
- ルール：平手・先後ランダム・持ち時間10分＋秒読み30秒（人間側のみ）。待った・ヒント・コーチ・形勢表示・分析は終局まで使用不可。投了・時間切れ・中断（対局中に別の対局／レッスン／詰将棋／局面編集／棋譜読込／オンラインへ移る）は負け、千日手・持将棋（512手）は引き分け（0.5）。再読み込みすると対局は続きから再開し、結果は対局IDで1回だけ記録されます。
- 強さは読む局面数で決まるため、端末の速さにはほぼ左右されません（初段・二段のみ思考時間の上限あり）。段級位には ±1級程度の誤差があります。

## 制約・注意点

- ブラウザの JavaScript で動かすための小さなモデルです。Floodgate 上位のエンジン（大規模な NNUE や深層学習系）には遠く及びません。
- 入玉や駒落ちなど、学習データに少ない局面の評価は粗くなります。
- 評価値は推定で、詰みの読み切り以外は正確さを保証しません。

## ファイル形式

- `weights.bin.gz`: gzip 圧縮された Int16（リトルエンディアン）の配列、115,921 要素。値 ÷ 8 がセンチポーン相当。
- 並び: KP（45玉位置 × 28駒種 × 81升）→ KH（45 × 2 × 7 × 18）→ P（28 × 81）→ H（2 × 7 × 18）→ 手番ボーナス。
- 玉位置は「自玉が盤の左半分（9〜5筋）に来るよう左右反転した後の 9段 × 5筋」。駒種は自分の駒0〜13・相手の駒14〜27（歩香桂銀角飛金玉と成駒の順）。

```js
const buf = await (await fetch('weights.bin.gz')).arrayBuffer();
const raw = await new Response(new Blob([buf]).stream().pipeThrough(new DecompressionStream('gzip'))).arrayBuffer();
// Web Worker に {type: 'weights', buffer: raw} を送ると engine.js が読み込みます
```

## NNUE 評価関数（2026年10月〜、`nnue.bin.gz`）

チェスの AI で効果が大きかった設計を将棋に移した、小型の NNUE（差分更新できるニューラルネット）です。WebAssembly SIMD が使えるブラウザでは、8級以上・ヒント・形勢グラフ・振り返り分析にこの評価関数を使います（入門〜9級は線形評価。SIMD が使えない環境では従来どおり線形評価）。

| 項目 | 内容 |
|---|---|
| 構造 | (2534 → 256) × 2視点 → 1、活性化 SCReLU |
| 入力 | 盤上の駒（自分/相手 × 14種 × 81升）＋持ち駒（自分/相手 × 7種 × 枚数19段階）。手番側と相手側の2視点（相手側は盤を180度回転） |
| 量子化 | 第1層 Int16（×255）、累積は Int32、出力層 Int16（×64） |
| ファイル | 約1.3MB（gzip 約0.67MB） |
| 学習データ | Floodgate 2020〜2025年の約2,600万局面（レート3000以上どうしの対局。教師値は 0.7×sigmoid(評価値/600)＋0.3×勝敗） |
| 学習 | 自作の C 学習器、Adam、ミニバッチ16,384、3エポック（学習率 1→0.2→0.05倍）。それ以上回すと検証誤差が悪化（過学習）したため短く止めています |

| 比較 | 条件 | 結果 |
|---|---|---|
| 検証誤差（二乗誤差） | 2025年分の末尾1% | 線形 0.0418 → NNUE 0.0380 |
