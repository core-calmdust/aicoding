# アゴン 学習した評価の道具（Mac）

アゴンAIの評価関数に、自己対局で学習した小さなネットワークの「補正」を足すための一式です。
先生は**サイトのアゴンAI自身**（`core.c` の αβ＋手作りの評価）です。外部のエンジンは使いません。
自己対局の各局面について「探索した値」と「その対局の勝敗」を記録し、手作りの評価のずれ（特に「大きく有利と言いながら引き分けになる」局面）を学習で直します。
ネットの形・入力は `agon/MODEL_CARD.md`「学習した評価」を見てください。

## 使い方

```bash
cd ~/Documents/GitHub/aicoding
bash agon/tools/nnue/run.sh
```

データを外付けディスクに置くとき（パスに空白があっても大丈夫）:

```bash
WORK="/Volumes/Orico A 8TB/agon-nnue" bash agon/tools/nnue/run.sh
```

自動で次の順に進みます。途中で止めても（Ctrl+C）、もう一度同じコマンドを実行すれば続きから進みます。

1. ツールのビルド（`nn` ひとつ：自己対局・学習・対局・確認）
2. 自己対局で学習データ作り（既定 約2000万局面。全コアを使用。5局に1局は1842年の配置ルール）。コア数×20局ごとに保存
3. 学習（8エポック。各局面を盤の12通りの対称形のどれかで見せる。最後の2%は学習に使わず確認用）
4. 確認：手作りの評価との対局（序盤4手ランダム、先後入れ替え）。① 1手の局面数をそろえて（3万局面）400局 ② 1手の CPU 時間をそろえて（0.1秒）400局
5. **採用の基準**（②で 52% 以上、かつ①で 50% 以上）を満たしたら `作業フォルダ/adopt/net.js` ができて完了

必要なもの: Xcode Command Line Tools（`xcode-select --install`）、空き容量 2GB ほど（2000万局面で 1.1GB、1局面56バイト）。

## 時間の目安（Mac mini M4 Pro、14コア）

| 段階 | 目安 |
|---|---|
| 自己対局 2000万局面（1手2万局面） | 2〜4時間（進み具合と残り時間を表示します） |
| 学習 8エポック | 10〜20分 |
| 確認の対局（400局×2） | 15〜30分 |

見積もりの元：作業機（ほかの作業と共用の2コア）で、1手1万局面の自己対局が1コア毎秒約270局面（CPU 時間）、探索は毎秒約200万局面。
1手2万局面なら1コア毎秒約140局面、M4 Pro の性能コアは作業機の約2倍と見て 10コア＋効率コアで毎秒2000〜3000局面。
実際の速さは自己対局の途中に表示します。CPU を空けたいときは `JOBS=8` のようにコア数を絞れます。

## 設定（任意）

```bash
POS=10000000 NK=30 JOBS=10 bash agon/tools/nnue/run.sh
```

| 変数 | 既定 | 内容 |
|---|---|---|
| `WORK` | `~/agon-nnue-work` | 作業フォルダ（データ・ネット・ログ） |
| `POS` | 20000000 | 1周の自己対局の局面数（増やして再実行すると追加で作る） |
| `NK` | 20 | 先生が1手に読む局面数（千単位。多いほど教師が正確で、時間がかかる） |
| `JOBS` | 全コア | 同時に動かす数（自己対局・学習・対局） |
| `EPOCHS` | 8 | 学習の周回数 |
| `HIDDEN` | 32 | 中間層の数（最大64。増やすと評価が遅くなる） |
| `LAMBDA` | 0.5 | 教師値の配分（探索の値 × λ ＋ 実際の勝敗 × (1−λ)） |
| `ROUNDS` | 1 | 周回数。2以上にすると、2周目からは前の周で採用されたネットを先生にして自己対局し、前のネットから学習を続けます |
| `PAIRS` | 200 | 確認の対局の組（1組＝先後を入れ替えた2局） |
| `MS` | 100 | 時間をそろえた対局の1手の CPU 時間（ミリ秒） |
| `NET` | なし | 1周目の先生に使うネット（例：前回の `adopt/net.bin`） |
| `FORCE` | 0 | 1 にすると基準を満たさなくても `net.js` を書き出す（試すとき用。採用はしない） |

周回の例（2周）:

```bash
ROUNDS=2 WORK="/Volumes/Orico A 8TB/agon-nnue" bash agon/tools/nnue/run.sh
```

## 終わったら

`作業フォルダ/adopt/net.js` ができていたら、それを `agon/net.js` に置き換えるだけでAIが学習した評価に切り替わります
（`agon/engine.js` が `net.js` を読み、空でなければ局面数・時間で考えるレベル（Lv.12〜23・レート戦・PRO）と分析・ヒント・コーチの評価に補正が入ります。深さで決める Lv.1〜11 は今のまま）。
置き換えたら `agon/engine.js` の `importScripts('net.js?v=N')` の N を1つ上げてください（ブラウザのキャッシュ）。

Claude に頼む場合は、`adopt/net.js`・`adopt/net.bin`・`adopt/vals.txt`・`adopt/check.log`・`r*/train.log` の最後の数行を渡してください。
`node agon/tools/nnue/check_net.js net.bin vals.txt net.js` で WebAssembly の値の一致を確かめ、レベル表（局面数の Lv.12〜18、時間の Lv.19〜23）を測り直して調整します。

## ファイル

| ファイル | 内容 |
|---|---|
| `run.sh` | 全部まとめて実行 |
| `nn.c` | `nn selfplay`（自己対局と記録：序盤2〜8手（配置ルールはもっと長く）は深さ2で最善から80以内の手からランダム、その後30手までは時々（1割）深さ3で最善から40以内の別の手）、`nn train`（学習）、`nn match`（対局：`n=30,net=1` のように局面数（千）・`t=`ミリ秒・ネットの有無）、`nn check`（固定局面の値：`check_net.js` で WebAssembly と照合）、`nn speed`（評価と探索の速さ）、`nn tojs`（`net.js` の書き出し）、`nn zero`（補正0のネット：確認用）、`nn depth`（深さ固定の局面数：探索の実験用） |
| `geo.h` | 盤の形・ハッシュの鍵・初期配置・盤の12の対称（`node agon/tools/nnue/gen_geo.js` で作り直す。Node がなくても run.sh は動く） |
| `check_net.js` | `node agon/tools/nnue/check_net.js net.bin vals.txt [net.js]`：ネイティブと wasm（core-wasm.js・core_mt.wasm）で値が全部同じか、engine.js がその net.js を読んで指せるか |
| `../../core.c` | 評価（`evaluatePL` の最後に `nnOut`）・ネットの読み込み（`nn_load`）・`nn_use` |

記録の形式（1局面 56バイト）：盤 46バイト（1マス4ビット：駒 0〜4 ＋ 捕まった印 8）、手持ち（白 | 黒 << 4）、手番（0 白・1 黒）、手数 u16、探索の値 int16（手番から、約100＝1手）、勝敗 int8（手番から +1／0／−1）、ルール（0 標準・1 配置）、予備2バイト。
