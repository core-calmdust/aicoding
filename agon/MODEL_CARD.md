## 学習した評価（2026-11-20）

### なぜ評価を学習するか
自己対局（1手1万局面、400局・6万局面）の記録で、探索の値と実際の結果を比べると、**手作りの評価は勝敗をほとんど言い当てていない**：引き分けが7割（ほとんどが同一局面3回）、値が +1200 以上（12手分有利）の局面でも得点率は 57%。値が −2700 から引き分けになる対局も普通にある（捕まった駒の置き直し・ふさぎで形勢が大きく振れて見える）。枝刈りでは強くならず（spec）、読みの量は効くが評価の目盛りがずれている、というのが今の見立てなので、評価を結果から学ぶのが次の手段。

### ネットの形（`core.c` の `nnFeat`・`nnOut`）
- 出力＝**手作りの評価＋補正**。補正＝100 ×（b2 ＋ Σ w2・clamp(acc, 0, 1)）、acc＝b1 ＋ 入力の行の和。w2 が0なら手作りの評価と完全に同じ値（学習の始まりはこの形）。
- 入力（740、手番から見る）：駒ごとに 種類（自分のガード・自分の女王・相手のガード・相手の女王）× 捕まっているか × マス（黒の手番は盤を180°回してマス 90−i）＝ 8×91、手持ち（自分 1〜6・相手 1〜6）12。1局面で有効な入力は最大16個。
- 中間層 32（最大64）。重みは半精度で `net.js`（base64、約47KB）。読み込み時に float に戻し、ネイティブと wasm で同じ順で足すので値は完全に一致（`check_net.js`）。
- 速さ（作業機ネイティブ）：評価だけ 毎秒 約370万 → 約230万。探索の局面数は 1割前後減る（評価は局面の一部の仕事のため）。中間層を増やすと遅くなるので 32 を既定にした。
- 使う所：局面数・時間で考える Lv.12〜23・レート戦・PRO・分析・ヒント・コーチ・検討・マルチスレッドの全仕事（`engine.js` の `useNet`）。深さで決める Lv.1〜11 は手作りの評価のまま（ノイズの大きさが手作りの評価の目盛りで調整されているため）。ページ本体の JS の探索（ワーカーが無いとき）は手作りの評価のまま。ネットの入り切りで置換表を消す。
- `core_mt.wasm`：ネットは共有メモリにあり、主の Worker が1回読み込めば補助スレッドも同じものを使う。

### 学習（`agon/tools/nnue/`）
- 先生＝**このサイトのエンジン自身**（`core.c` の `ab_best`、1手2万局面）。外部のエンジンは使わない。5局に1局は1842年の配置ルール。序盤は深さ2で最善から80以内の手からランダム（2〜8手、配置ルールは長め）、その後30手までは1割の確率で深さ3の近い手、で対局を散らす。
- 記録：探索の値と最終的な勝敗（手番から）。目標＝λ・σ(値/K) ＋ (1−λ)・結果（λ=0.5、引き分け ½）。K は学習の前に手作りの評価と結果から当てはめる（作業機のデータでは K≈3800：値がほとんど勝敗を言い当てないので大きい）。
- 損失は σ((手作り＋補正)/K) の交差エントロピー、Adam、各局面を盤の12通りの対称形（6回転×裏返し：アゴンの決まりはどれでも同じ）のどれかで見せる。最後の2%は確認用（学習に使わない）。
- 確認と採用：手作りの評価との対局（序盤4手ランダム、先後入れ替え、互いに別の置換表）で、① 1手3万局面 400局で 50% 以上、② 1手 CPU 0.1秒 400局で 52% 以上なら採用（`adopt/net.js`）。

## 推論の高速化（2026-11-20、値は同じ）

- **core-wasm.js を SIMD 版と SIMD なし版の2本に**（`tools/build-core.sh`、`AG_WASM`／`AG_WASM0`。engine.js はコンパイルできた方を使う、Node は `AG_NOSIMD=1` で SIMD なし）。core_mt.wasm も `-msimd128`（ほかのゲームと同じ）。前はどれも SIMD なしだった。
- **`nnOut` の中間層を f32x4 で**（H が4の倍数のとき）：各レーンの和は前と同じ順番なので float もビット単位で同じ。出力の和は前と同じ順に1つずつ。ほかのコードはコンパイラの自動 SIMD 化だけ（float の和の順番は変えない）。
- **確認**：`tools/nnue/check_net.js`（仮ネット、300局面：ネイティブと core-wasm.js SIMD・SIMD なし・core_mt.wasm がネットあり・なしで一致、engine.js が net.js でネットを使う）、`tools/check_ab.js`（旧版と 424 探索が core-wasm.js・core_mt.wasm 1スレッドでネットなし・あり・SIMD なしとも一致）、旧版と新版の探索（Lv.14、8局面×2）が一致、ブラウザ（headless Chrome、仮ネットを `net.js` に置いて）で1スレッド・マルチスレッドとも Node と同じ手・値。
- **速さ**（wasm、Lv.14 の探索を旧・新交互に同じプロセスで、CPU 時間）：ネットあり **約+12〜15%**（SIMD なし版でも約+9%）、ネットなし約+6%。ネットなしの約 0.86 倍 → 0.90 倍。時間固定の対局は差が小さいため今回は測っていない。
