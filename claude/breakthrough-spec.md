# ブレイクスルー（breakthrough/）仕様

URL: https://core-calmdust.github.io/aicoding/breakthrough/ ／ トップはアマゾンズの次（cat: line、also: chess、ALPHA、2026-11-28 公開）。テーマ色 #c25f37（ガンメタルの地 #111417 に銅・朱のアクセント #e58a5c→#c25f37、真鍮 #e9b07c）。保存キー `aicoding-breakthrough`（-rules / -rated / -lessons / -puzzles / -daily / -open）。

## ルール（ゲームタブで 8×8・7×7・6×6）
- 各自、手前の2段に駒を並べる（8×8 は16個ずつ）。白（P1、下）が先手。
- 1手＝自分の駒1つを前・斜め前に1マス。前は空きマスのみ、斜め前は空きマスか相手の駒（取る）。取るのは斜め前だけ。取りは義務ではない。パスはない。
- 相手の最終段（向こう端の段）に1つでも着けば勝ち。相手の駒を全部取っても勝ち（動ける手がない局面は起こらないが、念のため「動けない側の負け」）。引き分けはない。
- 種目：8×8（標準）／7×7（考案者がはじめに使った大きさ、14個ずつ）／6×6（短い入門向け、12個ずつ）。どれもルールは同じ。

### 出典（2026-11 確認。記憶で書かず Web で確かめた）
- Wikipedia「Breakthrough (board game)」：Dan Troyka が2000年に考案、Zillions of Games のファイル（ZRF）として公開、はじめは 7×7、**2001年の 8x8 Game Design Competition で優勝**。小さい盤の解析（6×5 は後手勝ち、6×6 は先手勝ち）。
- jpneto.github.io（Rognlie のページ、Troyka のルール文）：コンテストの主催は About Board Games・Abstract Games Magazine・Strategy Gaming Society。
- mindsports.nl：白が先手。
- C. Luna-Mota「Basic Introduction to Breakthrough」（Little Golem、考案者の戦略メモを含む）：1つの守り駒では攻め駒を止められない／横・縦の列はすり抜けられない、斜めの列はすり抜けられる／中央を取る／守り駒を後ろに残す／ランナー（前に相手の駒がない駒）。序盤例：本陣を残して3段目に壁（強い打ち手の攻撃的な序盤）、両翼の 3×2 ブロック（堅いが中央と主導権を渡しがち）。10×10 の変種にも触れる。
- 研究：R. Lorentz & T. Horey「Programming Breakthrough」（CG 2013, LNCS 8427）＝MCTS；Saffidine・Jouandeau・Cazenave（6×5 の解析）；Björnsson ほか「Solving Breakthrough for the 6x6 board」（ICGA Journal 2026、先手勝ち）。
- **依頼文との違い**：「2001年 Zillions コンテスト優勝」とあったが、優勝したのは「8x8 Game Design Competition」（上の3団体の主催）。Zillions は公開に使ったソフト。ページの文もそのように書いた。

## エンジン（core.c → WebAssembly、engine.js、Web Worker）
- 自作。ビットボード（u64、bit = r×8+c、5〜8路すべて1語）、αβ（PVS）＋置換表 2^20＋キラー／ヒストリー＋LMR、取りだけの静止探索、反復深化＋アスピレーション。
- ゲーム固有の強制ルール：ゴール1歩手前の自駒＝即勝ち、自陣1歩手前の相手駒が2つ＝負け、1つなら必ず取る手だけ読む。**正確なランナー判定**（前方に広がる円錐の中に相手の駒がない駒は止められない。Luna-Mota の「mutually unreachable」）で競走を読み切る。勝ち点数は WIN−ply。
- 評価（駒1つ＝100）：駒数、前進（ゴールに近い段ほど急に高い ADV8）、本陣に残る守り（列ごと HOMEW8）、縦の支え（W_COL）・横並び（W_PHAL）、取られて取り返せない駒（W_HANG / 相手側 W_HANG_OPP）、自陣に迫る相手駒（W_DANGER）、手番（W_TEMPO）、後ろの支え（W_SUPP）。重みは `set_w(i, v)` で外から変えられる（tools/match.js）。
- 重みの比較（tools/match.js、自己対局、乱数を直したあと 2026-11-28 にやり直し：各200局・1手5万局面の予算・同じ序盤で先後交互、2σ は約 ±50 Elo）：本陣の守りなし −220、本陣2倍 +17、取られ駒 55→100 −3、→30 −31、迫る駒 70→140 −28、→35 +17、縦・横の形0 −42、縦10・横6 −63、手番0 −7、後ろの支え0 +38、相手の取られ駒 12→30 +3 → **誤差を超えて良くなる変更はなく、既定の重みのまま**（本陣の守りと縦・横の形は効いている）。
- 厳密ソルバー（パズル・レッスン・振り返り用）：`winIn`（手番側が相手のどの応手にも k 手以内に勝てるか）・`lossAfter`・`duel_good`（k 手以内に勝つ初手の一覧）・`duel_min`・`duel_replies`。
- 速さ：1スレッド wasm SIMD で約260万局面/秒（作業機、負荷なし）。Praline のマルチスレッド共通コアは使っていない（1スレッドで天上でも20秒以内に深さ13前後）。

## レベル（Lv.1〜20＋天上Ⅰ〜Ⅲ＝Lv.21〜23、2026-11-28 に測り直し）
- Lv.1〜11：深さ1〜5 の全手評価＋ノイズ＋ときどきの軽率な手（1手で勝てる手は逃さず、すぐ負ける手は指さない）。
- **Lv.12〜20：読む局面数の予算**（2.5万・5万・10万・20万・40万・80万・160万・320万・640万。機械の速さによらず強さが同じ。遅い端末のため6秒で打ち切り）。作業機（1スレッド wasm SIMD 約400万局面/秒）で Lv.20 は1手 約1〜2秒。予算の45%を使った深さの次は読み始めない（時間と同じ規則、core.c）。

## レッスン（lessons.json、tools/gen_content.js → tools/verify_content.js）
- 「はじめの一歩」3：ただで取る（b_cap）・侵入を止める（b_stop）・2手で突破（b_win2）。「戦略」5：手薄な所を攻める（s_break）・防御陣形（s_wall）・交換（s_trade）・手待ち／ツークツワンク（s_tempo）・終盤の競走（s_race）。
- 各ステップ：準備2つ（説明 explain＋例題 try、採点なし）→ 本番5問（1問20点、75点以上で合格）。易しい順（勝ちまでの手数 k が増える順）。
- 答えはすべてエンジンの厳密ソルバーで決める：攻め＝k 手以内に勝つ初手がただ1つ、守り＝3手の間突破されない手がただ1つで、そのあと5手以内に負けない、取り＝取り返されない取りがただ1つ（深さ4と6の探索も一致）。間違えた手ごとに盤の事実（相手の応手と、その後どうなるか）を前もって計算して保存（評価値では説明しない）。
- **手待ち**は本当のツークツワンクだけ：正解の手のあと「もし相手がパスできたら k 手以内の勝ちがない」局面（相手が動かなければならないことが勝ちの理由）。自己対局の局面にはほとんど無いので、向かい合った駒の組を置いた終盤局面を探索で集めた（tools/gen_zz.js）。
- 局面の出どころ：自己対局 1200局（tools/gen_pool.js、6.1万局面）と、組み立てた終盤 16万局面（tools/gen_end.js）。自己対局の局面を優先（fun に +12）。左右反転・色の入れ替えで同じ局面、4マス以内の違いの局面は使わない。
- 候補は1テーマに必要数の3倍以上（puzzle-fun-score）。足りないテーマは問題数を候補の1/3に減らす。
- ランダム関数：線形合同法を JS の double で回すと周期が極端に短くなり（4万局面が735種類に）、mulberry32 に替えた（tools/*.js すべて）。

## パズル（puzzles.json）
- テーマ：○手で突破（2・3・4・5手、各30）、守り切れ（30）、テーマ（交換で突破・手待ちで勝つ・競走に勝つ：候補の数に合わせて）。今日の一問あり。
- 判定：攻めは厳密ソルバーで、手順の途中で別の勝ち方をしても k 手以内に勝てば正解。守りは3手しのげば正解。
