### 奥原氏の Edax 高速化の解説との突き合わせ（2026-11-20）
解説2本（bitboard のテクニック／bitboard 以外の最適化。Edax 4.7 に入っているもの）を読み、本作の `engine.c` と比べた。
- **すでに入っているもの**：上下反転（bswap）で斜めをまとめる SIMD の着手生成、マスごとに分けた石を返す計算、最後の1手の石数の表引き、2マス空きの「隣に相手の石があるか」の前判定、4〜7マス空きの偶数理論の並べ替え（3マス空きは1個だけの区画を先に）、確定石による枝刈り、評価の添字の SIMD 更新と手を戻すときの保存。
- **wasm では使えないもの**：置換表の先読み（prefetch）、CRC32C のハッシュ命令、AVX2 の256ビット・gather・PEXT。
- **試す価値があるもの**：
  1. **着手生成を普通の整数演算で**（解説：Arm では SIMD より整数8方向のほうが速い。+1方向は桁上がりで求める）。本作の wasm は SIMD 版で、採用時の計測は x86 の作業機。Mac・スマホは Arm なので測り直す。試験ビルド `g1`（今のスカラー版）・`g2`（解説の形）。作業機（x86）では g2 が中盤 ×1.006・終盤 ×0.952（揺れ ±5% の中）。
  2. 最後の1手で、手番側が打てないとき値が α 以下に決まるなら相手側の石数を数えない（lazy cut-off）。小さい。
  3. 完全読み・勝敗読みで、置換表の手が今より4手以上浅い読みのものなら優先しない（"Othello is solved" の変更）。
  4. 空き7〜14マス専用の小さな置換表（Edax はスレッドごと 1024 個＝24KB で約10%）。本作は 512KB で試して −3〜4%（見送り）。もっと小さい表は未計測。
```sh
cd reversi && git pull
node tools/variant-bench.js --variants g1,g2,lc,g2_lc --n 12 --depth 19 --empties 22 --rounds 4     # 約5分
```
**Mac の結果（M4 Pro、2026-11-20、4回のうち最短、手と値はすべて同じ）**

| ビルド | 中盤（深さ19×12局面） | 終盤（空き22の完全読み×12局面） |
|---|---|---|
| 今の版（SIMD の着手生成） | 1.34秒 | 3.92秒 |
| g1 | ×1.004 | ×0.988 |
| g2 | ×0.975 | ×0.978 |
| lc | ×1.009 | ×1.006 |
| g2_lc | ×0.989 | ×0.977 |

- `g2`（整数演算・桁上がり）は約2%速い。**2026-11-21 に採用**（Edax と同じ時間で互角まで来たので、数%の高速化も切り捨てずに積む方針に変更。手・値・局面数が同じ変更は、Mac で 1%以上速ければ入れる）。以前の SIMD 版は試験ビルド `g0`。`lc` は効果なし（×1.006〜1.009、見送り）。
- 細かい高速化で届くのは数%まで。10%以上を狙えるのは「評価から着手可能数を外す（学習のやり直し）」と「空き7〜14マス専用の小さい置換表」。

`lc`＝上の 2.（最後の1手の省略、`-DLAZYCUT`）。手と値は同じで、数える局面数だけ減る。作業機（x86・2コア共用）は揺れが ±5% 以上あり、数%の差は判定できなかった。
出力の「今の版との比」が 0.97 未満なら、その方式を wasm の既定にする（読みの内容は同じ。スマホでも確かめる）。

### 着手可能数なしの評価（2026-11-20、準備済み・Mac で学習待ち）
1スレッド・同じ時間で Edax と互角なので、次は1局面を軽くして同じ時間で深く読む。評価の着手可能数（1評価で着手生成2回）を外した重みを学習し、Edax 相手に同じ時間で比べる。学習ツールに `--ext 0`、`edax-anchor.js` に `--weights` を足した。手順は `reversi/tools/train/README.md`「着手可能数なしの評価を試す」（学習3本を夜に、翌日に比較30分）。作業機の動作確認（でたらめな重み）では毎秒の局面数が 216万 → 403万（読む木が違うので参考値。学習後に `nps.js` で測る）。

### 将棋の記録（`claude/shogi-search-comparison.md`）から取り入れたこと（2026-11-19 見直し）
将棋で成果が出たやり方と突き合わせて、最初の案を次のように直した。

| 設定 | 意味 |
|---|---|
| d（深さ） | 中盤の読みの深さ |
| t | 中盤と「終局まで読む」の枝刈りの強さ（小さいほど強く切る。今は 1.5、Edax・Egaroucid の中盤は約1.1） |
| x（完全読み／勝敗読み） | 読み切りを始める空きマス |
| e（終局まで読む） | この空きマス以下で、確率つきで終局まで読む |
| k（ENDK） | 終局まで読むときの誤差幅を何%にするか（今は 100。実測では幅が足りていないので 130〜200 を試す） |
| nn（MPC_NONEST） | 試しの読みの中では枝刈りをしない（Egaroucid の方式） |
| p（MPC_PRE） | 静的評価が境から p/100 石以内のときだけ試しの読みをする（Edax の方式） |

k・nn・p は `engine.c` のテスト用ビルド（`frontier.js` が自動で作る。付けなければ公開中の wasm と同じバイナリ）。

### A0：Edax を物差しに（最初に）

- 自前は wasm の1スレッド、Edax はネイティブ（1スレッド）。Edax は1手ごとに起動するので、時間は Edax が表示する読みの時間を使う。
