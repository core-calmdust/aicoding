## わかっていること（作業機、2026-11-18）
- 評価関数の精度・同じ深さの手の質は、**空き16〜22マスでは** Edax 4.7・Egaroucid 7.8 と同じ水準（同じ局面で実測）。空き27〜45マスでは手番側への一定のずれ（偶数の空きで +1.5〜2石、奇数で −1〜3石）があり、それを除いた誤差は同じ水準（下の「評価関数の再確認」）。中盤の同じ深さまでの速さは同等。
- 完全読みは Edax の約2倍・Egaroucid の約2.8倍の時間。1つの大きな原因は見つかっていない。
- 定石は本線が正しく、手順に幅を持たせると黒が損をする（Lv.22〜36 は幅を 0.3石に変更済み）。大きさは Egaroucid の約1/100。
- これまでの検証は「1つの設定を変えて同じ時間で比べる」形がほとんどで、**設定の組み合わせ**と**今よりずっと長い時間**は調べていない。将棋で、局面数を10倍以上にしたときと、複数の設定を同時に変えたときに大きく伸びた例があるので、リバーシでも同じ形で確かめる。

## 「わかっていること」の確かさ（2026-11-19 追記、将棋の計測を受けて）
将棋で同じ日に、**自己対局で +290 の改良が、外の相手（技巧2）には +50 程度**という結果が出た（`claude/shogi-search-comparison.md` §0.13）。「部品ごとの比較をつないで全体の強さを言う」推論が外れた例なので、上の「同じ水準」も同じ目で見直した。
- **信頼できる点**：評価関数の精度は、完全読みの正解に対する誤差を Edax・Egaroucid と同じ局面で比べた数字（自分どうしの比較ではない）。選んだ手の石損も比べている。将棋の「学習の誤差」「自己対局」より強さに近い物差し。
- **足りない点**：(1) **同じ持ち時間での直接対局がない**。「Lv.21 が Edax レベル15 と互角」は深さ固定の Edax との比較で、同じ時間で何 Elo 違うかは未計測。(2) Egaroucid との実戦は2〜4局で、何も言えない局数（将棋では240局の +58 が偶然だった）。(3) 誤差の平均が同じでも強さが同じとは限らない（将棋・氷彗の記録とも、誤差の指標と対局の結果が合わなかった）。
- **したがって**：「評価関数・中盤は同じ水準、差は完全読みと定石だけ」は**仮説**として扱う。確定には、**同じ時間の Edax・Egaroucid に対して数百局**（黒番・白番別、定石あり／なし別）の結果が要る。下の A0 を最優先にし、深さ固定ではなく時間をそろえた表で読む。ここで大きく負け越すなら、評価関数・中盤にも差が残っていることになり、検証 A〜D の優先順位を組み直す。

## 評価関数の再確認：差の正体は「手番側への一定のずれ」（2026-11-20、作業機。同日の前の版を訂正）
**訂正**：この節は最初「空き36・44マスでは自前の誤差が1〜4割大きい。教師が弱い見立て」と書いたが、数字を分けて見ると、大きい分は**一定のずれ（偏り）**で、局面ごとの見分けは Edax・Egaroucid と同じだった。

測り方：Edax と Egaroucid の読み（レベル14〜24）を正解役にし、**相手側の正解役**で比べる（自前 対 Egaroucid は Edax が正解役、自前 対 Edax は Egaroucid が正解役）。100〜120局面ずつ、MPC なしの全幅読み。「偏り」は値−正解役の平均（＋は手番側に甘い）、「除いた誤差」は偏りを引いたあとの平均絶対誤差（石）。深さ6 の行：

|---|---|---|---|
| 45 | −1.67 ／ −2.84 | 1.37 対 1.53 | 1.51 対 1.61 |
| 44 | +1.77 ／ +2.02 | 1.49 対 1.59 | 1.56 対 1.74 |
| 43 | −0.82 ／ −2.11 | 1.25 対 1.38 | 1.30 対 1.58 |
| 37 | −1.06 ／ −2.60 | 1.49 対 1.57 | 1.52 対 1.60 |
| 36 | +1.54 ／ +1.90 | 1.51 対 1.69 | 1.50 対 1.62 |
| 35 | −1.61 ／ −2.89 | 1.66 対 1.77 | 1.80 対 2.01 |
| 29 | −1.31 ／ −2.90 | 1.85 対 1.96 | 1.57 対 1.74 |

- **偶数の空きマスでは手番側に約 +1.5〜2石甘く、奇数では約 1〜3石辛い**（1手ごとに約3.5石ゆれる）。深さを変えてもほぼ同じ。完全読みが正解の空き12〜22マスでも同じ向き（偶数 +1.1、奇数 −1.9。2,600局面）。
- **偏りを除くと、誤差は Edax・Egaroucid と同じか少し小さい**（全部の段・深さで）。「序盤〜中盤の見分けが弱い」は誤りだった。
- 正解役どうしも奇数の段では約1.3石ずれる（Edax と Egaroucid の間。偶数では 0.3石）。ゆれは程度の差で他ソフトにもある。
- 原因の見立て：重みは2手ごとの段（30段）で、段の中の定数が1つ。学習の正解（対局の最終石差）の平均は1手ごとに符号が入れ替わるので、1つの定数では合わせられない（`rvtrain.c` に同じ注記）。
- **強さへの影響は小さい見込み**：同じ深さの読みでは末端がすべて同じ偶奇なので、手の選び方は変わらない。効くのは、終局までの読みの枝刈り（浅い読みの値と完全読みの値を比べる所）、読みの窓、定石の値との混ざり。
- 作業機の試し（`-DEVOFF_E=150 -DEVOFF_O=190`：偶数で −1.5石、奇数で +1.9石の補正。Lv.28 の設定どうし、400序盤×2局）：深さ13 で **+6 ± 4 Elo**、深さ14 で **+5 ± 5 Elo**、時間は同じ（×0.98〜1.00）。向きは良いが有意とは言えない大きさ。作業機では局数が足りないので Mac で確かめる（検証E の 0.）。
- 道具：`tools/eval-accuracy.js` は偏りと「除いた誤差」の表も出すようにした。`engine.c` の `-DEVOFF_E`・`-DEVOFF_O` は試験ビルド専用（付けなければ今までと同じバイナリ）。

（最初の計測：空き44・36、120局面、レベル24。平均絶対誤差は 空き44・深さ6 で 自前 2.16 対 Egaroucid 1.52、自前 2.63 対 Edax 1.85。この差が上の偏りの分。）

## 検証A：読みの設定の組み合わせ（`tools/train/frontier.js`・`tools/edax-anchor.js`）
### 将棋の記録（`claude/shogi-search-comparison.md`）から取り入れたこと（2026-11-19 見直し）
将棋で成果が出たやり方と突き合わせて、最初の案を次のように直した。
1. **外の物差しを先に置く**：将棋は「同じ評価関数でやねうら王の探索に載せ替える」実測で、差が探索にあると確定してから進めた。最初の案は自前どうしの対局だけだったので、**Edax を同じ表に載せる**（A0）。自前の設定が Edax の線にどこまで近いか・どの時間帯で離れるかが分かる。
2. **深い読みで測る**：将棋では、浅い条件（2万局面）で「弱くなる」と出た枝刈りが、深い条件（30万局面）で逆転した。リバーシのこれまでの結論（t を下げても同じ、など）は 1手100ms や Lv.28（深さ13）の浅い条件のもの。**基準を Lv.31（深さ20）・Lv.34（深さ25）にした計測を必ず行い**、採否はそちらで決める。
3. **数値だけでなく仕組みも組み合わせる**：将棋では「単独では −133 の枝刈りが、ほかの仕組みと組んで基準をゆるめると働いた」。数値（深さ・t・範囲）だけでなく、**枝刈りのまわりの仕組み**（試しの読みの中では枝刈りしない＝Egaroucid、静的評価で試すかどうかを決める＝Edax）を t と一緒に動かす計画（mech）を足した。
4. **対局の数え方**：将棋では同じ対局を重ねて数えていた誤りがあった。`rvmatch` は別々の序盤（`op10.bin` は3,000個）を先後入れ替えて使い、誤差は序盤の組ごとに出すので、この問題はない。**`--n` は 3000 以下にする。**
5. **1つずつの段が終わったら同時調整**：良い向きが分かった数値は、深い条件で同時に動かして合わせる（将棋の SPSA に当たる。道具はまだなく、A3 までの結果を見てから作る）。

### 設定の意味
| 設定 | 意味 |
|---|---|
| d（深さ） | 中盤の読みの深さ |
| t | 中盤と「終局まで読む」の枝刈りの強さ（小さいほど強く切る。今は 1.5、Edax・Egaroucid の中盤は約1.1） |
| x（完全読み／勝敗読み） | 読み切りを始める空きマス |
| e（終局まで読む） | この空きマス以下で、確率つきで終局まで読む |
| k（ENDK） | 終局まで読むときの誤差幅を何%にするか（今は 100。実測では幅が足りていないので 130〜200 を試す） |
| nn（MPC_NONEST） | 試しの読みの中では枝刈りをしない（Egaroucid の方式） |
| p（MPC_PRE） | 静的評価が境から p/100 石以内のときだけ試しの読みをする（Edax の方式） |

k・nn・p は `engine.c` のテスト用ビルド（`frontier.js` が自動で作る。付けなければ公開中の wasm と同じバイナリ）。
