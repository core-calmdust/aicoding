# ウル王朝のゲーム（ur/）設計仕様

世界のボドゲ大百科の新タイトル。新カテゴリ「ヒストリカル」（cat: `hist`）の第1作。
テーマは「歴史浪漫」：約4500年前、ウル王墓（レナード・ウーリー発掘、1922〜34）から出土し大英博物館が所蔵する盤（BM 120834）を、2Dでも3Dでも現物同等の見た目で遊ぶ。

**必読**：プロジェクト共通仕様（`claude/game-conventions.md` ＋ 追補 `claude/game-conventions-addendum.md`。リポジトリには無いので本書末尾の要約と、手本ゲームのコードで確認）。手本：構造は `fanorona/`（最新のテンプレ一式）、サイコロ・レース系の挙動と横長盤のレイアウトは `backgammon/`、3Dスキンは `atlas/skin/checkers.js`・`atlas/skin/backgammon.js`、3Dサイコロは `backgammon/dice3d.js`。

## 1. ルール（フィンケル・ルール ＝ 既定）
アーヴィング・フィンケル（大英博物館）がバビロニアの粘土板（紀元前177年、書記イティ・マルドゥク・バラートゥ）から復元したルール。現在もっとも広く遊ばれる標準。
- 2人、各7枚。4個の四面体サイコロ（4つの頂点のうち2つに白い印）。振って上を向いた白い印の数＝進む数 0〜4（確率 0:1/16, 1:4/16, 2:6/16, 3:4/16, 4:1/16）。
- 各自の道は14マス：自分の列の4マス → 中央の列8マス（共有）→ 自分の列の2マス → ゴール（盤外）。
- 1回に1枚を出た目だけ進める（盤外からの入場も1枚）。自分の駒がいるマスには止まれない。ゴールはちょうどの目でのみ（14マス目の先＝15がゴール。超える目は不可）。
- 相手の駒がいるマスに止まると取る（相手の駒は盤外へ戻る）。取れるのは共有の中央の列だけ（自陣の列には相手は来ない）。
- ロゼット（花のマス：道の4・8・14マス目）に止まるともう一度振れる。中央のロゼット（8マス目）にいる駒は取られない（そこに相手がいれば止まれない）。
- 0の目、または動かせる手がないときはパス。先に7枚すべてゴールさせた方の勝ち。
- 先手：対局設定で選択（既定：ランダム＝両者1回ずつ振って大きい方、同点は振り直し…ではなく単純にランダムでよい）。

### ルール違い（ゲームタブに絵と説明付きカードで並べる）
- `finkel` フィンケル（既定）— 上記。
- `blitz` ブリッツ — 各5枚、マスターズ経路（16マス）、取るともう一度振れる、ロゼットは安全ではない（RoyalUr.net の Blitz。確定）。
- `masters` マスターズ — 各7枚、マスターズ経路（自陣 列3→0 → 中央 列0→6 → 相手の列 列6→7 → 中央 列7 → 自陣 列7→6、16マス）、サイコロ3個（0は4として数える）、ロゼットは安全ではない、取っても追加手番なし（確定）。
- 出典と確認方法は `ur/tools/RULES-RESEARCH.md`（RoyalUr の完全解析表との一致で検証済み）。
ルールの確実性を優先：調べて確証の取れない細則は入れない。

## 2. 盤の座標
- 盤は 3行×8列。存在するマス：行0・行2は列0〜3と列6〜7、行1は列0〜7（全20マス）。列4・5の行0/2は空き。
- 横向き（PC・既定）：行0＝上＝side 1（暗＝黒の駒）の自陣、行2＝下＝side 0（明＝貝殻の白い駒）の自陣。左が大きいブロック（4列）、右が小さいブロック（2列）。
- 道（path index）：0＝盤外（未入場）、1〜14＝盤上、15＝ゴール。自陣の行 L（side0→2、side1→0）として
  - i=1..4 → (L, 4−i)（列3→0）、i=5..12 → (1, i−5)（列0→7）、i=13..14 → (L, 7), (L, 6)
  - ロゼット：(L,0)=4, (1,3)=8, (L,6)=14。つまり盤のロゼットは (0,0) (2,0) (1,3) (0,6) (2,6)。
- 各マスの文様（大英博物館の盤どおり。添付写真で確認済み）：
  - 行0・行2：列0 ロゼット／列1 目の文様（eyes：2×2の目＋間の梯子文）／列2 五つ円（circles5：二重円5つ、中心はラピス）／列3 目の文様／列6 ロゼット／列7 ジグザグ枠に5点（zig5）
  - 行1：列0 点の格子（dotgrid：4つの小区画に点）／列1 五つ円／列2 四つ割り点（dots4：ジグザグ縁の小区画4つにそれぞれ5点）／列3 ロゼット／列4 五つ円／列5 四つ割り点／列6 目の文様／列7 五つ円
- 盤の素材（原本）：白い貝殻の象嵌（少し黄ばんだ乳白色、黒い線刻）、マスの間はラピスラズリの帯（深い群青、まだら）、ロゼットの花弁は赤（紅玉髄・赤い石灰岩）とラピス、外枠は黒い瀝青（ビチューメン）、周縁に貝殻の小さな菱形と赤い菱形の帯、箱の側面は赤い石灰岩と貝殻の縦の短冊＋目の文様の板。
- 駒：白＝貝殻の円盤にラピスの点5つ（サイコロの5の配置）、黒＝黒い頁岩（シスト）の円盤に貝殻の点5つ。
- サイコロ：四面体（正三角錐）、白っぽい素材で2つの頂点に印（原本は貝殻・ラピスの象嵌付き）。

## 3. 2Dデザイン（対局設定のデザインタブ。盤と駒は別々に絵のタイルで選ぶ）
- 盤：①大英博物館（原本・既定：経年の色、欠け・ひびの風合い）②復元（作られた当時の鮮やかな色）③木製（レーザー彫刻の木工キット風。参照：薄い木の盤）④粘土板（素焼き・刻線の簡素な盤）
- 駒：①貝殻×頁岩（原本）②象牙×黒檀 ③木（明るい木×焼き色）④金×ラピス
- 描画は `ur/board2d.js`（下記API）。2Dでも原本の質感（象嵌の盛り上がり、刻線、ラピス帯の粒、瀝青の艶）を出す。WebP画像を使ってもよい（`ur/img/`、生成スクリプトは `ur/tools/`）。

### 4.1 エンジンAPI（`window.UrEngine`、Node でも `require` 可。依存なし）
```
RULES: { finkel:{pieces:7, ...}, blitz:{...}, masters:{...} }
newGame(rule='finkel') → state
  state = { rule, pos:[Array(n), Array(n)] /* 各駒の path index 0..15 */, turn:0|1, winner:-1|0|1 }
coords(rule, side, i) → [r, c] | null    // i=1..14（盤上）
isRosette(rule, side, i) → bool;  ROSETTES_RC: [[r,c],...]
rollDice(rng=Math.random) → { dice:[0|1,0|1,0|1,0|1], n }   // dice[k]=1：その四面体の白い頂点が上
PROB: [1,4,6,4,1].map(x=>x/16)
legalMoves(state, n) → [{ piece, from, to, capture:bool, rosette:bool, finish:bool, enter:bool }]  // 同じ from の重複は1つにまとめる（盤外からの入場は1手）
apply(state, move|null) → { state, again:bool }   // null＝パス。again＝もう一度振れる
key(state) → string（同一局面判定）
winProb(state) → 手番側（これから振る側）の勝率 0..1
evaluate(state, n) → [{ move, wp }]（良い順。wp＝その手を指した後の自分の勝率）
think(state, n, level 1..20, opts) → move     // 弱いレベルはわざと誤る（確率的）。強いレベルは期待値探索
resist：負けが確定的な局面でもいちばん粘る手（相手の取りを避ける・ロゼットを守る）を選ぶ
```
マルチスレッド（2026-11-08、`shared/mtworkers.js`、addendum「本編のマルチスレッド」）：`splitEval(state, n, depth)` が `evaluate` を「手 × 次の出目」の仕事 `{ state, n, d }` に分け、`worker.js` の `'roll'`（`rollTask`）を Worker のプールで並べて読み、`combine` で `evaluate` と同じ数値に戻す（Node で 1,188 手を照合して一致）。使う所：Lv.20 の AI の手（2投先。1スレッドでは 80 ミリ秒で打ち切る上限つき）、ヒント（スレッドがあると3投先、なしは2投先）、振り返り（`'review1'` で局面ごと）。`think(…, { ev })` はスレッドで読んだ評価から選ぶ（乱数・粘りは同じ）。Lv.1〜19 は一瞬で終わるので1スレッド、最上位の追加はしない（Lv.20 が完全解析表に対し平均損失 約0.01%／手）。計測：`ur/bench.html`（どこからもリンクしない）。
- ユーザーの Mac（M4 Pro 14コア＝高性能10＋高効率4、Chrome、2026-11-09）の実測（上の方式、深さ3）：2・4・8・14スレッド ×1.93／×3.42／×5.23／×5.51。8 以降が伸びない原因は仕事の数：「手 × 出目」は1局面 10〜20 個（平均15）しかなく、8〜14 スレッドではいちばん重い仕事を待つ時間が大半になる（作業機で仕事ごとの時間を測ったシミュレーションでも同じ形：8 ×5.7、14 ×7.6〜8.0）。また Worker の数は `min(コア数 − 1, 7) + 1`＝8 が上限で、アプリでは 14コアのうち 6 が遊んでいた。
- **2026-11-09 の改善**：重い局面（3投先以上、`E.fineFor(d, threads)`＝スレッド数の3倍の仕事）は、手の多い「手 × 出目」からさらに「その出目の手」ごとの仕事 `{ state, n, d, k }` に分け（`rollTask(state, n, d, k)`、`combine` は `bestAfterRoll` と同じ最大を取るので同じ数値。Node で 24局面 × 3通りの分け方を照合して一致）、重そうな順（手の数）に配る。2投先（Lv.20、1局面 約3ミリ秒）は分けると通信の分だけ遅くなるので今まで通り。Worker の数は PC で全論理コア（`MTWorkers.use({ all: true })`、最大16、スマホは 3 + 1）。見積もり（作業機、1仕事 0.15 ミリ秒の通信込み）：8 ×5.7 → ×6.9、14 ×8.0 → ×10.6。Mac で測り直すページ：`ur/bench.html`。
AI：期待値最大化探索（expectiminimax）＋よく調整した評価関数。レベル20は可能ならほぼ最善（RoyalUr.net の強いAI相当）。軽量であること（スマホで1手0.5秒以内が目安）。可能ならオフラインで強化した評価表（数百KB以内、gz）を使ってよい。

### 4.2 2D描画API（`window.UrBoard2D`）
```
mount(el, { orient:'h'|'v', design, pieces, interactive }) → view
view.render(state, { sel, targets:[{r,c,...}], last:{from,to}, hint, marks })
view.cellRect(r, c) → DOMRect;  view.offRect(side, 'start'|'goal')
view.setDesign(design, pieces); view.setOrient('h'|'v')
view.on('cell'|'piece'|'tray', fn)
view.animateMove(side, from, to, {capture}) → Promise
UrBoard2D.dice(el, { style }) → { roll(dice) → Promise /* 転がる演出 */, show(dice) }
UrBoard2D.mini(state, { design, orient, marks, crop }) → SVG文字列（チュートリアル・一覧カード用。本物の盤と同じ絵）
```
- 縦向き（スマホ縦）：盤を時計回りに90°回した形（3列×8行。自分の陣＝右列…ではなく**自分の陣が手前（下）に来る**よう、横向きの行2が右列、行0が左列、大きいブロックが上）。担当Vと担当Aで実際に見て決めてよい。
- 盤外の駒（未入場7枚・ゴール済み）は盤の両脇（横向き：未入場は大ブロック側の空き＝列4・5の上下の空間も使ってよい、原本は列4・5の行0/2が空いている）に整列して見せる。

### 4.3 3Dスキン契約（`?skin=atlas`）
- チェッカー・バックギャモンと同じ方式：DOMの盤（透明）を上に残してタップ・選択・印を受け、three.js の盤をDOMの盤に合わせて置く。駒はDOMの状態を写す。
- 本体（担当A）は次を用意する：`window.UrSkinHooks = { sync(state), animateMove(side, from, to, info) → Promise, animateRoll(dice) → Promise, orient() → 'h'|'v' }` を**呼ぶ側**として、`window.UrSkin3D` が存在すればその関数（同名）を使い、なければ2Dの演出。
- 3Dのサイコロ：四面体4個を盤の脇（各自の側）で転がし、白い頂点の数が分かる止まり方。
- 負荷：`claude/game-conventions.md` の3D規定（オンデマンド描画、`T3.kick(ms)`、影マップ1024、スマホ pixelRatio 1.5）。三角形数 展示盤8万以下。駒は形・材質を共有（自動インスタンス化）。

## 5. 画面と機能（担当A。全テンプレを踏襲）
- テーマ色：夜のメソポタミア＝深い群青（ラピス）＋金＋紅玉髄の赤。台帳の色 `#2a3f9e`（他と被らない）。UIフォントは既存と同じ系、見出しにセリフ体（Cormorant Garamond 等）を使ってよい。
- 横長盤なのでPCは**追補の「横長盤のPCレイアウト」**（盤を上段に横幅いっぱい、情報を盤の下に横一列：コーチ1/2・形勢1/4・棋譜1/4 など）。スマホ縦は盤を縦向きに。
- ヘッダーバー（`shared/headerbar.js`）：対局＞待った＞投了＞ヒント＞ルール＞レッスン＞パズル、戦績。右側アイコン：サウンド→言語→ホーム。
- 対局設定（`shared/ngtabs.js`、ポーカー準拠3タブ：ゲーム｜ルール｜デザイン）：対戦形式（AI／二人／AI同士／レート戦）、AIの強さ20段階、先手、持ち時間なし／1手30秒／フィッシャー（`shared/fischer.js`、各自の持ち時間 `game.fz`、1手ごとに加算。レート戦・オンラインは1手30秒のまま）、アニメ速度、ルール違い（ゲームタブ）、盤・駒（デザインタブ、絵のタイル 4×1 ずつ）。［閉じる］［対局開始］。
- サイコロ：振るボタン（スペースキー・盤タップでも）、自動で振る設定。出目の確率表示（コーチ）。
- レート戦（ソロ、`shared/placement.js` の予備選）、戦績（`shared/record.js`）、投了（`shared/resign.js`）、コーチ（`shared/coachkit.js` ＋ `ur/coach.js`：勝率、レース差、中央ロゼットの確保、取られる確率、推奨方針、分かれ道）、振り返り（各手の勝率損失：最善／悪くない／疑問手／悪手、PCは振り返りボックス `rvbox.js`）、棋譜（例：「明 3：入場→3」「暗 2：7→9 ×取り」「ロゼットでもう一度」）、←→キーで手順送り。
- オンライン：「準備中」表記（Firebaseプロジェクトは後日ユーザーが作成）。
- 10言語（ja, en, zh, ko, es, fr, pt, de, hi, ar。ar は RTL）。
- localStorage：`aicoding-ur`（設定・対局）、`aicoding-ur-rated`、`aicoding-ur-lessons`、`aicoding-ur-puzzles`、記録は `atlas-rec-ur`。
- 共通アカウント3行（atlas.js / atlas-firebase-config.js / atlas-account.js）を `</body>` 前に。

## 6. 学ぶ（担当L）
- **ルールのチュートリアル（最重要）**：`shared/ruletour.js` の枠で、**本物の盤（board2d.js の同じ絵）を使って**実際にサイコロを振り・駒を動かす。1ページ目はゲーム紹介（歴史：ウル王墓、ウーリー、紀元前2600〜2400年頃、フィンケルの復元、地中海〜インドまで広がり、インド・コーチンのユダヤ人社会で20世紀まで遊ばれた、など確実な事実のみ）。続いて：盤と道順（光る矢印で道をたどる）→ サイコロ（4個振って白い印を数える）→ 入場 → 進む → 自分の駒には止まれない → 取る → ロゼットでもう一度 → 中央ロゼットは安全 → ちょうどの目でゴール → 0・動けないときはパス → 勝ち方 → これで遊べます。各ページに課題、正解で自動で次へ。本文は日本語2行程度、10言語。
- レッスン：概念→例題→練習→採点問題の段階化（`ramp`）。題材：確率（各目の確率と「取られる確率」の数え方）、ロゼットの価値、中央ロゼットを占拠する、安全なマスと危険なマス、入場か前進か、取りに行くか、終盤のゴール、ブリッツの取り返し等。満点20・合格75。
- パズル：「次の一手」（局面＋出目、エンジンで最善手が明確に良いものを厳選、200問程度、難易度カテゴリ別）。`claude/puzzle-collection-spec.md` の一覧ホーム型（`shared/pzbook.js`）。

## 共通仕様の要点（抜けやすいもの）
- 読み込み直後に対局設定ダイアログを自動で出さない。結果ダイアログはその場で終わったときだけ。
- ボタン：否定・キャンセルが左。ボタン文字は折り返さない。
- `prefers-reduced-motion` で演出を省略しない（ゲーム内設定のみ）。
- 正解音・やさしい誤答音。タブを隠したら音を止める。
- ルール説明はチュートリアル式（`shared/ruletour.js`）、一覧のタブ順：ルール → レッスン → パズル。一覧ダイアログの大きさは固定、閉じる等のボタンは下端に固定。
- レッスン・パズルのカード操作は `shared/cardbar.js`（「〈モード名〉をやめる」の文字ボタン）。
- スマホ下部タブ（`shared/infotabs.js`）：コーチ｜形勢｜棋譜｜戦績｜オンライン。スマホ縦の間隔は全部8px。
- コーチ候補の盤上の印は明るい緑 #3df59a＋暗い縁。
- 3D版：ポータルから `?skin=atlas` で起動、PCでロゴの右にゲーム名（headerbar.js が行う）。
