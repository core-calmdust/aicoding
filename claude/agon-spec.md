# アゴン（agon/）仕様

URL: https://core-calmdust.github.io/aicoding/agon/ ／ トップはアルケルケの次（cat: chess、定番タグ、オンラインは準備中）

## ルール（Ludii「Agon」＝1842年の原典準拠、Wikipedia・boardandpieces で確認）
- 91マスの六角形盤（6つの輪＋中央の王座）。各自 女王1・ガード6。初期配置は Ludii の Agon.lud（外周に交互、180°回転対称、白が下・先手）。
- 手番：1枚を隣の空きマスへ1歩、同じ輪か内側の輪のみ（外へ戻れない）。王座は女王だけ。相手2枚に一直線にはさまれるマスへは入れない。
- 捕獲：動かした駒と自分の駒で相手の駒を一直線にはさむ。捕まった駒は盤に残り、持ち主が次の手番で置き直す（女王→王座以外の空きマス、先に女王。ガード→外周の空きマス、1手に1枚）。置き直しは捕獲しない。置き直し先もはさまれるマスは不可（他に無い時のみ可）。
- 勝ち：自分の女王が王座＋周りの6マスが自分のガード。空の王座（または相手の女王）を自分のガード6枚で囲むと負け。動けない時はパス。
- 引き分け（本サイトの設定）：同一局面3回、300手。
- 種目：std（標準）、place（1842年原典の配置：女王だけ角、ガード12枚を交互に配置してから開始、配置は捕獲なし）。

## エンジン（engine.js、純JS、Worker）
- 盤 Int8Array(91)（1白ガード 2白女王 3黒ガード 4黒女王）＋ cap フラグ。手 m = from + 92×to（from 91＝手持ちから配置）、PASS=92²。
- 表記：輪.番号（左上の角から時計回り、王座は T）。例 5.12-4.10x、2.4>5.17（置き直し）、+2.5（配置）、Q は女王。
- 評価：歩数（女王→王座、ガード→1の輪）、王座・内周、敵の内周ブロック、捕獲待ち、はさまれる駒。negamax＋TT＋捕獲の静止探索、引き分けに contempt 30。負け確は Engine.resist。
- 23段階：15級〜5級は深さ1〜4＋ノイズ・見る駒数・悪手率、4級〜三段はノード数、四段・五段は1.2/2.5秒（上位が下位に負けないことを対局で確認）、Lv.21〜23 は5秒・10秒・20秒（全スレッド、2026-11-09、下の「最上位レベル」）。
- 勝ち切りソルバー duelGood / duelMin / duelReply（need＝女王の歩数＋足りないガード）。
- 高速化（2026-11-08、結果は不変）：探索の子局面は手ごとの clone でなく深さごとに1つ使い回す（`child()`）、評価のはさまれ数は割り当てなしの `hangN`、同一局面チェックは数値の配列、手の並べ替えは安定な挿入ソート。2ルール×レベル8/13/17・各40局面で手・評価値・深さ・局面数が完全一致のまま **約2倍**。

- 盤（tools/gen_art.py、1024px、セル中心は 512+(q+r/2)·80, 512+r·69.28）：ヴィクトリア朝（既定・ユーザー指定）・アメリカ民芸盤（参考画像の19世紀塗装盤）＝ヒストリカル、ウォールナット・スレート＝モダン。駒：骨と黒檀（既定）・手塗りの木・セラミック・真鍮と鋼（ガード＝円盤、女王＝六角形＋王冠）。保存済み設定は dv2 フラグで一度だけ既定へ切替。
- 対局設定は shared/nglux.js の Luxury レイアウト。先手＝白（ng.first / ng.second を上書き）。
- 盤の上下：女王の着座（♛）とガード n/6、置き直し・手持ちの数。捕まった駒は赤い点線＋↺。置き直し・配置の手番は行き先を自動表示（駒を選ばなくてよい）。
- ルール説明（RuleTour、実際の盤で操作）：紹介→盤と輪→駒→動き方→外へ戻れない→王座→捕獲→置き直し→女王の置き直し→はさまれるマス→勝ち→空の王座→もう1つの始め方と引き分け。
- レッスン12（tools/gen_lessons.js、正解集合はルール／エンジンで計算、検証 tools/check_lessons.js）：はじめて6（内側へ1歩・女王を王座へ・はさんで捕獲・置き直しの場所・危ない駒を守る・完成させる）、作戦6（相手の完成を止める・王座の女王を捕まえる・2枚同時・どれを捕まえる・2手で勝つ・実戦の最善手）。準備（ramp）は tools/lesson_ramps.js＋ramp_text.js。
- 序盤（tools/gen_openings.js）：名前のある定跡は伝わっていないため、エンジンによる作戦3つ（女王から進む・ガードの壁・内周の取り合い）。
- パズル＝勝ち切りパズル152問（tools/gen_pz.js 構成局面＋gen_duel.js 実戦 → build_pz.js）：x2（2手以内）8問、w3/b3, w4/b4, w5/b5 各24問。x2 は単純すぎるとのユーザー指摘で24→8問に削減（2026-11-05）。

- オンライン：firebase-config.js が null → 準備中表示。手の符号化は3文字（下位6bit×2＋上位bit）。
- アイコン：トップ images/icons/agon.svg、ポータル3D atlas/icons3d.js の agon() → images/atlas/agon.webp（atlas/app.js の R3）、ゲーム一覧サムネ atlas/shots/agon.webp：いずれもヴィクトリア朝の盤と骨の女王。トップのSS images/agon.webp は民芸盤のまま（ユーザー指定）。

## 3D（ポータル、2026-11-05）
- 盤は2種（ユーザー指定：2Dにもあるアメリカ民藝盤＝しっかり劣化させる／文化的背景のあるもの＝1842年ロンドンのヴィクトリア盤）。atlas/models/agon.js の board('folk'|'victorian')、1マス（中心間）＝1、盤＝12.8角（2D画像そのまま）。
- テクスチャは gen_art.py の `3d` モード（`python3 agon/tools/gen_art.py 3d`）が書き出す agon/img/3d-<look>-c|n|r.webp（陰影なしの色・高さ場からの法線・G粗さ/B金属）。2Dの bd-*.webp は書き換えない。3D民藝盤は2Dより劣化を強める（木目に沿った割れ2本、角の欠けと摩耗）。
- 民藝盤：厚い松板、縁は不規則に欠けた輪郭（角も丸く摩耗）、側面は素地の松に緑の地塗りの垂れと汚れ。駒はミルクペイントの木（クリーム地に赤の輪・黒地にからし色、ひび・剥げ）、女王は六角形に描いた王冠。
- ヴィクトリア盤：磨いたマホガニー＋金の罫・フルーロン・王座の六芒星（金属）、丸い面取りの縁。駒は骨と黒檀の挽き物（面に轆轤の溝）、女王は六角形＋王冠の象嵌（骨の女王に黒檀、黒檀の女王に骨）。
- 三角形数：盤 約2.7万（駒込みでも8万以下）。ショーケースはヴィクトリア盤（scale .74）。
- フル機能（agon/?skin=atlas、atlas/skin/agon.js）：デザインタブの先頭に「3D ヴィクトリア盤」「3D 民藝盤」の2タイル（2D盤を選ぶとポータル枠の2D画面）。選択は localStorage atlas-agon-look（folk / victorian / 2d）、最後の3D盤は atlas-agon-look3（ちゃぶ台・ルールコースもこれを使う）。3D時は駒デザイン欄を隠して説明文。駒は syncPieces/animateMove をミラー：一歩＝滑る、置き直し＝持ち上げて弧、配置＝落とす、捕まった駒は傾く（赤い点線リングはDOM）。persp:10、outer に上下のプレート（0.75マス）を含める。
- ちゃぶ台（atlas/games/agon.js）：std ルール、Lv1〜20、置き直しは捕まった駒が1枚なら自動選択、六角形のマーク。
- ルールコース（atlas/rules/agon.js、案内役キンダイスン g-gold）：13ステップ（2Dチュートリアルの局面を流用）、正解で自動で次へ（タイマー表示）。`window.__agRules`。

## 本編のマルチスレッド（2026-11-08、`shared/mtsplit.js`）
- エンジンが JavaScript だけなので、**ふつうの Worker の組**（同じ `engine.js` を複数）で読む。**ページが分離されているときは置換表を1つ共有する**（2026-11-09、`shared/mtsplit.js` の共有モード＋`shared/mttt.js`：SharedArrayBuffer、ロックなしの XOR 照合、端末のメモリで 16〜64MB、探索ごとの年齢、止める合図も共有メモリ）。分離は `agon/sw.js`（mtengine.js と同じ軽い方式：Chrome / Edge の PC は Document-Isolation-Policy で自動・初回だけ再読み込み、ログイン・オンライン対戦はそのまま。Safari・Firefox はオプションをオンにしたときだけ COOP モード＝ログイン・オンライン対戦は止まる。スマホはオンにするまで Service Worker を入れない）。分離できないとき（Safari・Firefox で自動のまま等）は今まで通り各 Worker が自分の置換表を持つ（非共有）。オプション（歯車）の「マルチスレッド」は mtengine.js のゲームと同じ選択（全ブラウザで `aicoding-mt`。PC は自動でオン、スマホ・タブレットはオンにするまで1スレッド）。1スレッドの Worker（局面数・深さで決めるレベル）は今まで通りの置換表で、指し手・局面数は前と同じ（確認済み）。
- 方式：**ルートの手と本筋の分担（Young Brothers Wait）**。各深さで最初の手（前の深さの最善手）を先に読み、その間ほかのスレッドは残りの手を前の深さの評価値と比べる null window で試す。最初の手が終わったら残りを本当の α で並列に試し、上回った手だけ (α, ∞) で読み直す。本筋は残り深さ5以上の節点で同じように分ける（後半の手は1手浅い試し読みから：エンジンの LMR と同じ）。解析（分析・ヒント・コーチ・検討ボックス）は全部の手を深さごとに全幅で分け合う。エンジン側は `mtPlan`（読むもの・その場の答え）・`mtV`（ルートからの手順 `line` の局面を窓 (wa, wb) で）・`mtKids`（その局面の手の順）・`mtPv`・`mtFin`（1スレッドと同じ形の返事）。
- 使う所：分析・ヒント・コーチ（深読み＝四段）・検討ボックス（`rvbox.js` に `pool()`／`cancel()`）・時間で考える四段・五段（レート戦も）。15級〜三段は局面数・深さで決めるので1スレッドのまま（置換表を共有しないため、同じ局面数では1スレッドより浅くなる：局面数の上乗せが2スレッドで約1.1〜1.5倍）。PRO の「スレッド数」はどの制限でも（局面数は全スレッドの合計）。AI の手は分析などからスレッドを譲ってもらう（`pool('ai')`）。情報行の末尾に全スレッド合計の「· NNNk nps」。
- 計測（作業機は共用2コアのため、実際の速さはユーザーの Mac で `agon/bench.html`）：作業機では各スレッドを別の置換表を持つエンジンにして、仕事の量（局面数）で時間を数えるシミュレーションで見積もった。最善手の探索（深さ7、4局面）：2スレッド 約1.4倍、4スレッド 約1.9倍、8スレッド 約2.5倍、14スレッド 約3.4倍。解析は手の数（約25手）まで分けられるので、ほぼスレッド数どおり速くなる。
- 共有の置換表の効果（2026-11-09、深さ8、8局面、ふつうの1スレッドの読みの局面数を基準）：Young Brothers Wait のままでは 8スレッド 約2.8〜3.1倍（非共有 約2.4倍、`shared/tools/mtsim.js`）にとどまり、**Lazy SMP**（`shared/tools/mtlazy.js`：実スレッド、主スレッドの局面数を時間とみなす）が 8スレッド 約4.0倍、4スレッド 約2.5倍、2スレッド 約1.9倍と速いので、共有モードの最善手（時間で考えるレベル・PRO・コーチの深読み）は Lazy SMP：主の Worker が1スレッドと同じ探索（`mtlead`）、残りは同じ局面を読み続ける（`mthelp`：1つおきに1手深く、ルートの手の順を回す）。主が終われば止める合図で全員止まる。解析（全部の手の値）は深さごとに全部の手を分け合う方式のまま（置換表も共有）。分離できないときは今まで通りの Young Brothers Wait（非共有）。
- **最上位レベル Lv.21〜23（2026-11-09）**：時間で考える 5秒・10秒・20秒（Lv.20 の 2.5秒から1段階2倍、全スレッド、レート戦も。レート戦では持ち時間（5分＋3秒）を超えないよう、残り時間の約1/20＋加算の8割までに縮める）。1スレッド・オプションオフでも同じ時間で読む。開いた直後でスレッドの準備がまだのときは最大4秒待つ。1段階の幅は局面数の2倍対1倍の対局（`shared/tools/nodematch.js`、序盤4〜8手をLv.9で散らし先後入れ替え）で：5万対10万局面 +26 Elo（80局・引き分け48、95%区間 −22〜+75）。引き分けが多い（6割）ため差が出にくく、20万局面以上の対局は作業機では時間が足りず未測定。ウゴルキでは局面数が多いほど1段階の幅が大きかった（5万→10万 +22、20万→40万 +120）ことも考え、RT_LV は1段階 +30（2380・2410・2440、推定）。目安の +100 には届かない見込み（ユーザーの Mac の対局で見直す）。大百科の3D卓も 23 まで。
