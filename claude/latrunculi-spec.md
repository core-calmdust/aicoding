## ルール（確実性優先：古代のルールは失われており、すべて現代の復元）
出典（2026-11 確認）：Locus Ludi（フリブール大学）のルールシート「Ludus latrunculorum — Seneca variant / Piso variant」（U. Schädler 1994・2001 に基づく）、Wikipedia「Ludus latrunculorum」（ウァロ・オウィディウス・マルティアリス・『ピソ頌』・イシドルス・マクロビウス、ローマ時代ブリテンの 7×8・8×8・9×10 の盤、ヴィンドランダ、Museum Quintana のルール）。

盤は 8×8。黒（P1）が先手。ゲームタブで3つの復元を選ぶ（`engine.js` の RULES）。

| キー | 名前 | 内容 |
|---|---|---|
| `seneca`（既定） | シェードラー式 | 空の盤に20個ずつ交互に置く（置く間は取れない）→ 縦横1歩、または**味方の駒**を跳び越える（連続可・向きを変えてよい）。相手の駒を2個で両側から挟むと**裏返って動けなくなる**（incitus）。挟んだ側の**次の番のはじめに必ず1個取り除き**、それから1手動かす（複数挟んでいても1手に1個、どれを取るかは選ぶ）。挟んでいる2個のどちらかが挟まれると、挟まれていた駒は自由になる。裏返った駒は挟む役にならない。 |
| `piso` | ピソ式 | 置き方・1歩移動は同じ。跳び越えなし。挟んだ駒はその場で取る（複数同時も全部）。 |
| `quintana` | クインタナ式 | 16個ずつ手前2列に並べて開始。縦横に好きなだけ進む。挟んだらその場で取る。隅の特則なし。動けなくなった側の負け。 |

共通：
- 隅の駒は、隅のとなりの2マスを押さえると挟まれる（seneca・piso）。辺の駒は辺に沿って両側から。
- 自分から相手2個の間に入っても挟まれない（挟めるのは動かした駒で両側がそろったときだけ）。
- 同じ駒を続けて行ったり来たりさせない（直前の自分の手を逆に戻す手は不可）。
- 終了：どちらかが1個以下 → 多い方の勝ち。動かせる手がない → seneca・piso は取った数の多い方（同数は引き分け）、quintana は動けない側の負け。
- **quintana の同数ルール（2026-11-19 ユーザー：決着がつかないので → 後手勝ちは白に寄りすぎ → 調査）**：取り合いなしの手数制限（30手ずつ）で終わったとき取った数が同じなら、**相手の陣地（盤の向こう半分：黒は上の4段、白は下の4段）に入っている駒が多い方の勝ち**、それも同じなら**後手（白）の勝ち**（`RULES.quintana.tie = 'adv'`、`advDiff(pos)`、終わり方 `why: 'tie'`／`'tie2'`、文言 `res.why.tie`／`tie2`・大百科 `wTie`／`wTie2`）。評価は取った数が同じ間、手数が進むほど陣地の差（±3で頭打ち、同数なら白へ少し）× `TIE_W`（60）× quiet/QUIET_MAX。
  - 調査（AI同士 nk:20／80、ランダムな最初の2手、黒・白・引き分け）：同数は引き分け（旧）＝0-0-12（全局0対0）。同数は白の勝ち＝0-12-0（制限を50・70手ずつに延ばしても 0-12・1-11）。中央4×4の駒の多い方＝4-2-6。**相手陣の駒の多い方＝19-10-7（36局）**、1手で先に届く空きマスの多い方＝19-11-6（36局。人には数えにくい）。陣地の差が同じときの白勝ちを足すと相手陣式で黒19・白17。相手陣式は取り合いも増える（平均1.3個）。本番エンジン（評価に陣地の差を入れたもの）で計72局：黒42・白30（黒58%、先手の利の範囲）。黒に「2個以上多い」を求める版（`LT_KOMI=1`、tools 用）は黒7・白17 で白に寄りすぎたので不採用。
- **本作の取り決め**（対局を終わらせるため。出典はベルの「30手取りなし」規定を参考）：取り合いなしで30手ずつ（60手）続いたら終了し、取った数の多い方の勝ち・同数は引き分け（`QUIET_MAX`）。
- 出典で決まっていない点の扱い：跳び越えは Locus Ludi の本文どおり味方のみ（図Cの相手越えは採らない）。取り除き後に動かせる駒がなければ、取り除きだけで手番終了。先手は黒。

## エンジン（core.c → WebAssembly ＋ engine.js、Web Worker）
- **C／WebAssembly 化（2026-11-20、`latrunculi/MODEL_CARD.md`）**：ルール・探索・評価を `core.c` に移した（`tools/build-core.sh` → `core-wasm.js`＝SIMD 版 `LT_WASM` と SIMD なし版 `LT_WASM0`、`core_mt.wasm`＝`-DMT`）。engine.js は Worker と Node で `core-wasm.js` を同期で読み、`search`・`orderMoves`・`bestMove`（`ab_best`）・`rootValues`（`ab_values`）・`evaluate` をコアに任せる。ページ本体・読み込みの失敗・`LT_NOWASM=1` は今までの JS（予備）。**JS と WebAssembly は同じ手・同じ値・同じ局面数**：`tools/check_rules.js`（ランダムな局面で合法手の順番・指したあとの盤／裏返り／手持ち／取った数／往復禁止／手数／ハッシュ・hasMove・judge・評価・ネットの値と差分更新）と `tools/check_wasm.js`（局面数・深さで決まるレベルの探索）。局面のやりとりは `SQ`／`INC`／`IO[8..18]`、Zobrist キー・重み・LMR の表（`Math.log` から作った `LMRT`）は engine.js がコアに書く（`waRule`、setRule／setW／setOpt のたび）。評価はビットボード（同じ値で約6倍速い）。速さ：作業機で JS 約6万 → WebAssembly 約95万局面／秒。
- **マルチスレッド（2026-11-20）**：分離されたページでは `core_mt.wasm` を `shared/mtengine.js` のスレッドで（主＝`engine.js?v=…&mt=1`、補助＝`mt-helper.js`、Praline の Young Brothers Wait。`app.js` の `MCP`、コナネと同じ設定）。分離できないページは今までの `shared/mtsplit.js`（各 Worker の探索は WebAssembly、共有の置換表は JS の SH を import で使う）。計測ページ `latrunculi/bench.html`（bench-all.html にも追加）。Praline のマーク（praline-badge.js の一覧）にも追加。
- **学習した評価（NNUE）の仕組み（2026-11-20、まだネットは採用していない）**：`engine.js` の `NETS = { seneca, piso, quintana }` が空の間は手作り評価のまま。`latrunculi/nets/` にファイルを置いて名前を書くと、Worker が取得してそのルールの評価が「手作り評価＋ネットの補正」になる（`core.c`「the net」：入力366×2視点 → H → 1、SCReLU、差分更新。JS の予備は同じ整数を作り直しで計算）。学習はユーザーの Mac で `bash latrunculi/tools/nnue/run.sh`（自己対局 → 学習 → 確認 → 採用ファイル。手順・時間・採用基準は `tools/nnue/README.md` と MODEL_CARD）。Node のツールは `LT_NET_<rule>=ファイル` でネットを読む、`LT_NONET=1` で切る。
- 探索の追加（reverse futility・LMP・IIR・置く段階の強い LMR：`core.c` の `SX`、ltn の `smatch`）は対局で勝ち越さず不採用（MODEL_CARD）。
- 手 m = from + 64×to + 4096×(rm+1)。置く手は from = to。rm＝この番のはじめに取り除く裏返った駒（なければ −1）。取り除きだけの手は from = to = rm。
- `Pos`：sq（持ち主）・inc（裏返りの向き：1 横・2 縦・3 隅）・hand（置く残り）・cap（取った数）・last（直前の手：往復禁止）・quiet。`E.effect(pos, m)` が1手の中身（path・leap・blocks・takes・frees・rm）を返す：画面・コーチ・レッスン生成はすべてこれを使う。
- 棋譜：置く `d4`、移動 `d4-d5`、跳び `d4^d6`、取る `xe5`、挟む（裏返す）`!e5`、取り除いてから動く `xe5,d4-d5`。
- 評価（2026-11-19 強化）：特徴の重み付き和（`FN`：駒・裏返った駒・狙われた駒・動ける向き・並び・中央・隅・手持ち・両方向から狙われた駒・辺・挟んでいる駒・手番・**取り合いなしの手数が進んだときの駒得**（quietMat）・手番側が取り除ける相手の駒）。重みはルールごとに `tools/tune.js`（自己対局の勝敗へのロジスティック回帰＝Texel 法、seneca・piso は2巡）で求めた `TUNED[rule]`。
- 探索（2026-11-19 強化）：negamax（PVS）＋置換表＋キラー＋**ヒストリー**＋**LMR（log×log）**＋**null move**（移動の段階・取り除き中でないとき）＋**アスピレーション**＋静止探索（挟む手のみ、取り除きが残っていても stand pat）。駒数は差分で持ち、終局判定は合法手の有無だけを早めに調べる（`hasMove`）、評価の「相手が1手で届くか」は局面ごとに前計算（`reachMap`）。同じ深さの探索が約1.7倍速く、seneca の中盤では同じ深さまでの局面数が約1/50。
- **並列探索（2026-11-19）**：`shared/mtsplit.js`（コナネと同じ。ルートの手を Young Brothers Wait で分担、分離されたページでは `shared/mttt.js` の共有置換表、`sw.js`）。エンジンは `mtplan`／`mtv`／`mtkids`／`mtpv`／`mtfin`／`mtshare` に答える。使う所：分析・ヒント・コーチ・時間で考える Lv.19・20（レート戦も）。Lv.1〜18 は1スレッドのまま。作業機（2コア）で2スレッド動作を確認。
- **置く段階の定跡（2026-11-19）**：`book.js`（`self.LT_BOOK`、ワーカーが importScripts）。seneca・piso の最初の1手、その応手（対称8通りでまとめて10局面）、定跡の1手目と任意の応手のあとの3手目（`tools/book.js`、1局面1千万局面の探索）。探索で決める段（Lv.10〜）だけが使う。
- **評価の学習の続き（2026-11-19）**：重みを置く段階と動かす段階で別々に（30個）、特徴「1手で届く空きマスの差」（ctl）を追加。`tools/tune.js` は静かな局面（挟める手がなく、取り除きもない）だけで学習。piso は +117 Elo で採用、seneca（−158）・quintana（−35）は効果がなく、前の重みのまま。quintana は人が指しても引き分けが多いゲームで、評価では差がつきにくい。
- **レート戦の基準値 RT_LV（2026-11-19 実測）**：`tools/ladder.js`（既定ルール、となりのレベル同士 24〜36局、定跡あり）で段差を測り、Lv.1＝100 から積み上げ。上の段は取り合いなしの引き分けが多く差が出にくい（+25 未満は +25 とみなす）。Lv.19・20 は局面数2倍あたり約 +50 Elo（Lv.13〜18 の実測）からの推定。大百科の `atlas/games/latrunculi.js` の RATING も同じ値。**2026-11-20**：WebAssembly のコアで Lv.1〜18 は前と同じ手（局面数・深さで決まるため）。時間で考える Lv.19・20 は同じ時間で約16倍の局面を読む（同じ時間の旧 JS 比 seneca 1手0.1秒で +209 Elo）ので、各 +148 して 2950・3000（長い持ち時間では引き分けが増えて差が縮むので控えめに）。**2026-11-20 の点検**：quintana も同じ扱いでよい（同じ時間の旧 JS 比、1手0.1秒・120局で +90 −30 =0＝75.0%、約 +191 Elo。seneca +209・piso +232 と同じくらい）。Lv.18→19→20 の段差（`tools/ladder.js`、Lv.19・20 は局面数 105万・210万）は3ルールとも逆転なし：Lv.19 対 Lv.18 は quintana 75.0%（+191）・seneca 54.2%（+29）・piso 58.3%（+58）（各12局）、Lv.20 対 Lv.19 は seneca 66.7%（+120、12局）・quintana 53.1%（+22、96局）・piso 56.3%（+44、24局）。RT_LV と大百科の RATING は変えない（詳細は MODEL_CARD「レベル表」）。
- 不具合の修正（2026-11-19）：跳び先の探索の通し番号（Int32）が約21億回で桁あふれし無限ループになっていた（同じワーカーで30分以上考え続けると起こりうる）。上限で巻き戻す。
- クインタナ式の説明（2D のルール欄・大百科の種目カード、14言語）には「古代の記録をもとに遊べる形に再構成したルールで、決着がつかないことが多い」を添え、続けて本作の同数ルール（下）を書く（2026-11-19 ユーザー）。
- 強さの計測（`tools/match.js`、1手60ms・40局）：旧エンジン比 seneca 75%（約+190 Elo）・piso 82.5%（約+270 Elo）。quintana はほぼ引き分け（36/40）で差が出ない（2026-11-19 の同数ルールより前。今は決着がつく：上の 2026-11-20 の 120局は引き分け 0）。`tools/bench.js`・`bench2.js` は速度の計測。
- 20段階（Lv.表記）：Lv.1〜9 は深さ1〜3＋ノイズ、Lv.10 は1,200局面、Lv.11〜18 は局面数（3千〜20万）、Lv.19・20 は 1.5 秒・3 秒。負け確定は `resist`（いちばん遅く負ける手）。2026-11-19：AIが強くなって段差が不揃い（Lv.4 が Lv.3 より弱い、1段 +400 超）になったので Lv.1〜10 のノイズ・深さを組み直した（すべて上の段が勝ち越す）。
- ソルバー：`goalGood / goalMin / goalReply`（N 手以内に「取った数の差を+1（裏返った自分の駒が残らない）」または「勝ち」、相手は最長抵抗＋評価の良い受け）。
- 既知の課題：強いレベル同士は取り合いが少なく「30手」で終わりやすい（特に quintana）。

## 検討ボックスのスレッド（2026-11-20、点検 #2929/#2938）
- 検討ボックス（`rvbox.js` の `pool()`）は、分離されたページでも `shared/mtsplit.js`（別の探索）で読んでいて、分析（`core_mt.wasm`、Praline の YBW）と深さ・値がずれていた。分析と同じ組に：分離されたページは `core_mt.wasm`（コーチの深読みなどでふさがっていれば1ワーカー、`mtsplit.js` には回さない）、分離されないページは今まで通り `mtsplit.js`。共通の決まりは addendum「検討ボックスのスレッド」。
- 確認：headless Chrome（Playwright、1440×900、2D と `?skin=atlas`）で、分離あり（DIP）・COOP モード・分離なしの各モードで対局の振り返りから検討ボックスを開き、読みが進んで候補手と値が出ること、分離ありでは `core_mt.wasm` の組で読むこと、分析と同じ局面で手と値が大きくずれないこと（αβ の値は深さの偶数・奇数で揺れる）、コンソールエラーなし（localhost の Firebase／reCAPTCHA を除く）。
- 版：`app.js?v=19`（`latrunculi/index.html`）。
- **分析・ヒント・コーチ・AI の手も（2026-11-20）**：`request()` も、分離されたページで `core_mt.wasm` の組がふさがっているとき（AI の手・コーチの深読み・検討ボックスが使用中）は `mtsplit.js` に回さず1ワーカーで読む（addendum「本編のマルチスレッド」の「使用中なら通常の1スレッドのワーカー」、チェス・チェッカー等と同じ）。分離されないページは今まで通り。確認：Playwright（headless Chrome）で分離あり（DIP）・COOP・分離なし × `?skin=atlas`（分離ありは 2D も）で、分析・ヒント・AI の手（時間で考えるレベル）・コーチの深読みと分析の同時、振り返りの検討ボックス＋コーチの深読み＋分析の同時で、値が出てエラーなし。分離ありでは `mtsplit.js` の組が一度も使われない（変更前はふさがっているとき使われていた）。版：`app.js?v=20`。
