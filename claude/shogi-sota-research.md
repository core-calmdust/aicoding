# 将棋：公開されている最先端ソフトの調査と、こちらへの活かし方（2026-11-19）

きっかけ：探索 v5 は自己対局で +290 だったが、技巧2（Floodgate 約3300）相手には +50 程度（11勝34敗3分、約 −181）。
**外の相手に強くなるには何が足りないのか**を、公開情報（2026年の大会のアピール文書、やねうら王・tanuki-・氷彗の開発記録）から調べた。
前の調査は `claude/shogi-eval-research.md`（評価関数）と `claude/shogi-search-comparison.md`（探索）。ここは「その後に分かったこと」と「次の一手」。

方針は変えない：他人の評価関数や GPL のコードはサイトに載せない。強いソフト・公開データは**教師・物差し**として使う。

## 0. 結論（先に）

> **訂正（2026-11-20）**：下の 1.「差の大部分は学習データの量と教師の質」は、技巧2の水準に対しては当たらない。評価関数は同じまま探索をやねうら王のものに替えると、技巧2に 22勝1敗1分（こちらの探索では 11勝34敗3分）。**まず探索**（差は局面数で約8倍、`claude/shogi-search-comparison.md` §0.14）。データと教師は、その先（水匠5 の水準）へ行くために要る。

1. **差の大部分は「学習データの量と教師の質」。** 強いチームは 80億〜240億局面を、DL 系（dlshogi 型）の評価値で付け直して学習している。こちらは約4億局面・付け直しなし（1.5億の付け直しは試して効果なし）。量が 20〜60倍違う。
2. **入力が「駒だけ」でも、水匠5より強い評価関数は作れる（実例あり）。** つようら王11micro（4.5MB、MIT）は、こちらと同じ系統の入力で水匠5 +150〜200。違いは「第1層 2048・小さな中間層 8→64・進行度で8つに切り替え」と、学習の量・教師。こちらの入力を作り直す必要はない。
3. **第1層をむやみに広げても強くならない。** tanuki- の 65,536局の比較で、1024 より広い 1536・2048・2304 はどの持ち時間でも同等か負け。奏乗も「512x2 より広げてもほぼ伸びない」。こちらの 1024 が負けたのと同じ向き。**広さではなく、データと教師と小さな後段。**
4. **学習の誤差（検証ロス）は強さの物差しにならない。** 氷彗の開発者も「ロスが最良の候補が対局では弱いことが多い」と書いている。こちらが見てきた現象と同じ。採否は対局、それも外の相手で。
5. **探索は、上位でも「やねうら王＋数値の自動調整（SPSA）」。** 氷彗は評価関数を変えるたびに SPSA をやり直し、時間配分の調整だけで +11〜27。Stockfish の新しい探索の取り込みは将棋ではほとんど伸びなかった、という評価。こちらの探索 v5 の方向は合っているが、外の相手への効きは評価関数が決める。

→ 次の一手は §4。まず「どこに何 Elo あるか」を外の相手で切り分ける（評価関数を入れ替える計測）。そのうえで、**データを20倍に増やして、後段つきのネットを GPU で学習**する。

| **こちら（v7）** | 駒だけ、512、**後段なし（線形の出力）**、切り替えなし | **約4億局面**、深さ9の評価値そのまま | 自作（v5） |

- 奏乗の数字（相手は水匠10、型は halfkp 512x2-8-64 で同じ）：**80億局面で −50、160億局面で −21**。量を倍にして +29。重複を除くと +19。
- 奏乗の数字（型の比較、教師は別のモデル）：512x2 = −174、1024x2 = −168、1536x2 = −168。**広げても変わらない。教師が違うだけで 120 以上違う。**
- tanuki- の比較（2026-11-15、1024-8-32 を基準、各4,096局）：1536 は −7 〜 +9（差なし）、2048 は −52 〜 −20、2304-16-64 は −56 〜 −41。持ち時間を長くすると差は縮むが逆転しない。
- 氷彗の記録：入力の工夫（駒ごとの利きの数 PE9）で +6、層の束の分け方で +20〜30、学習データの段階をやめて1つの山にして +13、時間配分の SPSA で +11〜27。**上位では1つ +5〜30 の積み重ね**。大きいのは教師（蒸留）とデータ量。
- 学習の道具：nnue-pytorch → **bullet-shogi / BulletOu（Rust、MIT、NVIDIA の GPU が必要）** へ移行が進む。約3倍速い。ノート PC 一晩（約12時間、1億局面×500回）で 768-16-64 が学習できた、という報告もある。
- 2026年9月の tanuki-：複数の教師の評価値の**平均**で追加学習（採用）、学習率を 1/10 にした追加学習（採用）、**全部の玉の位置に共通の「駒だけの重み」を足す**（採用）。最後のものは、こちらの HalfKP 実験でやった「共通の重み」と同じ考え。

## 2. こちらとの違い（大きい順の見立て）

| 項目 | 上位 | こちら | 見立て |
|---|---|---|---|
| 学習局面数 | 80億〜240億 | 約4億 | **最大の差**。量を倍で +30 前後（上位の水準で）。こちらの水準ではもっと大きいはず |
| 教師 | DL 系（DL 水匠・dlshogi・Ryfamate）で付け直し | 深さ9の探索の評価値 | 大きい。ただし 1.5億・GCT（古い小さなモデル）では効果なしだった。**教師の強さと量の両方が要る** |
| 後段 | 8〜16 → 32〜64、進行度や玉の位置で8〜9組 | なし（試して効果なし：4億局面） | データが増えてから効く形の可能性。micro がこの形 |
| 第1層の幅 | 1024〜2048（駒だけの入力なら 2048〜4096） | 512 | 駒だけの入力は1つ1つが軽いので広げやすい。ただし広げるだけでは伸びない |
| 探索 | やねうら王＋SPSA | 自作 v5＋SPSA | 自己対局では差が大きく出るが、外の相手には評価関数が先 |
| 評価値の尺度 | FV_SCALE を対局で合わせる（水匠は 16 → もっと大きい値が最良） | 0.805 固定 | 小さい。ネットを変えるたびに合わせ直す |

「技巧2に −181」の意味：技巧2は 2016〜17年の、3駒関係（手で設計＋学習）の評価関数。水匠5（2021）はそこから Floodgate で 1,000 近く上。**こちらの評価関数は、まだ 2016年の水準に届いていない**、と読むのが正直なところ。入力の系統は micro と同じなので、伸びしろは学習の側にある。

## 4. 進め方（提案）

**(1) 切り分けの計測（半日、サイトは変えない）**：外の相手（技巧2）に対して、
- a. やねうら王の探索＋こちらの評価関数（`tools/match/yo-ours.sh` の組み合わせ）対 技巧2
- b. やねうら王＋つようら王11micro 対 技巧2（同じ局面数）
- a が今（−181）と変わらなければ「壁は評価関数」で確定。b − a が評価関数の伸びしろ（Elo）。

**(2) データを 20倍に**：MIT のデータを 4億 → 40〜80億局面へ。重複を除く。ディスクは 300GB 級が要る（Mac の空きを確認）。

**(3) 学習器を GPU に**：今の C の学習器は 4億局面で 5〜7時間。80億は無理なので、Mac の GPU（Metal）で動く学習器を自分で書く（PyTorch の MPS か MLX）。目安は 50万〜100万局面/秒。

**(4) ネットの形を micro と同じ系統に**：駒だけの入力のまま、第1層 1024〜2048、8 → 32〜64、進行度で8組。エンジン側は前に作った中間層の計算（疎な計算）が使える。進行度の式は自分で学習する（玉の位置×駒の線形の式）。

**(5) 教師の付け直し**：(2)〜(4) のあと。micro を教師にする（MIT で条件が明確）か、dlshogi の公開モデルか。速さは Mac の GPU で約5千局面/秒なので、数億局面が上限。全部ではなく「評価が割れる局面」に絞る。

**(6) 探索の再調整**：評価関数が変わるたびに SPSA。採否は技巧2との対局（48局以上）でも見る。

やらないこと：第1層だけをさらに広げる、検証ロスで採否を決める、自己対局だけで採否を決める。
