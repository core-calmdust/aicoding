# 3Dレッスン（日本語）の品質ループ

2026-11-21 開始。対象：3Dレッスンのある全ゲーム（atlas/lessons3d.js の DATA：dots, morris, mancala, tafl, shogi, chess, reversi, gomoku, go, checkers, xiangqi, backgammon, hex, amazons, connect4）。

## 目標
- キャラクターの口調で自然な会話にする。文末に「〜だよ」「〜よ」が続かない。キャラらしい言い方（口ぐせ：ケロ・コン・ワン・ピョン・ペン・カニ など）を、くどくならない程度に。
- 問題の起承転結：問題を出す → ヒント → 正解ならほめて理由を言う → 不正解なら、正しい手（印・矢印・手の名前）と「なぜだめか（見落とし・デメリット）」を具体的に言う。
- 1つのレッスンの中でも、問いかけ・ほめ言葉・指摘の言い回しにバリエーションを持たせる。キャラの一貫性は保つ。
- 座標は3D盤にないので書かない（チェス・将棋の手の名前は可）。
- 文章量はスマホとPCの両方でバランスよく：吹き出しは1ページ（スマホ44字・PC58字が目安）に収め、1つの吹き出しはスマホで4ページ・PCで3ページまで。正解・不正解の解説は150字以内。長い1文は読点で区切れるように書く（区切れない長文は吹き出しが大きくなって盤を隠す）。
- 実機確認：スマホ（390×844）とPC（1440×900）の両方で吹き出しを開き、文字がはみ出さず盤を隠しすぎないことを見る。

- **理由はAIの評価ではなく、盤の上の事実で言う**（2026-11-22 ユーザー指示：「AIの評価が下がるから取りたくない」などは最悪）。不正解なら「その手のあと相手に何をされるか（詰まされる・動かした駒をただで取られる・ねらわれていた駒を取られる・王手で攻めこまれる・成りこまれる）」や「正解の手が何をする手か」を具体的に。「AIの評価・見立て・形勢・評価値・勝つ見込み○%」を理由にしない（評価ツールで大きく減点）。将棋のレッスンは shogi/tools/lesson-replies.js で全合法手への相手の応手を前もって調べ（shogi/lesson-replies.json）、atlas/lessons3d.js の shReplyCore が文にする。定跡は盤面から（shStaticWhyJa・shContrastJa）。
- **定跡の手順は、全部の手にひとことガイドを付ける**（2026-11-22 ユーザー指示：指すごとに何も言わない手があるのはやめて）。将棋は shStepNotesJa が盤面から作る（「☗先手：まずは歩を突いて角道を開ける手…」）。ほかのゲームの定跡も同じようにする。

- **盤の事実が正しいことも評価する**（2026-11-22 ユーザー指示：アマゾンの「緑の印はそれぞれの方向でいちばん遠いマス」が実際は1マス手前だった。文章と合わせて問題のチェックもきちんと評価する）。`node tools/lesson-facts.js [game]` が各ゲームのエンジンで、答え・許される手が合法か、印が文章の言うとおりか（届く／いちばん遠い など）を確かめる。lesson-quality.js はこの結果を読み、事実がまちがっているレッスンは −60 点（不合格）。**いまはアマゾンだけ**。ほかのゲームは、品質ループでそのゲームを直すときに、まず lesson-facts.js にそのゲームのチェックを足してから文章を直す（答えの合法性・正解手の一致・印や数（何マス・何枚・何%）が文章と盤で一致するか）。

## 評価ツール
- `node tools/lesson-quality.js [game,…] --json out.json --show N`
- 各レッスン100点から減点（吹き出しの長さ・ページ数（スマホ／PC）、プレースホルダー残り、丁寧語、生の値、文末の連続、〜よ の比率、口ぐせなし、ヒントなし、不正解の解説なし／正解手を言わない／理由がない、正誤で同じ文、問いかけが全部同じ）。
- 2026-11-21 02:45 基準を厳しくした（ユーザー指摘：96点のアマゾンズでも「〜よ。〜よ。」と読めた）：吹き出しはページ送りで続けて読まれるので、文末はレッスン全体を表示順（導入 → 準備 → 各問題）に通して数え、吹き出しをまたいだ連続も減点。〜よ の比率は35%超で減点（超えた分に比例）、〜んだ も30%超で減点。準備（ramp）の文も採点に入れる（3D用の座標なし版 atlas/nocoord を適用）。口ぐせのあるキャラは吹き出しの20%以上で口ぐせ、全キャラとも45%以上の吹き出しに会話らしさ（！？〜・ね・かな）が必要。3D盤で座標が出たら減点。
- 2026-11-21 03:10（ユーザー指示）：**定跡・定石の問題もレッスンと同じく採点**する。ツールは各ゲームの定跡を `<game>/open` として別に出す（導入・手順のメモ・問題。問いかけがない問題は案内役の opGoal で採点）。ループの対象選びでは `<game>/open` も1つの対象として扱う。あわせて、将棋の詰将棋レッスンがツールで落ちていた不具合（lesson() に X を渡していなかった）を直し、15級段すべてを採点するようにした。
- **2026-11-21 23:10 採点基準の大幅な見直し（ユーザー指摘）**：五目並べが100点なのに「ぼく、うれしくて踊っちゃう！」が5回出る・淡々として感情がない・プレイヤーを応援していない、ドット・アンド・ボックスの最初のレッスンで「安全な線があるうちは…」の繰り返しがオンパレード・ゲームの説明がない、と指摘。「採点が甘すぎる」「同じセリフを繰り返すのはやめて」。追加した減点：①**同じ文が1レッスンに2回**（最大15）、②**言い回しを少し変えただけの繰り返し**（句読点を除いた10文字が3つ以上の吹き出しに出る、最大12）、③**正解のほめ言葉がプレイヤーを応援していない**（その調子・いいね・さすが・お見事など。8割未満で減点）、④ほめ言葉に**次へ背中を押す言葉**（次も・どんどん・その調子で行こう）が一度もない、⑤ほめ言葉が案内役自身のこと（ぼく踊っちゃう）、⑥**不正解の励まし**（おしい・大丈夫・次は・あと少し。半分未満で減点）、⑦！？のない淡々とした吹き出しが45%超、⑧**最初のレッスンでゲームの説明（どんなゲームか・勝ち方）がない**（15点）。例：✕「5つ並んだ！ ぼく、踊っちゃう」→ ○「5つ並んだね！ そうそう、その調子！ どんどん行こう！」。全体 95.4 → 44.7（合格 0 本近く）。pass 90 は据え置き（下げない）。
- **2026-11-22 03:30 問題そのものの見直し（ユーザー指摘：チェッカーは100点なのに似たような問題が続く。セリフはだいぶ良くなった）**：これまでの採点は文だけを見ていて、問題の中身が似ていても満点になっていた。チェッカーでは「安全に進める」4問目＝「1回ジャンプ」2問目＝「連続ジャンプ」1問目のように、1〜2手しか違わない局面が別のレッスンにくり返し出る。また1つのレッスンの5問がどれも同じ1つのポイント（「2枚取れる」「取り返されない」）を言いかえているだけで、ほめ言葉・励ましの出だしも全レッスンで同じ順番（1問目は必ず「いいね！」、2問目は「さすが！」…）になっていた。追加した減点（ゲーム単位）：⑨**同じゲームのほかの問題と同じか1〜2手違いの局面**（表示順で2つ目以降、1問6点・最大18）、⑩**ほめ言葉・不正解の解説の出だし（先頭4文字）の並びがほかのレッスンと同じ**（各6点）、⑪**5問のほめ言葉が全部同じポイント**（同じ6文字が全問のほめ言葉に出る、8点）。全体 49.4 → 38.7（checkers 100 → 84.3、hex 98.8 → 80.8）。直し方：局面は別のレッスンと重ならない新しいものを用意し（エンジンで正解が1つに決まるか確かめる）、5問は易→難の順にして、テーマの中でも違う形を出す（例：連続ジャンプなら2枚→3枚→道が分かれる→取ったあと取り返される罠→キングの連続ジャンプ）。ほめ言葉・励ましは問題番号で固定せず、その局面の内容に合わせて選ぶ。セリフの口調はいまの調子を保つ。**次の回はチェッカーから**（ユーザー指摘のゲーム）、そのあとヘックス・チェスなど点の高いゲームも同じ見直しをする。
  - ほかに直したもの：EASY2（2問）のレッスンで 40/40点なのに「合格は30点。もう一度挑戦しよう！」と出ていた不具合（一部の save が100点満点前提の 75 で判定）→ 100点換算で判定。結果の文も応援する言い回しに。最初のレッスンの頭に、ゲームの説明と勝ち方を案内役の口調で入れる `GAME_JA`（atlas/lessons3d.js：dots・morris・mancala・tafl・shogi・reversi・backgammon・amazons・connect4）。
- 合格点は `tools/lesson-quality.json` の `pass`。全体の平均が pass+10 を超えたら pass を5上げる（上限95）。
- 基準を満たさない書き換えは採用しない（作り直す）。

## 進行チェック（必須・全問）
- 2026-11-22 ユーザー指示：**進行チェックは必ず全問行う**（チェスの「チェック（王手）」2問目が進行不能だった。キング＋ビショップ対キングを「駒不足で引き分け」と判定して駒が動かせなかった）。
- `node tools/lesson-progress.js <game>[,game…] [--kind list|open] [--key K] [--jobs N] [--json out.json]`
  - そのゲームの全レッスン・全定跡を3D盤で開き、導入 → 準備（ramp）→ 手順 → 全問題を正解で解き、結果まで進むかを確かめる。正解で満点にならない・25秒進まない・JSエラーは失敗（終了コード1）。
  - 問題の前に「盤が手を受け付けるか」を確かめる（チェスは画面上のマスを実際にタップして指す。ほかのゲームは盤が over / busy でないこと）。
- 品質ループで書き換えたゲームは、マージ前に必ずそのゲームの全問を通す。失敗が1つでもあれば直してから採用する。重い（1レッスン約1分）ので、ほかのゲームは報告の回などで少しずつ回す。
