# 3Dレッスン（日本語）の品質ループ

2026-11-21 開始。対象：3Dレッスンのある全ゲーム（atlas/lessons3d.js の DATA：dots, morris, mancala, tafl, shogi, chess, reversi, gomoku, go, checkers, xiangqi, backgammon, hex, amazons, connect4）。

## 目標
- キャラクターの口調で自然な会話にする。文末に「〜だよ」「〜よ」が続かない。キャラらしい言い方（口ぐせ：ケロ・コン・ワン・ピョン・ペン・カニ など）を、くどくならない程度に。
- 問題の起承転結：問題を出す → ヒント → 正解ならほめて理由を言う → 不正解なら、正しい手（印・矢印・手の名前）と「なぜだめか（見落とし・デメリット）」を具体的に言う。
- 1つのレッスンの中でも、問いかけ・ほめ言葉・指摘の言い回しにバリエーションを持たせる。キャラの一貫性は保つ。
- 座標は3D盤にないので書かない（チェス・将棋の手の名前は可）。
- 文章量はスマホとPCの両方でバランスよく：吹き出しは1ページ（スマホ44字・PC58字が目安）に収め、1つの吹き出しはスマホで4ページ・PCで3ページまで。正解・不正解の解説は150字以内。長い1文は読点で区切れるように書く（区切れない長文は吹き出しが大きくなって盤を隠す）。
- 実機確認：スマホ（390×844）とPC（1440×900）の両方で吹き出しを開き、文字がはみ出さず盤を隠しすぎないことを見る。

## 評価ツール
- `node tools/lesson-quality.js [game,…] --json out.json --show N`
- 各レッスン100点から減点（吹き出しの長さ・ページ数（スマホ／PC）、プレースホルダー残り、丁寧語、生の値、文末の連続、〜よ の比率、口ぐせなし、ヒントなし、不正解の解説なし／正解手を言わない／理由がない、正誤で同じ文、問いかけが全部同じ）。
- 2026-11-21 02:45 基準を厳しくした（ユーザー指摘：96点のアマゾンズでも「〜よ。〜よ。」と読めた）：吹き出しはページ送りで続けて読まれるので、文末はレッスン全体を表示順（導入 → 準備 → 各問題）に通して数え、吹き出しをまたいだ連続も減点。〜よ の比率は35%超で減点（超えた分に比例）、〜んだ も30%超で減点。準備（ramp）の文も採点に入れる（3D用の座標なし版 atlas/nocoord を適用）。口ぐせのあるキャラは吹き出しの20%以上で口ぐせ、全キャラとも45%以上の吹き出しに会話らしさ（！？〜・ね・かな）が必要。3D盤で座標が出たら減点。
- 2026-11-21 03:10（ユーザー指示）：**定跡・定石の問題もレッスンと同じく採点**する。ツールは各ゲームの定跡を `<game>/open` として別に出す（導入・手順のメモ・問題。問いかけがない問題は案内役の opGoal で採点）。ループの対象選びでは `<game>/open` も1つの対象として扱う。あわせて、将棋の詰将棋レッスンがツールで落ちていた不具合（lesson() に X を渡していなかった）を直し、15級段すべてを採点するようにした。
- 合格点は `tools/lesson-quality.json` の `pass`。全体の平均が pass+10 を超えたら pass を5上げる（上限95）。
- 基準を満たさない書き換えは採用しない（作り直す）。

## 直す場所
- キャラのセリフ：`<game>/voice-*-ja.js`（ある場合）、なければ `atlas/lsvoice-ja.js`（元の文 → キャラのセリフ）。
- 不正解の解説を足す：各 DATA の lesson() の `ng` / `good` / `ngTx`、または lessons.json / i18n の ja テキスト（2D版にも影響するので注意。3D専用なら lsvoice / voice 側で）。
- リバーシ：問題の問いかけ・正解／不正解の解説は atlas/lessons3d.js の `RVJ_ASK`・`rvTeachJa`（lessons.json の手ごとの数値 f から理由を作る。緑の枠＝正解、赤い枠＝自分の手／ヒントでは隅を渡す手・壁を作る手）。導入・ヒントは lsvoice-ja.js。
- 将棋：問いかけ・ヒント・不正解の解説は atlas/lessons3d.js の `SHJ`・`shTeachJa`（cand の評価値・詰み（±29996）・trap/bait・取れる駒から理由を作る。{m}=正解の手、{x}=指した手）。導入は shogi/voice-fox-ja.js。
- **簡単すぎる初級の問題は2問でクリア**（2026-11-21 ユーザー指示）：答えが光っている・1手で明らかな最初のステップは、5問ではなく2問だけ出す。対象は atlas/lessons3d.js の `EASY2`（アマゾンズ0〜2・ナインメンズモリス0・タフル0・マンカラ0・リバーシ0・五目並べ0・コネクトフォー0・ヘックス0）。同じような問題を見つけたら追加する。
- リバーシの問題の数字（返せる石の数）：準備と最初の2問だけ表示し（2問だけのレッスンは1問目だけ）、それ以降は数字なしで自力で解かせる（2026-11-21 ユーザー指示。atlas/lessons3d.js `RV_NUMS`。3問目の最初に「ここからは数字なし」と言う。問いかけも数字に触れない文に）。
- リバーシの定石（reversi/open）：3D用の座標なしの日本語（リバガメの口調）は atlas/nocoord/reversi.json の `op:<手順>/aim`・`op:<手順>/info`（ja だけ。ほかの言語は openings.json のまま）。問題の問いかけ・ヒント・正誤の解説は atlas/lessons3d.js の `RVJ_OP`・`rvOpJa`（定跡の手の返す数・開放度・相手の打てる数と、opcourse-evals.json の AI 評価から理由を作る。ヒントは場所を言わない。緑の枠＝定跡の手、赤い枠＝自分の手）。
- 五目並べの珠型（gomoku/open）：日本語の手順メモ・問いかけ・ヒント・正誤の解説は atlas/lessons3d.js の `GOMJ`（文）・`GMA`（盤の判定：五・四・活三・活二・相手の四／三を止めるか）・`GOMOKU.opJa`。ヒントは答えの点ではなく、相手の脅威または自分の並びの石に丸（石がないときは文だけ）。
- チェスの定跡（chess/open）：3D用の日本語（ナイトンの口調、座標なし）の導入・手順のメモは atlas/lessons3d.js の `CHJ_OP.intro`・`CHJ_OP.notes`（ja だけ）。問題の問いかけ・ヒント・正誤の解説は `chOpJa`（盤面から手の性質＝駒を出す・中央のポーン・キャスリング・取り返し・ピン・追い払い・タダで取られる駒を判定する `chFacts`、openings.json の cand の対局数から割合）。不正解の解説は {m}＝定跡の手、{x}＝指した手。
- 将棋の定跡（shogi/open）：導入（ショウギツネの口調、短い説明は atlas/nocoord の op:<id>/short）・問題の問いかけ・ヒント・正誤の解説は atlas/lessons3d.js の `SHJ_OP`・`shOpJa`（盤面から手の性質＝取る・取り返す・角交換・飛車を振る・角道を開ける／止める・飛車先の歩・端歩・歩をぶつける・玉を囲いへ・金銀を寄せる・タダで取られる駒を判定する `shFacts`、openings の cand：freq は対局数の割合、cp は AI の評価）。{m}＝定跡の手、{x}＝指した手。
- 将棋の定跡で実戦の問題が5問ない戦型（囲い12本・鬼殺し・立石流・エルモ囲い急戦・角頭歩・筋違い角・嬉野流）は、**手順そのものから問題を作る**（2026-11-21 ユーザー指示「問題を作る仕組みを整えて」）：`node shogi/tools/openings/lineprobs.js [1手のms=1500] [id…]` → `shogi/tools/openings/lineprobs.json` → `node shogi/tools/openings/build.js` で openings-*.json の `lineProbs` に入る（3D のレッスンだけが使い、実戦の問題が5問に足りない分を手順の順に補う。2D の実戦練習は今までどおり）。
  - 問題：組む側（`side`、囲いはすべて☗先手）の3手目以降の各手で「手順の次の一手は？」。正解＝手順の手＋**手順を入れかえても同じ最終形になり、AI評価が −60 以内の手**（囲いの組む順番ちがい）。AI はサイト最強設定と同じ wasm＋NNUE（`shogi/tools/openings/wasm-engine.js`）。
  - 手順の手が AI の最善より 150 以上悪い局面は `dub`（鬼殺しなどハメ手：「AIの評価は少し下がるけど、この手が持ち味」と言う）、400 以上悪い局面は手順に見落としがあるとみて出さない。
  - 点数（mode 'line'）：正解 20 点、ほかの手は手順の手との AI 評価の差から最大 12 点（部分点。正解あつかいにはしない）。
  - 文：atlas/lessons3d.js の `SHJ_OP.askL / tailL / dubL / altL / leadL / hintL` と `shLineJa`（不正解は「タダで取られる」「取り返しそびれ」「その手は手順のあとで指す手＝いまはまだ早い」「形勢を損ねる」「悪い手じゃないけど形からはずれる」を盤面と AI 評価から選ぶ）。
  - 定跡の手順（src/*.js の line）を変えたら lineprobs.js → build.js を実行し直す。
- ドット・アンド・ボックス（dots）：日本語の導入・問いかけ・ヒント・ひとこと（ハコピヨの口調、座標なし）は atlas/lessons3d.js の `DTJ`（lsvoice-ja.js の dots は廃止）。正誤の解説は `dotsJa`（盤面から `dFacts`＝取れる箱の数・相手に渡る箱の数・端から開いた2箱の鎖・安全な線の数を判定し、緑の線との違いとソルバー値の差（(best−v)/2 箱）で理由を言う）。不正解の見出しは「おしい！」だけ（解説が緑の線を言う）。
- ヘックスの定跡（hex/open）：日本語の導入・手順のメモ（ゴイシペンの口調、座標なし）・問題の問いかけ・ヒント・正誤の解説は atlas/lessons3d.js の `HXJ_OP`・`HEX.opJa`（盤面から `HXA`＝ブリッジ・割りこみ・割りこみへの受け・2段目の辺のテンプレート・つけて止める／離れてふさぐ・スワップを判定し、openings.json の sc（AI評価）から勝つ見込みの差を言う。ヒントは場所を言わず点線の輪で範囲だけ）。3D の答え合わせは hex 専用の分岐で p.good(u)/p.ng(u) を表示し、緑の印＝正解・赤い印＝自分の手（レッスンも同じ分岐。以前は汎用の分岐で解説が出ていなかった）。
- シャンチーの定跡（xiangqi/open）：日本語の導入（ショウギツネの口調、座標・筋の番号なし）・手順のメモ・問題の問いかけ・ヒント・正誤の解説は atlas/lessons3d.js の `XQJ_OP`・`XQ_WHY`・`xqOpJa`・`xqNotesJa`（盤面から `xqFacts`＝取る・取り返す・王手・車を出す／横車／川を渡る・馬を出す／端へ・中炮・九宮の角の炮・馬の道を開ける兵・守りの仕相・新しくねらう駒・取られる駒（engine の threats）を判定し、openings.json の sc（AI評価）の差を「ほんの少し／少し／はっきり／かなり」で言う。手順のメモの「（AI: …）」は残す）。問いかけは手番を言わない（ランナーが「黒の番だよ」を先に出す）。不正解の見出しは「おしい！」（p.own、解説が緑の矢印を言う）。
- タフルの定跡（tafl/open）：日本語の導入・手順のメモ・問題の問いかけ・ヒント・正誤の解説（タフリンの口調、座標なし）は atlas/lessons3d.js の `TFJ_OP`・`TF_WHY`・`tfOpJa`・`tfNotesJa`（盤面から `tfFacts`＝取る・はさまれそうな駒を逃がす・角固め・王の動けるマスを増やす／減らす・つぎのはさみ取りのねらい・端へ／角へ・相手の次の手での駒取り／王の脱出・捕獲を判定し、openings.json の sc（AI評価）の差を「ほんの少し／少し／はっきり／かなり」で言う）。問いかけで手番（攻め手／守り手）を言う（問題ごとに手番が変わる）。手順のメモの AI の見立ては変わったときだけ付ける。不正解の見出しは「おしい！」（p.own）。
- チェッカーの定跡（checkers/open）：日本語の導入（チェッカニの口調、マスの番号なし）・手順のメモ・問題の問いかけ・ヒント・正誤の解説は atlas/lessons3d.js の `CKJ_OP`・`CK_WHY`・`ckOpJa`・`ckNotesJa`（盤面から `ckFacts`＝取る・取り返す・取って交換になる・交換をしかける・ショット（取らせて跳び返す）・ねらわれた駒を守る・キングになる・後ろの段の駒を出す・中央・端を判定し、取り合いの損得は取りの連続を読み切って数える。openings.json の sc（AI評価）の差を「ほんの少し／少し／はっきり／かなり」で言う）。不正解の見出しは「おしい！」（p.own）。
- タフルのレッスン（tafl）：日本語の導入・問いかけ・ヒント（タフリンの口調、座標なし）は atlas/lessons3d.js の `TFJ_LS`（intro / ask / hint）。正誤の解説は `tfLsJa`（盤面から `tfLF`＝王が端に着くか・取った駒の数と角／玉座の助け・王の逃げ道の数（kingLines）・勝ち方（脱出・砦・包囲・捕獲）・相手の次の手での駒取り／王の脱出／トゥイチを判定）。正解のほめ言葉は「その手」（赤い印の手と書かない）。評価で点が決まる s_corner・s_breakout・s_squeeze は定跡の `tfOpJa` を流用し、問いかけとヒントだけレッスン用。3手の問題（b_escape・b_kingcap）は盤の印で手を言う定型文を3通り。
- ナイン・メンズ・モリスのレッスン（morris、ナイン／シックス／トゥエルブの41本）：日本語の導入・問いかけ・ヒント（モリフクの口調、座標なし）は atlas/lessons3d.js の `MRJ_LS`（intro / ask / hint）。正誤の解説は `mrLsJa`（盤面から `mrF`＝ミルになるか・取った駒が相手の2つ並びか／きみの線をふさぐ駒か・相手のミルの点をふさぐか・手のあとの両者のミルの点の数（2つなら両取り）・相手の動ける道（となりの空き点の数。置く時間も同じ数え方）・ミルを開いた点に相手が入れるか・相手の両取りの返し・勝ち、エンジン採点の問題は P.sc の勝ち／負けも）。正解は理由、不正解は緑の印の手と、きみの手の見落とし。エンジン（morris/engine.js）は MORRIS.load で読む。
- 文末のばらし：atlas/lessons3d.js `varyJa`（自動。手書きで変化をつけた文はそのまま）。
