# パトリ（patolli/）設計仕様

世界のボドゲ大百科のヒストリカル枠。アステカの賭けのレースゲーム。構造の手本は同じ「サイコロのレース」の `ur/`（ウル王朝のゲーム）。
状態：制作中（BETA・未掲載）。

## 0. 史料で確かなこと／復元であること（調査 2026-11-16）
当時のルールは残っていない。画面の文章は必ずこの区別を守る。
- **史料で確か**：ござ（ペタテ）に液状ゴムで描いた十字（X）の盤（デュラン）。小石12個＝赤6・青6を2人で分ける（デュラン、サアグン）。印（穴）をつけた豆を投げる（サアグンは4個、デュランは5〜6個）。豆5個すべて印＝10（デュラン）。大きな賭けを伴い、身分を問わず遊ばれた。賽の神マクイルショチトル（「五の花」）の名を呼んで投げた（デュラン、マリアベッキアーノ絵文書の絵）。スペイン人が禁じ、ござや豆を焼いた（デュラン）。名前は豆（patolli）から。
- **史料にない（＝復元）**：入り方、進む向き、印のマスの意味、同じマスの扱い、上がり方、マスの数。
- **解釈・説**：「52マス＝暦の52年周期」はカソの解釈（史料に明言なし。「〜という説がある」と書く）。パチーシとの関係（タイラー 1878–79 のアジア起源説。現在は別々に生まれたとみるのが主流）。
- **書かない**：「僧が手を焼いた」（出典を確認できず）、「テオティワカンの紀元前から」（石に刻まれた古い盤は四角い別系統。十字形は主に征服後の絵文書で知られる）。
- マヤの床に刻まれた盤（最古は古典期前期、ティカル・コパン）は形もまちまちで、ルールは伝わっていない。
- 出典：R.C. Bell『Board and Table Games from Many Civilizations』(1960) / A4 Games 版の解説 PDF / rulespal.com/patolli/rulebook（ベルの規則の転載）/ en.wikipedia.org/wiki/Patolli / mexicolore.co.uk の各記事 / nahuatl.wired-humanities.org/content/patolli / Depaulis 2018（要旨）。

## 1. ルール（`engine.js` の `RULES`）
共通：2人、各6個。豆5個を投げ、印の出た数だけ1個を進める（1〜4。5個すべて＝10。0個＝進めない）。確率 0:1/32、1:5/32、2:10/32、3:10/32、4:5/32、10:1/32。自分の駒のいるマスには止まれない。腕の先の丸いマス（8つ）に止まるともう一度。印のマス（8つ）は罰。盤を一周し、**ちょうどの目**で上がる。動かせる駒があれば必ず動かす。

### `bell` ベルの復元（既定）— R.C.ベル 1960。本人が「知られていることが少なすぎる」と断った提案規則
- 60マス（腕 2列×7 が4本＋中央4）。
- 最初に各自が賭けを場に出す（ゲーム内：宝20のうち4ずつ）。
- 入場：自分に近い中央マスから入り、目の数だけ進む。**盤に自分の駒が1つもなければどの目でも**、あれば**「1」の目だけ**。
- 相手の駒のいるマスにも止まれない。**取りはない**。
- 動かせる駒がない：場へ1。印のマス：相手へ2。1個上がるたび相手から1。0の目は何もなし。
- 6個すべて先に上げた方が勝ちで、場を取る。
- 向き：ベルは「最初の駒で右回りか左回りかを各自が選ぶ」。ゲーム内は対局設定「進む向き」（同じ向き＝既定／逆向き）。

### `popular` 広く知られたルール — 英語版 Wikipedia などの現代のルール（出どころの裏づけは弱い。史料由来とは書かない）
- 52マス（腕 2列×6 が4本＋中央4）。宝は各6。
- 入場は「1」の目だけ（出発マス＝自分に近い中央マスに置く）。
- **中央の4マスでだけ**相手の駒に止まれて、取れる（取られた駒は待ちに戻り、持ち主が1払う）。
- 0の目：供え物として場へ1（その回に上がりきった方が受け取る）。印のマス：相手へ1。1個上がるたび相手から1。動かせないときは手番を失うだけ。
- 6個上がるとその回は終わり。相手の宝がなくなった時点でゲーム終了（なくなっていなければ宝を持ち越して次の回。上がった側から）。
- 入れていないもの：「豆がすべて立ったら総取り」（確率を決められない）。歴史の話としてだけ触れる。

### ゲーム内で決めたこと（史料・復元のどちらにもないもの。ルール説明に「このゲームでの決まり」と書く）
- 印のマスの位置：各腕の、先から数えて4つ目の2マス（図によって位置が違う）。
- 2人の出発マスは向かい合う中央マス。宝が足りないときは払える分だけ払う。

## 2. 盤の座標（`engine.js`）
- 周回位置 q＝0..N−1（N＝8a+4、a＝腕の長さ）。中央マスは q＝0, 2a+1, 4a+2, 6a+3。`rcOfQ(R, q)` が一辺 2a+2 の格子の [行, 列] を返す（腕は上・右・下・左、時計回り）。画面では全体を45度回してX形に見せる。
- 駒の位置 i：0＝待ち、1..L＝盤上、L+1＝上がり。`qOf(R, side, i, dir)`。side 0＝手前（下）、side 1＝奥（上）。bell は L＝59（出発の中央マスは通るだけ）、popular は L＝52（1マス目＝出発マス）。
- `kindQ`：'c' 中央／'e' 腕の先（もう一度）／'p' 印のマス（罰）。

## 3. エンジンAPI（`window.PatolliEngine`、Worker・Node 共通。`ur/engine.js` に合わせた形）
```
RULES, PROB, STEPS, newGame(rule, { first, dir:[±1,±1] }) → state
state = { rule, pos:[[6],[6]], turn, winner, gold:[a,b], pool, dir, round }
rollDice(rng) → { dice:[0|1 ×5], k, n }          // n＝進む数（0,1,2,3,4,10）
legalMoves(state, n) → [{ piece, from, to, enter, finish, capture, again, pen }]
apply(state, move|null, n) → { state, again, ev:[{t:'pay',from,to:0|1|'pool',amt}|{t:'cap',side,piece}|{t:'pot',to,amt}|{t:'round',winner,round}|{t:'end',winner,why}] }
coords(rule, side, i, dir) → [r,c]；kind(rule, side, i, dir)
winProb(state, d)；evaluate(state, n, d) → [{ move, wp }]；think(state, n, level 1..20, { rng, ev, d, temp })
```
- AI：期待値探索（投げ d 回先）＋手数の見積もりによる形勢。Lv.1〜7＝手のあと0投、8〜15＝1投、16〜19＝2投、20＝3投先まで読む（1投読むだけで勝率 約65〜75%、2投目はベルでは差なし・広く知られたルールで65%、3投目は 52〜53%。Lv.20 の1手は平均 3〜4 ミリ秒）。弱いレベルは勝率差のソフトマックスでばらつく。
- 検査：`node tools/selftest.js`（盤の形、ルールの要点、宝の総数が変わらないこと、自動対局が必ず終わること）。

### 盤（`board2d.js`、`window.PatolliBoard2D`）
- 枠は正方形（viewBox −500…500）。エンジンの十字の格子を45度回して X 形に描く。手前（下）が side 0、奥（上）が side 1。
- X の4つのすき間を使う：下＝side 0 の「待ち」と「上がり」、上＝side 1、左＝豆を投げる場所（投げるボタンもここ）、右＝宝（相手・場・自分）。
- 腕の先の2マスは丸い印（もう一度）、罰のマスは黒い三角（外側の辺から中心線へ）、中央4マスは色つき。
- 盤6種：`petate` ござ＋黒いゴムの線（既定）／`hide` 鹿革／`stone` 石板／`codex` 絵文書／`mosaic` トルコ石／`night` 夜。駒6種：`pebble` 赤と青の小石（既定）／`maize` とうもろこし／`obsidian` 黒曜石と貝／`jade` ひすいと赤い石／`clay` 素焼き／`gold` 金とトルコ石。側の呼び名は駒に合わせる（赤／青、白／黒 …、`i18n` の `pn.*`）。盤と駒の名前はデザインの呼び名で、史料の裏づけがあるのは「ござにゴムの線」「赤と青の小石」だけ。
- 豆：黒い豆5個、片面に白い点。投げ込む動きのあと、数（`= n`）を出す。
- API：`mount(host, { design, pieces, trayLabel, speed })` → `render(state, { targets, hint, last, marks })`／`on('cell'|'tray')`／`animateMove(side, from, to, { capture })`／`animatePay(from, to, amt)`（from/to＝0|1|'pool'）／`setDesign`。`mini(state, { crop:'board'|'auto', … })`（一覧・タイル。'auto' は駒と印のまわりを切り出す）、`dice(host)`、`pieceIcon(pieces[, side])`。タップは座標から格子を逆算して判定（小さいマスでも押しやすい）。

### 対局（`app.js`）
- 対戦形式：AI（20段階）／レート戦（ベルの復元・同じ向き・1手30秒、`shared/placement.js`）／二人／AI同士。人はいつも手前（side 0）。
- 設定：ゲームタブ＝ルール（ベルの復元＝既定／広く知られたルール、絵と説明のカード）、ルールタブ＝進む向き（同じ向き＝既定／逆向き。ベルだけ）・手番・強さ（PRO：読む投げの数 0〜3、手のばらつき）・持ち時間（なし／1手30秒／フィッシャー）・アニメ速度、デザインタブ＝盤6・駒6（絵のタイル、選ぶとすぐ反映）。表示の項目は歯車（`shared/ngdisp.js`）。
- 棋譜の1手＝`{ s, d:[豆5個], n, m:{from,to}|null, ag }`。局面は初期局面から `E.apply(st, move, n)` で作り直す。棋譜の行には宝の動き（「青へ2」「場へ1」「場の8を獲得」「第2回へ」）も出す。
- 宝の支払い：エンジンの `ev` を順に、玉が飛ぶ動き（`animatePay`）と「+n」で見せ、その間は払う前の数を描く（`payView`）。印のマス・上がり・取り・回の切り替えは盤の中央に短い文。
- 形勢＝手前側の勝率（`E.winProb(st, 1)`）。ヒント・振り返り・コーチの候補は2投げ先（`worker.js`）。レート戦の各レベルのレート `RT_LV` は `tools/rate_levels.js` で測る。
- PC は「正方形の盤＋右の情報欄 360px」の2列（対局者 → 状態と投げるボタン → 形勢 → コーチ → 棋譜。高さ 800px 以下では状態の箱を隠す）。振り返りボックスは盤と右欄の下に横いっぱい。スマホは縦1列（間隔 8px、盤は 100lvh から）、下タブは `shared/infotabs.js`。
- オンライン：`firebase-config.js` が null なので「準備中」。`online.js`・`online-ui.js` は ur の写しで ID だけ変えてある。**対局の通信の形式（豆の鎖・手の記録）はまだウルのまま**なので、Firebase プロジェクト（`patolli-multiplay`）を作るときにパトリ用に直す。
- 「はじめての方へ」の文は、`shared/rulesoffer.js` にパトリの行がまだないので `app.js` の `fixRulesOffer()` で差し替えている（共通部品に足したら外す）。

### 学ぶ
- ルール（`tour.js`、`shared/ruletour.js`）：紹介（§0 の「史料で確か」だけ）→ 盤と道 → 豆 → 最初の駒 → 「1」で入る → 進む → 駒のいるマスには止まれない → 腕の先でもう一度 → 印のマスは払う → ちょうどで上がる → 動かせないとき → 勝ち方 → 広く知られたルール①②③。各ページ、本物の盤で投げて動かす（目は決めてある）。
- レッスン（`lessons.json`、9つ）：基本（ベルの復元）＝豆の確率（選ぶ問題）・腕の先でもう一度・「1」が出たら入れる・ちょうどの目で上がる・まとめ／広く知られたルール＝印のマスを避ける・中央で取る・中央の危険を避ける・まとめ。各レッスン＝実演 → 練習 → 採点5問（20点×5、75点で合格）。豆知識は `lux.json`（§0 の事実だけ）。
- パズル（`puzzles.json`、次の一手 200問・9テーマ）：ベルの復元＝もう一度30・「1」で入れる30・ちょうどで上がる20／宝と取り合い（広く知られたルール）＝印のマス30・中央で取る20・中央の危険20／広く知られたルール＝もう一度20・入場20・上がり10。
  - 選び方：自己対局の局面から、2投げ先の勝率で最善手が2番目より 0.04 以上良く、3投げ先でも同じ手が最善のもの（`audit_puzzles.js` が全問を調べ直す）。
  - **ベルの復元は「先に6個上げた方の勝ち」で、宝は勝ち負けに関係しない**（勝率に効くのは もう一度・入場・上がり）。印のマスを避ける・中央の取り合いは、宝がなくなると負ける「広く知られたルール」の題材にした。
  - 正解でない手を選んでも「悪手」とは言わず、その手と最善手の勝率を並べて見せる（そのまま選び直せる・次の問題へ進める）。
- コーチ（`coach.js`）：勝率・レースの差・宝・上がった数、推奨方針、候補手と方針（上がる／取る／もう一度／印のマス／逃げる／入場／中央へ／前進）、ヒント（「1」でしか入れない・動かせない確率・腕の先や印のマスに届く目・中央で取られる確率・豆の確率）、前の手の評価。
