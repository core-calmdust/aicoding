# パトリ（patolli/）設計仕様

世界のボドゲ大百科のヒストリカル枠。アステカの賭けのレースゲーム。構造の手本は同じ「サイコロのレース」の `ur/`（ウル王朝のゲーム）。
状態：制作中（BETA・未掲載）。

## 0. 史料で確かなこと／復元であること（調査 2026-11-16）
当時のルールは残っていない。画面の文章は必ずこの区別を守る。
- **史料で確か**：ござ（ペタテ）に液状ゴムで描いた十字（X）の盤（デュラン）。小石12個＝赤6・青6を2人で分ける（デュラン、サアグン）。印（穴）をつけた豆を投げる（サアグンは4個、デュランは5〜6個）。豆5個すべて印＝10（デュラン）。大きな賭けを伴い、身分を問わず遊ばれた。賽の神マクイルショチトル（「五の花」）の名を呼んで投げた（デュラン、マリアベッキアーノ絵文書の絵）。スペイン人が禁じ、ござや豆を焼いた（デュラン）。名前は豆（patolli）から。
- **史料にない（＝復元）**：入り方、進む向き、印のマスの意味、同じマスの扱い、上がり方、マスの数。
- **解釈・説**：「52マス＝暦の52年周期」はカソの解釈（史料に明言なし。「〜という説がある」と書く）。パチーシとの関係（タイラー 1878–79 のアジア起源説。現在は別々に生まれたとみるのが主流）。
- **書かない**：「僧が手を焼いた」（出典を確認できず）、「テオティワカンの紀元前から」（石に刻まれた古い盤は四角い別系統。十字形は主に征服後の絵文書で知られる）。
- マヤの床に刻まれた盤（最古は古典期前期、ティカル・コパン）は形もまちまちで、ルールは伝わっていない。
- 出典：R.C. Bell『Board and Table Games from Many Civilizations』(1960) / A4 Games 版の解説 PDF / rulespal.com/patolli/rulebook（ベルの規則の転載）/ en.wikipedia.org/wiki/Patolli / mexicolore.co.uk の各記事 / nahuatl.wired-humanities.org/content/patolli / Depaulis 2018（要旨）。

## 1. ルール（`engine.js` の `RULES`）
共通：2人、各6個。豆5個を投げ、印の出た数だけ1個を進める（1〜4。5個すべて＝10。0個＝進めない）。確率 0:1/32、1:5/32、2:10/32、3:10/32、4:5/32、10:1/32。自分の駒のいるマスには止まれない。腕の先の丸いマス（8つ）に止まるともう一度。印のマス（8つ）は罰。盤を一周し、**ちょうどの目**で上がる。動かせる駒があれば必ず動かす。

### `bell` ベルの復元（既定）— R.C.ベル 1960。本人が「知られていることが少なすぎる」と断った提案規則
- 60マス（腕 2列×7 が4本＋中央4）。
- 最初に各自が賭けを場に出す（ゲーム内：宝20のうち4ずつ）。
- 入場：自分に近い中央マスから入り、目の数だけ進む。**盤に自分の駒が1つもなければどの目でも**、あれば**「1」の目だけ**。
- 相手の駒のいるマスにも止まれない。**取りはない**。
- 動かせる駒がない：場へ1。印のマス：相手へ2。1個上がるたび相手から1。0の目は何もなし。
- 6個すべて先に上げた方が勝ちで、場を取る。
- 向き：ベルは「最初の駒で右回りか左回りかを各自が選ぶ」。ゲーム内は対局設定「進む向き」（同じ向き＝既定／逆向き）。

### `popular` 広く知られたルール — 英語版 Wikipedia などの現代のルール（出どころの裏づけは弱い。史料由来とは書かない）
- 52マス（腕 2列×6 が4本＋中央4）。宝は各6。
- 入場は「1」の目だけ（出発マス＝自分に近い中央マスに置く）。
- **中央の4マスでだけ**相手の駒に止まれて、取れる（取られた駒は待ちに戻り、持ち主が1払う）。
- 0の目：供え物として場へ1（その回に上がりきった方が受け取る）。印のマス：相手へ1。1個上がるたび相手から1。動かせないときは手番を失うだけ。
- 6個上がるとその回は終わり。相手の宝がなくなった時点でゲーム終了（なくなっていなければ宝を持ち越して次の回。上がった側から）。
- 入れていないもの：「豆がすべて立ったら総取り」（確率を決められない）。歴史の話としてだけ触れる。

### ゲーム内で決めたこと（史料・復元のどちらにもないもの。ルール説明に「このゲームでの決まり」と書く）
- 印のマスの位置：各腕の、先から数えて4つ目の2マス（図によって位置が違う）。
- 2人の出発マスは向かい合う中央マス。宝が足りないときは払える分だけ払う。

## 2. 盤の座標（`engine.js`）
- 周回位置 q＝0..N−1（N＝8a+4、a＝腕の長さ）。中央マスは q＝0, 2a+1, 4a+2, 6a+3。`rcOfQ(R, q)` が一辺 2a+2 の格子の [行, 列] を返す（腕は上・右・下・左、時計回り）。画面では全体を45度回してX形に見せる。
- 駒の位置 i：0＝待ち、1..L＝盤上、L+1＝上がり。`qOf(R, side, i, dir)`。side 0＝手前（下）、side 1＝奥（上）。bell は L＝59（出発の中央マスは通るだけ）、popular は L＝52（1マス目＝出発マス）。
- `kindQ`：'c' 中央／'e' 腕の先（もう一度）／'p' 印のマス（罰）。

## 3. エンジンAPI（`window.PatolliEngine`、Worker・Node 共通。`ur/engine.js` に合わせた形）
```
RULES, PROB, STEPS, newGame(rule, { first, dir:[±1,±1] }) → state
state = { rule, pos:[[6],[6]], turn, winner, gold:[a,b], pool, dir, round }
rollDice(rng) → { dice:[0|1 ×5], k, n }          // n＝進む数（0,1,2,3,4,10）
legalMoves(state, n) → [{ piece, from, to, enter, finish, capture, again, pen }]
apply(state, move|null, n) → { state, again, ev:[{t:'pay',from,to:0|1|'pool',amt}|{t:'cap',side,piece}|{t:'pot',to,amt}|{t:'round',winner,round}|{t:'end',winner,why}] }
coords(rule, side, i, dir) → [r,c]；kind(rule, side, i, dir)
winProb(state, d)；evaluate(state, n, d) → [{ move, wp }]；think(state, n, level 1..20, { rng, ev, d, temp })
```
- AI：期待値探索（投げ d 回先）＋手数の見積もりによる形勢。Lv.1〜11＝0投先、12〜19＝1投先、20＝2投先。弱いレベルは勝率差のソフトマックスでばらつく。
- 検査：`node tools/selftest.js`（盤の形、ルールの要点、宝の総数が変わらないこと、自動対局が必ず終わること）。
