# コナネ（konane/）仕様

URL: https://core-calmdust.github.io/aicoding/konane/ ／ トップは「アルケルケ」の次（cat: hist＝ヒストリカル、also: chess、定番タグ）。テーマ色 #0f8a7e（ティール）。

## ルール（8×8 を既定、ゲームタブで 6×6・8×8・10×10）
- すべてのマスに黒白の石を交互に置いて開始（a1＝黒、黒が先手 P1）。
- 1手目：黒が中央の2×2か四隅にある黒石を1個取り除く。2手目：白がその穴の上下左右に隣接する白石を1個取り除く。
- 以降の手はすべて「縦横に隣の相手の石を跳び越えて、その先の空きマスへ」。跳び越えた石を取る。同じ向きなら連続で跳べ、どこで止めてもよい（向きは変えられない）。斜めは不可。
- 自分の番に跳べる手がない側の負け。引き分けはない（引分提案ボタンも出さない）。
- 出典（2026-11 確認）：Wikipedia「Kōnane」、likonane.org、Board Game Arena、mindsports.nl。歴史：NPS（プウホヌア・オ・ホナウナウのパパムー）、Kaʻiwakīloumoku（カメハメハ・スクールズ）、Images of Old Hawaiʻi（クック：238マス・1列14、キャンベル：片側18個・カメハメハの腕前、ピコ・カカイ、ペレとカマプアア）、Hawaiʻi Public Radio（2026年2月 ビショップ博物館の招待トーナメント）。

## エンジン（engine.js、純JS、Web Worker）
- setRule('s6' | 's8' | 's10') で盤を作り直す（RC・RAYS・ADJ・OPEN1）。手 m = from + 128×to。取り除き（序盤2手）は from = to。
- 評価：跳べる手の数の差×34 ＋ 跳べる石の数の差×52 ＋ 手番30（約100＝余裕1手）。negamax＋TT＋killer、反復深化。
- 23段階（Lv. 表記）：弱い段はノイズ付き浅読み（終局の一手は逃さない）、中段はノード数、Lv.19/20 は 1.2 秒／2.5 秒、Lv.21〜23 は 5・10・20 秒（全スレッド、2026-11-09）。RT_LV は app.js。
- ソルバー：duelGood / duelMin / duelReply（N 手以内に相手を跳べなくする、相手は最長抵抗）、winningMoves / solve（完全読み、レッスンの正解集合）。
- 高速化（2026-11-08、結果は不変）：探索と手の並べ替えの子局面を使い回す（`child()`）、並べ替えは安定な挿入ソート。約1.1倍（残りの大半は並べ替えでの跳べる数の数え直し）。

## 画面（ugolki/ から派生）
- 盤（tools/gen_art.py ＋ gen_art_more.py のレンダリング画像、方針は「アーティスティックに」：質感の写実より絵としての美しさ）8種：ハワイアンキルト（既定）・オーシャンアート（ラッセン風の夕日の海・イルカ・ホヌ）・コナ・アート（水彩のモンステラ・ハイビスカス・プルメリア）・石のパパムー（風化した玄武岩、プリミティブ）・コアの盤・モダン3種（グレー・サンセット・ミッドナイト）。駒5種：玄武岩と珊瑚の小石（既定、なめらか）・真珠・コア材・ガラス・マット。ボツボツ・多孔質など対局中に気が散る質感は使わない。各マスにプカ（くぼみ）、座標 a–j / 1–10。
- 盤の上下：取られた数と跳べる手の数のプレート。序盤は取り除ける石が光る（rmable）、以後は「跳べる石を光らせる」オプション（mov）。最後の1手の残りは盤下の案内。
- ルール（RuleTour、実際の盤）：紹介 → 盤と石 → 黒の取り除き → 白の取り除き → 跳んで取る → 連続ジャンプ → 曲がれない → 途中で止まる → 跳べなくなったら負け → 盤の大きさ。
- レッスン9（tools/gen_lessons.js ＋ lesson_ramps.js、正解集合はルール／完全読みで計算）：はじめて4（最初の取り除き・取れる石を探す・連続ジャンプ・最後の跳び）、作戦5（相手の手を数える・途中で止まる・続けて跳ぶ・自分の手を残す・先を読む）。各5問・満点20・合格75。
- パズル（tools/gen_puzzles.js → build_puzzles.js、PZBook v2 の勝ち切り型）：「N 手以内に相手を跳べなくせ」、相手は最長抵抗。勝ちの初手は1〜2通り、「相手の跳べる手が最も減る手」だけでは解けないものだけ。テーマ7＝N手で勝て（w1〜w5）＋止まって勝つ（stop）＋続けて勝つ（chain）。1手で勝て（w1）は簡単すぎるので難しい順に10問だけ、ほかは各36問・計226問。build 時に全問を再検証。
- コーチ（coach.js / coach-i18n.js 10言語）：序盤は評価値ではなくルールで解説（中央か隅か・どの隣を取るか、AIの好みは「少し好む」とだけ）。以降は方針分類（最後の跳び・連続跳び・途中で止める・相手の手を消す・自分の手を残す・端へ）と、跳んだ後の双方の「跳べる手」の数。
- オンライン：Firebase プロジェクト konane-multiplay（App Check サイトキー設定済み）。ルールは shared/tools/secrules.py の konane（s8・s6、引き分けなし）→ konane/database.rules.json。DBルールはコンソールに貼り付け、App Check に reCAPTCHA Enterprise キーを登録（claude/online-security-setup.md）。10×10 はオフラインのみ（K64 の 3 文字エンコードが 64 マスまで）。

## 対局設定の Pro モード（2026-11-08）
対局設定の「AIの強さ」の PRO ボタン（`shared/proset.js` の `ProSet.ladder()`、addendum「対局設定の Pro モード」）。項目：思考の制限（時間／深さ／局面数）、手のばらつき（深さで読むときだけ。弱い段の既定はその段のノイズ、変えると 小＝いちばん弱いノイズ／大＝弱い段の中ほどのノイズ）。変えた値は engine.js `think` の `cfg`（LEVELS と同じキー。強い段の最大深さは `dx`）で渡す。レート戦では使わない。戦績のキーは `ai:pro<レベル>`、相手名に「PRO」。

## WebAssembly の探索（2026-11-10）
- `search()`（αβ・置換表・手の並べ替え・キラー・LMR・評価）を `core.c` に移植（`tools/build-core.sh` → `core-wasm.js`＝base64。ワーカーと Node は同期で読み込み、ページ本体と失敗時は JS のまま）。置換表は前の Map と同じ規則（h1 をキー、70万件を超えたら全部消す）を C の表で再現し、局面数・時間の確認・キラーも同じ順なので、**1スレッドの結果は JS と完全に一致**（`node tools/check_wasm.js`：3つの盤・Lv.12/15/18 の213探索で手・評価値・深さ・局面数が一致）。共有の置換表（分離ページの複数スレッド）は import 経由で `shared/mttt.js` の表を使う。
- 速さ：同じ時間の局面数 約2倍（作業機、Lv.20 で 30万→59万）。Lv.1〜18 の手は変わらず速くなるだけ、時間で考える Lv.19〜23 は強くなる（RT_LV の見直しが要る）。

## 本編のマルチスレッド（2026-11-08、`shared/mtsplit.js`）
- エンジンが JavaScript だけなので、**ふつうの Worker の組**（同じ `engine.js` を複数）で読む。**ページが分離されているときは置換表を1つ共有する**（2026-11-09、`shared/mtsplit.js` の共有モード＋`shared/mttt.js`：SharedArrayBuffer、ロックなしの XOR 照合、端末のメモリで 16〜64MB、探索ごとの年齢、止める合図も共有メモリ）。分離は `konane/sw.js`（mtengine.js と同じ軽い方式：Chrome / Edge の PC は Document-Isolation-Policy で自動・初回だけ再読み込み、ログイン・オンライン対戦はそのまま。Safari・Firefox はオプションをオンにしたときだけ COOP モード＝ログイン・オンライン対戦は止まる。スマホはオンにするまで Service Worker を入れない）。分離できないとき（Safari・Firefox で自動のまま等）は今まで通り各 Worker が自分の置換表を持つ（非共有）。オプション（歯車）の「マルチスレッド」は mtengine.js のゲームと同じ選択（全ブラウザで `aicoding-mt`。PC は自動でオン、スマホ・タブレットはオンにするまで1スレッド）。1スレッドの Worker（局面数・深さで決めるレベル）は今まで通りの置換表で、指し手・局面数は前と同じ（確認済み）。
- 方式：**ルートの手と本筋の分担（Young Brothers Wait）**。各深さで最初の手（前の深さの最善手）を先に読み、その間ほかのスレッドは残りの手を前の深さの評価値と比べる null window で試す。最初の手が終わったら残りを本当の α で並列に試し、上回った手だけ (α, ∞) で読み直す。本筋は分けない（コナネは置換表に強く頼るので、本筋を分けると局面数が2倍を超え、ルートだけの方が速い：深さ11で8スレッド 約2.3倍 対 1.2倍）。解析（分析・ヒント・コーチ・検討ボックス）は全部の手を深さごとに全幅で分け合う。エンジン側は `mtPlan`（読むもの・その場の答え）・`mtV`（ルートからの手順 `line` の局面を窓 (wa, wb) で）・`mtKids`（その局面の手の順）・`mtPv`・`mtFin`（1スレッドと同じ形の返事）。
- 使う所：分析・ヒント・コーチ（深読み＝Lv.19）・検討ボックス（`rvbox.js` に `pool()`／`cancel()`）・時間で考えるLv.19・20（レート戦も）。Lv.1〜18は局面数・深さで決めるので1スレッドのまま（置換表を共有しないため、同じ局面数では1スレッドより浅くなる：局面数の上乗せが2スレッドで約1.1〜1.5倍）。PRO の「スレッド数」はどの制限でも（局面数は全スレッドの合計）。AI の手は分析などからスレッドを譲ってもらう（`pool('ai')`）。情報行の末尾に全スレッド合計の「· NNNk nps」。
- 計測（作業機は共用2コアのため、実際の速さはユーザーの Mac で `konane/bench.html`）：作業機では各スレッドを別の置換表を持つエンジンにして、仕事の量（局面数）で時間を数えるシミュレーションで見積もった。最善手の探索（深さ11、3局面、ルートだけ分担）：2スレッド 約1.2倍、8スレッド 約2.3倍（局面数は1スレッドの約1.1倍）。最善手は1スレッドと一致。
- 共有の置換表の効果（2026-11-09、深さ12、ふつうの1スレッドの読みの局面数を基準）：Young Brothers Wait では共有しても伸びない（ルートだけ 8スレッド 約1.2倍、本筋も分けると1スレッド分の仕事が3倍に増える。`shared/tools/mtsim.js`）。**Lazy SMP**（`shared/tools/mtlazy.js`：実スレッド、主スレッドの局面数を時間とみなす）は 8スレッド 約2.9倍、4スレッド 約2.8倍、2スレッド 約2.4倍なので、共有モードの最善手（時間で考えるレベル・PRO・コーチの深読み）は Lazy SMP：主の Worker が1スレッドと同じ探索（`mtlead`）、残りは同じ局面を読み続ける（`mthelp`：1つおきに1手深く、ルートの手の順を回す）。主が終われば止める合図で全員止まる。解析は深さごとに全部の手を分け合う方式のまま（置換表も共有）。分離できないときは今まで通りルートだけの分担（非共有）。
- **最上位レベル Lv.21〜23（2026-11-09）**：時間で考える 5秒・10秒・20秒（Lv.20 の 2.5秒から1段階2倍、全スレッド、レート戦も。レート戦では持ち時間（5分＋3秒）を超えないよう、残り時間の約1/20＋加算の8割までに縮める）。1スレッド・オプションオフでも同じ時間で読む。開いた直後でスレッドの準備がまだのときは最大4秒待つ。1段階の幅は局面数の2倍対1倍の対局（`shared/tools/nodematch.js`、序盤4〜8手をLv.9で散らし先後入れ替え）で：5万対10万局面 +241 Elo（80局、95%区間 +158〜+359）、20万対40万局面 +191 Elo（24局、+54〜+432）。引き分けがなく、読みの深さがそのまま勝敗に出るゲームなので、他の2つより幅がずっと大きい。局面数とともに少しずつ縮む見込みで、Lv.21〜23（全スレッドで1スレッドの数百万〜1千万局面相当）には控えめに1段階 +120 Elo とし、RT_LV は 2470・2590・2710（ユーザーの Mac の対局で見直す）。大百科の3D卓も 23 まで。
