# ウゴルキ（ugolki/）仕様

URL: https://core-calmdust.github.io/aicoding/ugolki/ ／ トップは「チェッカー」の次（cat: chess、定番タグ、online タグ）

## ルール（古典3×3を既定、ゲームタブで4種）
- 8×8。白（先手 P1）は左下 a1–c3、黒（P2）は右上 f6–h8 に9枚。相手の陣地（初期配置の隅）を全部うめたら勝ち。
- 手：縦横に1マス（斜めルールは斜めも）、または隣の駒（敵味方どちらでも）を跳び越えて空きマスへ。連続ジャンプ可・途中で止まってよい・向きを変えてよい。取りはない。
- 決着は黒の手番のあと：白が先に完成し黒が次の1手で完成しなければ白勝ち、両者完成＝引き分け、黒が先に完成＝黒勝ち。
- 40手ルール：40手目（黒の40手目のあと）に自陣に駒が残っている側は負け（両方なら引き分け）。80手で決まらなければ相手陣地に入れた枚数で決着（同数は引き分け）。同一局面3回＝引き分け。動けない＝枚数で決着。
- 種目：c33（3×3・40/80）、c34（3×4・12枚・50/100）、c44（4×4・16枚・60/120）、diag（斜めあり・30/80）。c34/c44 の手数は本サイトの設定。
- 出典：I. トロイツキー『古典ウゴルキ教本』（定跡・40/80手ルール）、gamerules.ru、sports.ru。

## エンジン（engine.js、純JS、Web Worker）
- 盤 Int8Array(64)、手 m = from + 64×to（PASS=4096 は旧一人用パズル用）。BFSで跳び先を列挙（parent で経路）。reach の stamp は 2e9 で巻き戻す（長時間計算での桁あふれ対策）。
- 評価：遠い隅までの距離の和（BASE差し引き）×34、遅れた駒、自陣残り（期限が近いほど重く）。negamax＋TT＋killer＋LMR、反復深化。
- 20段階：15級〜5級は固定深さ1〜4＋ノイズ＋悪手確率、4級〜三段はノード数（3千〜22万）、四段・五段は1.2秒／2.5秒。
- 二人用ソルバー duelGood / duelMin / duelReply（2026-11-04）：手番側が自分の N 手以内に必ず勝つか（judge どおり、白の完成後の黒の最後の1手も含む）。枝刈り＝陣地外の駒数 > 残り手数。相手の応手は「勝つのに最も手数がかかる手」（同点は相手自身の入陣／こちらの陣地をふさぐ手）。Worker メッセージ 'duel' / 'duelReply'。
- 一人用ソルバー soloMin / soloGood は s_deep レッスンで使用。
- 高速化（2026-11-08、結果は不変）：`judge` の「動ける手がない」判定を手の列挙でなく `Pos.hasMove()`（1歩か最初の跳びがあるか）で、探索の同一局面チェックを文字列 `"h1:h2"` の配列検索から数値の配列（`RH1/RH2`）に、手の並べ替えを安定な挿入ソートに。3ルール×レベル8/13/18・各40局面で手・評価値・深さ・局面数が完全一致のまま **約2.5〜3倍**。

## 画面（checkers/ から派生）
- テーマ：グジェリ（藍と白磁、金のアクセントなし）。盤（tools/gen_art.py のレンダリング画像）：グジェリ（既定）・ホフロマ・パレフ・白樺、駒：磁器（既定）・漆塗り・琥珀・マトリョーシカ。陣地は点線枠＋淡い色、座標 a–h / 1–8。
- 盤の上下：相手陣地に入れた数 n/9 のバー、自陣の残りと40手ルールまでの手数（明朝体、プレート上）。先手後手カードは1行（色＋n/9）。
- 新規対局のゲームタブ：各ルールのカード右下に「ルール」ボタン（将棋と同形式）。3×3 はルール説明の最初へ、他はバリエーションのページへ。
- ルール（RuleTour、実際の盤）：紹介 → 盤と陣地 → 1歩 → 跳ぶ → 相手も跳べる → 連続ジャンプ → 陣地完成 → 黒の最後の1手 → 40/80手ルール → バリエーション。
- レッスン11（tools/gen_lessons.js ＋ lesson_ramps.js、全問の正解集合はルール／エンジンで計算）：はじめて4（1歩・跳び越えて進む〔単発＋連続を統合〕・陣地に入る・完成と最後の1手）、作戦7（いちばん遠くへ・道を作る・相手の駒を使う〔新設〕・ふさぐ・40手ルール・陣地を速く埋める・手数を数える）。全ステップの前に盤面の解説（explain）と必要に応じ練習1手（try）、10言語。
- 定跡（tools/gen_openings.js）：標準の定跡、標準（f3型）、ルージンの定跡。
- パズル＝勝ち切りパズル（2026-11-04、tools/gen_duel.js → build_duel.py、生データ tools/duel_raw.jsonl）：実戦の終盤局面（手数・40/80手ルールそのまま、生成時は中盤にランダム手を混ぜて形を多様化）で「手番側が N 手以内に勝て、相手も最善で粘る」。勝ちの初手は1〜2通り、素直な手（いちばん大きく前進する手）では勝てないものだけ。多様性：同じ正解手は1テーマ2題まで、正解手＋陣地の空きマスが同じ問題は1題、同じ正解手は連続させない。テーマ7＝2手（白黒混合・8題、2手は形の種類が少ないため）、白番／黒番 × 3（やさしい）、4（ふつう）、5（むずかしい）、計144問。誤答は solver で即判定して戻し正解を表示。ヒント3段階、答えの再生あり。
- コーチ（coach.js / coach-i18n.js 10言語）。
- オンライン：Firebase ugolki-multiplay（firebase-config.js、App Check キー設定済み）、ルールは shared/tools/secrules.py の ugolki → ugolki/database.rules.json。
- 3D（ポータルのフル機能版）は未対応。ポータルのアイコンは atlas/icons3d.js の ugolki()（グジェリ盤と gzhelPiece）。

## 対局設定の Pro モード（2026-11-08）
対局設定の「AIの強さ」の PRO ボタン（`shared/proset.js` の `ProSet.ladder()`、addendum「対局設定の Pro モード」）。項目：思考の制限（時間／深さ／局面数）、手のばらつき（深さで読むときだけ。弱い段の既定はその段のノイズ、変えると 小＝いちばん弱いノイズ／大＝弱い段の中ほどのノイズ）。変えた値は engine.js `think` の `cfg`（LEVELS と同じキー。強い段の最大深さは `dx`）で渡す。レート戦では使わない。戦績のキーは `ai:pro<レベル>`、相手名に「PRO」。
