# 世界のボドゲ大全：全ゲーム共通の必須仕様

新しいゲームを作るとき・改修するときに必ず満たすこと（抜けやすいもの）。
適用範囲：特記がなければプレミアムのボドゲ大全ゲームすべて（まいにち数独は除く）。

- **PCのヘッダーバー（規定）**：PCブラウザ版は画面最上部にヘッダーバーを置く（`shared/headerbar.js`）。左にタイトル、右端にアイコンセット（言語・ホーム等）、その左に別グループとしてメニューボタン。メニューの並びは全タイトル共通で **対局 ＞ 待った ＞ 投了 ＞ ヒント ＞ ルール ＞ レッスン ＞ パズル（詰め）**（その他はその後ろ）。ルールボタンがないゲームは追加する。中央の空きスペースは解析・形勢・手番など、そのゲームの情報表示に使う（2D版のみ）。引き分け提案ボタンが出ている間はボタンの幅が足りないので、ヘッダーのパズルボタンは省く（`shared/headerbar.js` が自動で行う）。ゲーム側のCSSでヘッダーに移った `.controls.hb-menu` を隠さないこと。
- **PCレイアウトとスマホ表示の切り替え（規定・2026-10-28）**：PCレイアウトの条件は `HeaderBar.MEDIA` ＝ `(hover: hover) and (pointer: fine) and (min-width: 1040px) and (min-aspect-ratio: 3/4)`。PCは基本横レイアウトで、**9:16 のように明らかに縦長（3:4より細い）か、幅1040px未満のときだけスマホ表示**（タブレット・スマホも各ゲームのスマホ表示）。
  - **PCは「盤＋右の情報欄」の2列**（3列は見づらいので不可）：左に盤、右に**固定幅の情報欄（360px。横長盤のマンカラ・バックギャモンは 310〜330px）**。右欄の幅は画面サイズで変えない。盤は「画面の高さ」と「画面幅−右欄−余白」の小さいほうで決め、右欄の高さ＝盤の高さ（中身が多いときは欄内スクロール）。広い画面では「盤＋右欄」のまとまりを中央に置き、外側は空白でよい。右欄の並び：観戦／レッスン・パズルのカード → 対局者 → 形勢（バー・グラフ・◀▶）→ 振り返り → 棋譜 → 情報行。
  - PCで縦長気味のウィンドウ（例 1100×1300）でも2列で崩れないこと（横長盤は常に横向き）。
- **投了ボタン（規定）**：対戦型のゲームはすべて、メニューの **対局・待ったの次に「投了」ボタン**（`#btnResign`、白旗アイコン）を置く。押すと **「投了しますか？」の確認ポップアップ（いいえ／はい）** を出し、はい のときだけ対局を自分の負けとして終える（既存の終局処理・結果表示・レート反映・オンラインの投了送信を通す）。確認は共通部品 `shared/resign.js` の `Resign.confirm({lang})`（10言語、既定のフォーカスは「いいえ」、Esc・背景クリックで いいえ）。文言は `Resign.label(lang)`、アイコンは `Resign.icon`。待ったボタンを投了に変える方式は使わず、待ったと投了は別ボタン（レート戦・オンラインでは待ったは無効）。対局していない・終局後・レッスン／パズル中・観戦中は投了ボタンを無効化。2人対局（同じ端末）では手番側が投了したことにする。
  - 例外：バックギャモンのオンライン対局で点数を選んで投了を申し出られる場面は、「何点で投了するか（1／2／3点）」を選ぶ既存のダイアログを使う（選択肢がない場面は共通の いいえ／はい）。オフラインの投了は1点×キューブ（勝者が上がり始めていて敗者が0枚ならギャモン／バックギャモン）。
- **ボタンの並び（規定・2026-10-28）**：否定・キャンセルが左、肯定・決定が右。確認ダイアログは［いいえ］［はい］、新しい対局ダイアログは［閉じる］［対局開始］、再開確認は［閉じる］［最初から］［続きから］、オンラインの再戦・引き分け提案は［断る］［受ける］。
- **読み込み直後（規定）**：ページを開いた直後に新しい対局ダイアログ（対局設定）を自動で出さない。保存があれば続き、なければ初期局面で待つ（AIが先手のゲームはAIが最初の1手を指してよい）。初回訪問のプロフィールなどは可。
- **結果ダイアログ（規定）**：結果ダイアログは「その場で対局が終わったとき」だけ出す。遅延表示（タイマー）の間にレッスン・パズル・別の対局へ移ったら出さない。復元した終局済みの対局・レッスン等から戻ったときは出さない。
- **ポータル版（3D）のヘッダー（規定）**：ポータルから3Dで起動したゲーム画面（`?skin=atlas`）は、PCでは世界のボドゲ大全のロゴの右に、ロゴの文字と同じくらいの大きさで**ゲーム名だけ**を出す（手番などのゲーム情報は出さない。ロゴのサブタイトル表示は変えない）。メニューの並びは2D版と同じ。`shared/headerbar.js` が自動で行う。スマホはスペースがないのでゲーム名は不要。
- **3D盤の低負荷（規定）**：3Dスキン（`?skin=atlas`）は動きがないときに描画しない（オンデマンド描画）。`atlas/table3d.js` の共通ループが行う：盤の位置・画面サイズが変わったとき、または `Table3D.kick(ms)` が呼ばれている間だけ描画し、何も動かない状態が1秒続いたら盤位置の確認も約10回/秒に落とす（リサイズで即復帰）。各スキンは **3Dの見た目を変えたら必ず `T3.kick(ms)` を呼ぶ**（駒アニメ中は毎フレーム、素材・トーン切替時は1回）。常時回り続けるアニメ（requestAnimationFrame の自前ループで毎フレーム描画）は作らない。スマホは pixelRatio 1.5まで・影マップ1024・点光源の影なし。キャンバスは盤の親要素の中に置いてページと一緒にスクロールさせる（スクロールで再描画しない）。
- **3D盤の駒の移動アニメ（規定）**：3D盤では駒の移動にアニメーションをつける（チェス：持ち上げて置く、リバーシ：落下・裏返し）。ゲーム側のアニメ設定がOFFのときは従う。
- **スマホのメニュー位置（規定）**：対局・待った・投了・ヒント・レッスンなどのメニュー（.controls）は、タイトル行のすぐ下・盤より上に置き、1段に収める（将棋・チェスと同じ。スマホ縦向きのメディアクエリで `.brand{order:-5}` `.controls{order:-4}`）。
- **スマホの縦並び（規定）**：盤 → 形勢＋ナビゲーション（◀ ▶）→ 振り返り → 棋譜 の順（スマホで見やすい順番）。振り返り中の形勢はグラフを隠した簡易表示（形勢バー＋ナビ）にし、形勢表示をOFFにしていてもナビは出す。大きさ・余白はドット＆ボックスに合わせる（手本：ドット＆ボックス・モリス）。
- **対局者カードはコンパクト（規定）**：情報欄が盤の横にあるとき（`html.side-col`、`shared/headerbar.js` が判定）、対局者カードは1行（左に名前、右に先手・後手／石数などを控えめな大きさで、状態はその下に小さく）。右欄で名前が切れるゲームは1人1行。大きな見出し文字の箱にしない。時計表示中のカードは各ゲームの時計レイアウトのまま。
- **オンライン欄を開いたとき（規定・PC）**：画面下のオンライン欄を開くと、盤と情報（.app）がヘッダーバーと開いた欄の中間へ滑らかにスクロールする（閉じると戻る）。収まらないときは先にゲームを小さく並べ直す（`html.dock-fit` ＋ `--vh` の上書き、JSで盤を決めるゲームは `DockFit.extra`）。それでも情報欄が入らなければ情報欄を詰める（`html.dock-compact`：対局者小さく、グラフ・棋譜・info-line を隠し、形勢バーと◀▶は残す）。`shared/headerbar.js` が行う。各ゲームは盤・情報欄の大きさを `--vh` から決めること（盤の最小サイズの縛りは dock-fit 中は緩める）。
- **アニメーションは省略しない（規定）**：端末の「視覚効果を減らす」（`prefers-reduced-motion`）がONでも、駒の移動・演出・紙吹雪などのアニメーションを省略しない。`@media (prefers-reduced-motion: reduce)` のCSSや、それを見て演出を飛ばすJSは書かない（アニメのON/OFFはゲーム内の設定で行う）。
- **秒読みの時報音**：秒読み（持ち時間の残りが数秒になる時計すべて）は、残り5秒から1秒まで1秒ごとに「ピッ」と鳴らす（`shared/tick.js` の `CountTick`、効果音オフのときは鳴らさない）。
- **時計の開始**：ページを開いた直後に再開・自動開始された対局では、最初の1手が指されるまで時計（秒読み）を動かさない。新しい対局ダイアログから普通に始めた対局は従来どおり。
- **終わった対局の結果**：前回終わった対局が保存されていても、ページを開くたびに結果（勝ち負け・勝利条件）のダイアログを出し直さない。
- **キー操作**：棋譜だけでなく、定跡の解説・進行例など「手順を見せる画面」すべてで ← → で1手ずつ、↓ ↑ で最初／最後へ送れること。ルールのチュートリアルも ← → で前後のページへ送れること。
- **定跡解説のスマホ表示**：盤のすぐ下に「⏮ ◀ ▶/⏸ ▶ ⏭ ＋ n / N」の操作バー。▶で約1.2秒ごとに自動再生（PCはスペースキー、タップで停止）。解説カードは解説中に高さを縮めない（ページが上に飛ばないように）。
- **一覧へ戻る**：レッスン・定跡の解説・実戦練習中のカードに「一覧へ戻る」ボタンを置き、選んだ一覧（レッスン／定跡／詰め問題）を開き直せること。
- **レッスン・定跡の終了画面（規定）**：終了画面のボタンは「レッスンに戻る」（定跡は「定跡に戻る」。タブ名が定石なら「定石に戻る」）とし、レッスンを終えて元の対局を復元したうえで、来た一覧を同じタブ・カテゴリで開き直してその項目までスクロールする（「対局に戻る」にはしない）。自分の対局のミスから作った復習問題だけは「対局に戻る」のまま。
- **一覧のタブ順**：ルール → レッスン → 定跡 → 詰め（詰将棋・パズル）の順に並べる。ルールは独立したダイアログにせず、このダイアログのタブに置く（ルールボタン・「ルールを見る」からはルールタブで開く）。タブ名は短く（例：将棋も「段級位レッスン」ではなく「レッスン」）。
- **一覧ダイアログの大きさ**：カテゴリのタブを切り替えてもダイアログの大きさが変わらないこと（いちばん大きいカテゴリに合わせて高さを固定）。PCでは横幅を活かして広げる。
- **レッスン・定跡一覧はグラフィック付き（規定）**：手本は五目並べ。見出し＋説明 → カテゴリのタブ（アイコン＋名前＋進捗）→ 選んだカテゴリのヘッダーカード（説明・n/N 合格・進捗バー）→ 項目カードのグリッド（PC 2列・スマホ1列）。各カードの左に**その局面のミニ盤**、右に番号／STEP・状態・名前・要点・説明2〜3行・進捗バー（定跡は評価バッジ）。詰めパズル一覧は `claude/puzzle-collection-spec.md` の「一覧ホーム」（詰めオセロ型）に従う。アイコンは小さくても形が分かるSVGで描く（絵文字・記号文字は小さいと潰れる）。
  - **駒の動きを教える項目は動きのアイコン**：「各駒の動き・取り方・特殊ルール」のような基本の項目は、局面のミニ盤ではなく、小さな盤の中央に駒を大きく描き、動ける方向を矢印・点で示す図にする（手本：チェスの「はじめてのチェス」、`chess/app.js` の `LX_MOVE_ICON` / `lxMoveIcon`）。
- **ミニ盤は注目部分を切り出して拡大（規定）**：大きい盤（将棋9×9・五目並べ15×15）や駒の少ない局面（チェッカーの終盤など）は、一覧カード・サムネイルのミニ盤を注目部分だけ切り出して拡大する。範囲は局面から自動判定（囲い＝玉と金銀の周り、戦法＝初期配置から動いた駒と玉、レッスン＝強調マス・初手と玉の周り、詰め／パズル＝玉と攻め駒・石の範囲＋余白）し、項目ごとに手動上書き（`crop:[c0,r0,c1,r1]`）もできる。正方形〜1マス長い形に整え、盤枠は正方形のまま中央寄せ。盤端まで1マスなら端まで広げる。盤端に接する辺は通常の縁、切れた辺は縁なし＋フェード。**パズルの正解手のマスを範囲決めに使わない**（ヒントになるため）。切り出しても7×7以上になる局面・序盤や定跡など全体の形が大事な局面は全体表示。実装：`shogi/lists-ui.js`（cropFor）、`gomoku/app.js`（thumbCrop）、`checkers/app.js`（cropOf）。8×8のチェスは対象局面が少ないため未適用、小さい盤や盤の構造が大事なゲーム（リバーシ・コネクトフォー・ドット・モリス・マンカラ・バックギャモン）は対象外。
- **定跡カードは軽く**：一覧のカードは名前・手順・狙い1行・稽古ボタンだけにし、由来や詳しい解説は通し稽古（解説）の中で出す（手本：リバーシの定石）。
- **ルール説明はチュートリアル式（規定）**：1ページに詰め込まず、ステップ（ページ）に分けて、各ページで実際に石を置く・駒を動かすなどの課題をやらせる（`shared/ruletour.js` の共通の枠：上にステップ番号、見出し・説明、小さな盤、「👉 課題」、正誤メッセージ、もう一度、前へ／閉じる／次へ、最後のページに「対局してみる／レッスンへ」）。ルールは遊べるようになる最低限まで。戦術・定跡・細則（例：将棋の駒落ち・入玉宣言・千日手の詳細）はレッスンに任せる。手本はドット＆ボックス。
  - **1ページ目はゲーム紹介**：そのゲームの歴史・勝ち方（勝利条件）・文化を紹介する読むだけのページ（`RuleTour.intro`：ポータルのアイコン画像、発祥・人数・1局の目安、📜歴史／🏆勝ち方／🌏文化。PCは3つを横3列）。内容は確実な事実だけ。盤のないページはダイアログの横幅いっぱいを使う。
  - **最後のページ（これで遊べます！）は中央揃え**：見出し・説明・🎉・ボタンを上下左右とも中央に。説明文は最後の文の前で改行する（「…対局してみましょう。」／「上達のコツや作戦は…」）。`shared/ruletour.js` が行う。
  - **正解したら自動で次のページへ**（✓の約1.8秒後。演出があるページは演出が終わってから）。
  - ← → キーで前後のページへ。
  - **スマホはスワイプでページ送り（規定・共通構造）**：ルール説明はすべて、左へスワイプ＝次へ、右へスワイプ＝前へ（アラビア語は逆）。判定は横に56px以上・縦の1.6倍以上・0.9秒以内（指に付いてきたページを幅の30%以上引いた場合は時間に関係なく送る）。**盤（ミニ盤・数独の盤／入力パッド）やボタンの上で始まったスワイプは無視**して、駒の操作・フリック入力を優先する。最後のページで次へスワイプしても閉じない。`shared/ruletour.js` が自動で行う（独自のルール画面を持つゲームは同じ判定を組み込む：ドット＆ボックス `dots/learn.js`、まいにち数独／すぴーど数独 `sudoku/tutorial.js`）。
  - **ページ切り替えはスライド（規定・共通構造）**：ページが替わるときは横にスライドする（前のページが出ていき、次のページが進む側から入る。約0.28秒、アラビア語は左右逆）。スマホのスワイプ中はページが指に付いてきて、離すとそのまま送る／足りなければ元に戻る（送れない側はゴムのように少しだけ動く）。ボタン・←→キー・ステップ番号・正解後の自動送りでも同じスライド。スライド中も上のステップ番号が切れないこと（はみ出し禁止は左右だけ）。`shared/ruletour.js` が行う（ドット＆ボックス・数独は入ってくる側のスライドのみ）。
  - **前へ／閉じる／次へはダイアログの下端に固定**（ページごとに位置が動かない）。ダイアログは固定の高さ、上にステップ番号、その間にページ本文。
  - **ミニ盤の大きさは固定（規定）**：ウィンドウサイズごとに1つの固定サイズとし（`shared/ruletour.js` がダイアログの空き領域から計算）、全ページと正解・不正解の前後で大きさも位置も変えない。PCでは盤の枠をタイトルと上揃えにし、右の列いっぱいに使う（手本：チェス）。部分盤（5×5など）も小さく浮かせず枠を埋めるよう拡大する。正誤メッセージ（2行分）と「もう一度」ボタンの場所は最初から確保しておく。ゲーム側で本文の残りスペースから盤の大きさを決めるCSS／JSを書かない。
  - **スマホは本文をスクロールさせない（規定）**：スマホ縦向き（目安 390×664）で、盤のあるページの本文（見出し＋説明）がスクロールなしで全部見えること。`shared/ruletour.js` v16〜 は全ページで一番長い本文が収まるように盤の大きさを決める（ただし盤は幅の約68%以上を確保。Webフォント読込後に測り直す）。収まらない分は**本文を短くして**対応する：各ページの本文は日本語で2行程度（約30〜90字）、10言語とも同じ内容。細則・補足・例外はレッスンに任せる。タイトルも1行に収まる長さに（独・仏・西語で折り返さないように）。スマホでは見出し17.5px・本文14px（行高1.62）に詰める。スマホで盤の枠を可能な限り大きくしたいゲームは `aspect: 'fill'`（空き全部を盤の枠に）を使い、ボタンなどは盤の上に重ねて場所を予約しない（手本：将棋の成る／成らない、駒一覧は盤の横に2列）。
  - **横長の盤はスマホで左右いっぱい（規定）**：横長の盤（縦横比1.2以上：バックギャモン・マンカラ）は、スマホではダイアログの左右端近くまで広げて、ポイント・穴をタップしやすくする（`shared/ruletour.js` が自動で行う）。
  - **ボタンの大きさは全ページ同じ**：PCでは前へ／閉じる／次へ・最後のページのボタンを幅220pxに統一（`shared/ruletour.js` が行う。ゲーム側のCSSで幅を変えない）。
  - PCでは盤を大きく（最大600px、盤と説明を2列に並べてよい）、文字も大きく（見出し25px・本文16.5px・課題18px）表示し、**1280×720 でもスクロールなしで下のボタンまで見える**こと。盤の端のマスもマス全体がクリックできること。
  - 「図解ルール」という言い方は使わない（「ルール」）。
