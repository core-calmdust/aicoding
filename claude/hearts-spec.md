# ハーツ（Hearts）仕様（hearts/）

- 公開：2026-11-28（ALPHA）。カードゲーム（2Dのみ・3D卓なし）。トップページ `index.html` の GAMES で guandan の直後（`id:'hearts'`、key `ht`、サムネ `images/hearts.webp`、アイコン `images/icons/hearts.svg`）。
- 大百科（`shared/atlas.js`）への登録と 3D 版は今回は作らない（ブリーフどおり後日）。オンラインは未実装（ボタンなし）。
- パズルは作らない（ユーザー了承済み）。

## 出典（ルール・歴史・戦術）
- ルールと変種：pagat.com「Hearts」<https://www.pagat.com/reverse/hearts.html>（標準ルール、パス、最初のトリック、ハートブレイク、Q♠でブレイクする派、ムーンの2方式、Omnibus（J♦ −10）、Black Maria（A♠7・K♠10・Q♠13、右へ3枚、最初の人は何でも出せる）、Spot Hearts）。
- 歴史：Wikipedia「Hearts (card game)」（スペインの Reversis（1750年ごろ）→ 1880年代アメリカ、1909年ごろ Q♠ が加わる Black Lady、1939年 英国で Black Maria と "Hitting the Moon"、1950年 Culbertson の Omnibus）、Wikipedia「Microsoft Hearts」（Windows for Workgroups 3.11〜Windows 7 に付属）。
- 戦術：World of Card Games「Hearts strategy tips」、cardsjd.com「Hearts strategy」（ボイドを作るパス、Q/K/A♠ を渡す・持つ判断、ムーンは1枚でもハートを取って止める、カウンティング）。

## ルール（実装：`engine.js`）
- 52枚を4人に13枚。座席 0=あなた（下）1=左 2=向かい 3=右、時計回り。
- パス：3枚。左→右→向かい→なし の繰り返し（設定で 左右向かいのみ／左だけ／右だけ／なし）。
- 2♣ を持つ人が最初に出す。フォロー必須。最初のトリックにハートと Q♠ は出せない（それしかない時は除く。オプションで許可）。
- ハートは「ブレイク」（誰かがハートを捨てる）まではリードできない（ハートしか持っていない時は除く）。オプション：Q♠ でもブレイク／いつでもリード可。
- 点：ハート1点、Q♠ 13点（合計26）。ムーン（1人で全部取る）：ほかの全員 +26（既定）／自分 −26／有利な方 を選べる。
- 誰かが終了点（既定100）に達したハンドで終わり、最少点の人が勝ち。最少が同点ならもう1ハンド続ける。
- 変種（ルールタブの4枚のカード）
  - スタンダード（上の通り）
  - オムニバス：J♦ を取ると −10点。ムーンの条件は26点分（J♦は不要）。
  - ブラック・マリア：A♠7・K♠10・Q♠13（合計43）。パスは毎回右。ハートはいつでもリード可。ムーンは pagat に記載がないが、既定でオン（設定で変更可）とした。
  - スポット・ハーツ：ハートは数字どおり（2〜10、J11、Q12、K13、A14）、Q♠ 25点（合計129）。終了点は500。
- 設定（ルールタブ）：パス方向・ムーン方式・終了点（50/100/150/200/500）・最初のトリックの点札・Q♠ブレイク・リード制限。

## AI（`ai.js`、Web Worker `worker.js`）
- ヒューリスティック（`heur`）：フォローは「取らない最大」（ダック）、取るしかない時は最大で取る、捨て札は Q♠ → A♠K♠（Q♠未出）→ ハートの高い札 → 短いスートの高い札。リードは安全な低い札・相手のボイドの見込み。
- 情報集合サンプリング（PIMC）：見えていない札を制約（ボイド・自分が渡した札の行き先）つきで配り直し、各候補で最後までロールアウト。終盤（残り3トリック以下）は max-n の厳密探索。目的関数は「自分の失点 − 他3人の平均」。ムーン狙いのロールアウト（自分が全部取れるか）と、相手のムーンの検出・阻止も入れる。
- パス：ヒューリスティック（Q♠/A♠/K♠、高いハート、ボイド作り）＋上位レベルは候補10組をシミュレーションで評価。
- 強さ Lv.1〜20（`LEVELS`）：Lv.1〜8 はヒューリスティックに不注意（ランダム手 55%→5%、ランダムパス 100%→4%）を混ぜる。Lv.9 は純ヒューリスティック。Lv.10〜20 はサンプリング数 10→260（Lv.14 からパスもシミュレーション）、Lv.19〜20 は 1手 2.2〜2.6秒の上限。
- 隣どうしのレベルの強さ（`node hearts/tools/arena.js A B 配り数 seed`。同じ配りを座席を入れ替えて打つ duplicate 方式、A 2人 対 B 2人、1ハンドあたりの平均失点の差。正なら上位が強い）

## 研究機能（poker/ と同じ方針）
- コーチ（右欄、スマホは「コーチ」タブ）：推奨札・理由（取らずに済む／安全に高い札を捨てる／Q♠を持つ人への注意 など、評価値の言い換えではなく理由）・出せる札ごとの失点期待値（70通りの配り直し）・ムーン判定（自分が狙えるか、相手が狙っていそうか、その確率）・考え方のヒント。
- パスの評価：候補の組ごとにシミュレーションで失点期待値を比べる（ヒントと振り返り）。
- カードカウンティング（「カウント」タブ）：スートごとの未出札、各人のボイド、Q♠ の所在の推定。
- 振り返り（`review.js`）：直近30ハンド。全員の手札を開いた卓、1手ずつ進める、自分の各判断に ◎○△✕（期待値差でしきい値 0.35/1.2/3、スポットは4倍）、パスの評価、最後に要約。
- 研究（`study.js`）：パス評価／期待値／ムーン／分布の確率（超幾何で厳密計算）／点の早見。
- 統計：ハンド数・平均失点・ムーン回数・勝率など、変種ごと。GameRecord `hearts`（variant `std`/`omni`/`maria`/`spot`）。
- 用語集：20語。本文中の用語には下線と吹き出し（`#glTip`）。

## 学習
- ルール説明（`rules.js`、RuleTour 紹介＋課題11ページ：目的・パス・2♣・フォロー・トリックの勝ち・ボイド・最初のトリック・ブレイク・点の計算・ムーン・終わり方）＋用語集タブ。
- レッスン 13（5分類：基本 3／守り 3／パス 3／読み 2／ムーン 2、`lessons.js`）。各レッスンは 考え方 → 例題（正解の札を光らせてタップ）→ 練習 → テスト5問（4問で合格）。ヒントは3段階（3段目は不正解扱い）。進み具合は `aicoding-hearts-lessons`。
- 問題は `lessons-gen.js`（DOMなし）が毎回生成し、答えが1つに決まるものだけ出す。終盤問題は全員の最悪応手まで厳密に読む。パスの問題は事前シミュレーションで作った `lesson-pool.js`（1局面あたり500通り以上の配り直しで、正解の組が2位より明確に良いものだけ）。
- 検証：`node hearts/tools/lesson-verify.js 200` が ①答えが1つ ②正解が本当に正しい ③不正解がちゃんと悪い ④ヒントが答えを言わない ⑤文言キーの存在 ⑥14言語 ⑦プールの再シミュレーション、を確認（`selftest` で答えをわざと入れ替えると失敗することも確認）。

## 画面
- シェルは guandan/ と同じ（`app.css` の `pk gd` ＋ `.ht` の上書き）。ヘッダー順：新規＞投了＞ヒント＞ルール＞レッスン＞研究＞振り返り＞統計。
- 卓：クラレット（ワイン色）のフェルトが既定。細かいノイズ＋5px の織り目＋ゆるいムラ（タイルの継ぎ目が出ないよう放射グラデーションで作る）、木の縁。ほか7色。
- カード：solitaire/ の画像（poker/guandan と同じ絵柄）を流用。裏面は「ローズ」が既定ほか15種、絵札3種。
- スマホ（390×844）：卓の下にコーチ｜カウント｜スコア｜ログ｜戦績 のタブ。パスの箱は卓の中央。
- キー：Space 出す／渡す、H ヒント、←→ 札を選ぶ。ウィンドウが非アクティブの間は進行を止める（focusgate）。アニメは reduced motion でも省かない。
