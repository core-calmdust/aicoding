# リバーシAIの強さ：引き継ぎ資料（2026-11-12）

別のアカウントで、根本的な原因を一緒に考えてもらうための資料です。
ユーザーの問題意識：**学習や読みをここまで深めても強さが伸びず、先手（黒）で弱い。根本的なところに何か問題があるのでは。**

関係するファイル：

- `reversi/engine.js`（レベル表 `LEVELS`、定石、think の流れ）

- `reversi/tools/book-gen.js`・`BOOK.md`（定石）

## 1. 今の作り

### 探索
- αβ（PVS）＋置換表＋Multi-ProbCut（MPC）、反復深化。
- 終盤は「勝敗だけの読み（WLD）」と「完全読み」に切り替える。
- C → WebAssembly（SIMD）。複数スレッドは YBW の分割探索（最大14スレッド）。
- 速さ：Mac（M4 Pro）の1スレッドで約 10M 局面/秒（深さ13・中盤）。

### 評価関数（v4、いまサイトで使用）
- パターンの線形評価（Logistello / Edax 系）。
  - 15種類・62インスタンスのパターン。
  - 追加特徴は4つ：自分の着手可能数、相手の着手可能数、両者の潜在的着手可能数。
- フェーズは **2手ごとに30段階**。
- 出力は手番側から見た最終石差の予想。
- 学習データは Egaroucid の公開データ。
  - 局面と評価値の組：約2,550万（教師は Egaroucid Lv.17 の評価値）。
  - 対局棋譜：約5,200万局（Egaroucid 7.8 Lv.11 対 Edax 4.5.5 Lv.11）。教師は最終石差。
  - 合計の学習局面は約3億。
- 検証誤差（RMSE）：中盤で 7〜8石、40手目付近で 6.3石、終盤の数手前で 3〜5石。

### 定石
- v3（サイトで使用）：深さ20で読んだ 44,343 局面。26手目まで。
- 値の戻し方は negamax。
- AI は、最善から 0.8石以内の手の中から無作為に選ぶ。

### レベル
- 28段階。
- Lv.17〜27 は読む深さを固定し、終盤の読み切りを始める空きマス数（exact / wld）も固定。
  - 例：Lv.20 は深さ13・完全読み19マス・勝敗読み21マス。Lv.23 は深さ20・22・24。
- Lv.28 は1手約18秒で、勝敗読みを30マス・完全読みを26マスまで試す。

## 2. 起きていること

1. **Egaroucid（デスクトップ版）に、後手（白）だと6石差くらいで勝てるが、先手（黒）だと勝ちにくい。** Egaroucid は読みが圧倒的に速いのに強い。
2. **同じエンジン・同じ定石どうしの自己対局で、白が勝ちすぎた。**
   - Lv.20・400局で、白の得点率が 67〜68%（平均 +1.8〜2.6石）。
   - 定石 v3 でも v4 でも、評価関数 v4 でも v5 でも同じだった。
   - リバーシは完全な読みでは引き分けなので、本来は 50% 前後になるはず。
3. **評価関数を作り直しても（v5）、強さが変わらなかった。**
   - v5 の変更点：
     - フェーズを1手ごとに60段階にした。
     - パターンを1種類増やした。
     - 石数を特徴に足した。
   - 検証誤差は、全フェーズで 0.13〜0.18石小さくなった（中盤の例：7.84 → 7.68）。
   - それでも、v4 との対戦は深さ10で −14 ± 31、Lv.20 で +24 ± 29、2秒で +24 ± 23（どれも v4 から見た値）。差がないので採用しなかった。

## 3. わかったこと（2026-11-12）

### エンジンは白黒に対して対称
- 自己対局から840局面を取った。
- 石の色と手番を入れ替えた局面と比べると、手・評価値・読んだ局面数・静的評価がすべて一致した。
- 色による不具合はない。偏りは、空きマスの偶奇（＝どちらの手番か）から来ている。

### 原因1：深さを決めた読みは「最後に打った側」が得をする（約1.7石）
- 定石の元データで、ある手の値を次の2通りで比べた。
  - 親の局面の読み（子の局面を深さ19で読む）。
  - 子の局面の読み（深さ20。つまり1手先まで読む）。
- 指した側に、平均で **+1.7石** の差があった。手目4〜26・黒白どちらでも 1.65〜1.75石でほぼ一定。
- 定石の値は、その手順が何手目で終わるかの偶奇で1.7石ずれる。
- 本線はすべて偶数手目で終わる。そのため、白は本線を、黒は脇道を良く見積もり、黒が不利な手を選んでいた。
- **対策**：`book-gen.js build` に手番の補正を入れた（PR #1840）。
- **効果**：定石 v3 の自己対局（Lv.20）で、黒の得点率が 32% → **46%** になった。

### 原因2：定石 v4 では、棋譜（WTHOR）で足した細い手順の値が戻っていた
- 対策：棋譜の局面の値を、定石の評価に使わないようにした（PR #1847）。
- 作業機の浅い読み（深さ9・10）では、黒の得点率が 47〜53% で釣り合った。
- **しかし Mac の Lv.20 では、v4 の自己対局の黒の得点率は 35.5% のまま**。未解決。

### 評価関数が、空きマスの偶奇で片寄っている（重要な疑い）
- 空き6〜18マスの局面で、静的評価と完全読みの差を測った。
  - 空きが偶数のとき：手番側を **+0.6〜+1.5石** 高く見ている。
  - 空きが奇数のとき：手番側を **−0.3〜−1.2石** 低く見ている。
- 自己対局の各局面を深さ12で読むと、評価値が手番ごとに約1.4石上下に振れる。
- 評価に偶奇の補正項を足す試しでは、深さ11の自己対局は変わらなかった。ほぼ一定のずれなので、手の選択はあまり変わらない、という見立て。
- **ただし、学習の作り方そのものに疑いがある（下の4.1）。**

### その他の観察
- 自己対局では、空き20マスの時点で勝敗がほぼ決まっている（147局中144局で、完全読みと最終結果が一致）。
- 定石を抜けたあと（空き約36マス）から空き20マスまでの中盤で、白が平均約2石リードを広げる。
- 終盤の読み切りを始めるマス数が奇数（Lv.20 の 19・21）だと、白が1手早く読み切りに入る。深さ8の試しでは、境を奇数にすると黒の得点率が約5%下がった。
- MPC のσは、v4・v5 ともほぼ同じ：σ ≈ 355 + 2.5×深さ − 3.5×空き（単位は1/100石。空き30マスで約2.6石）。

## 4. 根本の候補（見てほしいところ）

### 4.1 学習で、偶奇の違う局面を同じフェーズに混ぜている
- `rvtrain` は、各フェーズを前後1手の局面も含めて学習している（ログ：`plies 15-15 (+1 each side)`、`--window 1`）。
  - 手数が1つ違う局面は、手番が逆で、空きの偶奇も逆。
  - つまり、1手ごとの60フェーズ（v5）にしても、学習では偶奇の違う局面を混ぜている。
- v4 も、2手ごとのフェーズに前後1手を足しているので同じ。
- これで「評価関数の偶奇の片寄り」と「v5 で強くならなかったこと」の両方が説明できるか？
- 試し方の例：`--window 0` で学習する。または、同じ偶奇の局面だけを混ぜる（±2手）。

### 4.2 教師の質と混ぜ方
- 学習データの約9割は対局棋譜（約2.75億局面）で、教師は**最終石差**。
  - Lv.11 どうしの対局なので、局面ごとの値としては粗い。
  - 中盤の局面の教師が、そのあとの悪手の影響を強く受ける。
- 局面と評価値の組（約2,550万、Egaroucid Lv.17 の評価値）は約1割しかない。
- 両方の重みは同じ（weight 1）。
- 評価値の組を重く見る、深い読みで教師を付け直す（`rvlabel label` がある）などで変わるか？

### 4.3 評価関数の形そのもの
- 線形パターンで、RMSE が中盤 7〜8石。
- Egaroucid は、評価の作り（パターン・特徴・学習量）でもっと誤差が小さいと理解している（細部は未確認）。
- Edax 系の教科書的なパターン（edge+2X、corner 3×3、2×5 など）・特徴量・学習方法と比べて、何が足りないか？

### 4.4 探索の偶奇の扱い
- 反復深化の値は、深さの偶奇で約1.4石振れる。
- MPC の浅い読み（深さの差 ≈ 深さの半分）も、偶奇が混ざる。
  - 例：深さ8の判定に深さ4、深さ9の判定に深さ5。
  - 片寄った値で枝を切っていないか？
- 置換表に入れた、深さの違う値の使い回しで、偶奇のずれを持ち込んでいないか？

### 4.5 終盤の切り替え
- Lv.20 の読み切りの境（19・21）が奇数なのは、白に有利か？
- 境は全レベルで偶数にそろえるべきか？

## 8. 調査結果と次の一手（2026-11-12、引き継ぎ先のアカウント）

数字と表は `reversi/MODEL_CARD.md`「根本原因の調査」。

### 聞かれたことへの答え
1. **偶奇の片寄りは 4.1 で説明できるか。直すと強くなるか。**
   - 説明できる。ランダムな序盤からは白が平均 約2.5石有利で、v4（2手ごとのフェーズ）はそれを表せず、どの手数でも黒に約1.8石甘い。60フェーズで偶奇を混ぜずに学習すると ±0.2石以内になる。
   - ただし強くはならない。片寄りを打ち消した評価と今の評価は、1,400局で ±0.06石の差（深さ8・9）。1回の読みの中では一定のずれなので、手の選択が変わらない。
2. **Egaroucid との差の主因。**
   - 評価の学習ではない。1/12 のデータで学習し直した重みが v4 とほぼ互角（−9 ± 10 Elo）、4倍に増やして +7 Elo。評価は頭打ち。
   - 効くのは読みの深さ（+1手で +83 Elo）、読み切りの広さ（+2マスで +29 Elo）、定石。黒番の弱さは定石（黒がまだ約2石損）と、Lv.20 の読み切りの境が奇数で白が先に入ること（約1〜1.5石）。
3. **定石 v4 が Lv.20 でだけ白に偏る理由。**
   - 定石の自己対局は別々の進行が少なく（1,500局で出口 302）、設定ごとに ±8% ほど揺れる。35.5% はその揺れの範囲で、v4 だけの不具合とは言えない。1つの設定の自己対局では判断できない。
4. **次の一手** → 下。

### 次の一手（Mac、上から順に）
```sh
cd reversi/tools/train && git pull
cc -O3 -pthread -o rvtrain rvtrain.c -lz -lm
cc -O3 -shared -fPIC -DENGINE_ALLOC=malloc -DENGINE_OWN_NOW -o rveng.so ../../engine.c
cc -O3 -o rvmatch rvmatch.c -ldl -lz -lm
./rvmatch openings pairs.bin op10.bin
```
1. **v5 を測り直す（約5分）**：`./rvmatch match op10.bin --wb weights_v5m.bin.gz --n 3000` と `--a 13,19,21` を付けた Lv.20 相当。±5〜10 Elo で出る。差がなければ、評価の学習はここで止める。
2. **黒番の対 Egaroucid を測り直す**：定石の補正（PR #1840）のあと、黒番・白番を別々に。まだ黒が弱ければ定石が原因。
3. **定石を作り直すなら**：奇数手目の局面を1手深く読み、どの局面も読みの末端を同じ手番にそろえる（補正 T が要らなくなる）。`book-gen.js` への実装はまだ。
4. **強さを上げるなら**：読みを速くして同じ時間で深く読む、読み切りを広げる。効果は `rvmatch` の `--a` / `--b` で先に測れる（例：`--a 13,20,22 --b 13,19,21`）。

### 作業機に残していないもの
学習データ（Egaroucid の公開データ。再配布不可）と、試しに学習した重み S・L は残していない。同じものは Mac で `rvtrain train pairs.bin games.bin --tie 1 --window 0 --max-pos 2000000 --iters 150` で作れる。
