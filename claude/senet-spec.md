# セネト（senet/）設計仕様

世界のボドゲ大百科のタイトル。カテゴリ「ヒストリカル」（cat: `hist`）の第2作（第1作はウル、`claude/ur-spec.md`）。台帳の色 `#8c9a2e`。
テーマ：古代エジプトの「通過」のゲーム。ツタンカーメン王墓の黒檀×象牙の箱型盤を、2Dでも3Dでも「その現物で遊ぶ」感覚で。
構造はウル（`ur/`）を手本にしたフォーク。サイコロの代わりに4本の投げ棒。

## 1. ルール（ケンドール式 ＝ 採用）
古代のルールは残っていない。現代の復元のうち最も広く遊ばれるティモシー・ケンドール（1978/79）系を採用。根拠と異説は `senet/tools/RULES-RESEARCH.md`。
- 盤 3行×10列、道は逆S字：1→10（上段 左→右）、11→20（中段 右→左）、21→30（下段 左→右）、31＝盤外（上がり）。
- 駒：`std` 各5枚（既定）／`long` 各7枚（ケンドールの原案）。1〜10（`long` は 1〜14）に交互に並べ、先手が奇数マス。
- 投げ棒4本（片面が白）：白の本数 1〜4 がそのまま進む数、全部黒＝5。確率 1:4/16, 2:6/16, 3:4/16, 4:1/16, 5:1/16。**1・4・5 はもう一度投げる**（パスになっても）。
- 動かせる手があれば必ず動かす。なければパス。
- 自分の駒のマスには止まれない。相手の駒が1枚だけのマスに止まると**入れ替わる**（相手の駒は自分の出発マスへ）。
- 2枚以上並んだ相手の駒は入れ替えられない（ペア）。**3枚以上並ぶと壁**で、越えられない。
- 26「美の家」には必ずちょうど止まる（26を越える手は不可）。26・28・29・30 は安全（入れ替え不可）。
- 26 から：1→27「水の家」に落ちて 15「再生の家」へ戻る（15がふさがっていればその手前の空きマス）／2→28／3→29／4→30／5→上がり。
- 28 は 3、29 は 2、30 は 1 のちょうどで上がり。28・29 の駒は、行き先が空いていれば先のマスへも進める（28→29 は1、28→30 は2、29→30 は1）。（2026-11-07 変更。それまでは上がり以外の動きなし。パズル・レッスンは `tools/recheck_28.js` で再検証し、新しい手で答えが変わる問題は削除＝パズル178問）
- 全部上がった方の勝ち。

## 2. 座標と描画（`senet/board2d.js` → `window.SenetBoard2D`）
- `coords(rule, side, i)` → `[r, c]`：r = floor((i−1)/10)、c = r==1 ? 9−k : k（k=(i−1)%10）。両者同じ道。
- 横（h）：cellXY = ((c−4.5)·100, (r−1)·100)。縦（v）は h を −90° 回したもの：((1−r)·100, (c−4.5)·100)。3D の盤も同じ回転で縦にする。
- 盤の絵は手続き生成のSVG（象牙・黒檀・ファイアンス・パピルス・夜空のフィルタ、マスの聖刻文字：15 アンク、26 ネフェル×3、27 水、28 III、29 II、30 ウジャトの目、各マスに小さな番号）。
- デザイン：盤 `tut`（ツタンカーメン：黒檀×象牙・金縁、既定）／`faience`（青いファイアンス）／`papyrus`（パピルス画）／`night`（夜空・モダン）。駒 `tut`／`faience`／`gold`／`modern`。
- 駒の形：side0＝糸巻き（spool）、side1＝円錐（cone）。2Dの駒と投げ棒は3Dモデル（atlas/models/senet.js、素材のテクスチャ付き）を描いた絵：`senet/sprites.js`（webp の data URL）を `senet/tools/make_sprites.py`（`tools/sprites.html` をヘッドレス Chrome で描画）で作る。3Dの駒・棒を変えたら作り直す。sprites.js がないときだけベクターの絵。投げ棒は帯の中に2本ずつ横に寝かせて大きく見せる。
- 盤の光：マスはぼかしたアルファからの拡散光＋鏡面光（feDiffuse/SpecularLighting）でやわらかい面取り。ファイアンスは細い貫入、`papyrus`（墓の壁画）：盤そのものは普通の彩色した木の盤。周りの縁だけが墓の壁画風（漆喰、手描きの揺れのある帯、剥落とひび）。
- 投げ棒：大きく明るく。2Dの投げる動きは、SVGを一度だけ組み立てて毎フレーム属性だけ動かす（放物線で飛んで回転・裏返り、1回小さく弾んで止まる）。白い面は彩色（帯と菱形）、裏は木目。3D（atlas/models/senet.js）も裏は木目のテクスチャ、断面は少し丸く、長さ方向にわずかに反る。
- 投げ棒：`dice(host,{style})` → `{roll, show, setStyle}`。盤の両脇の帯（stickBox）で投げる。
- PCの配置（2D・3Dスキン共通、2026-11-07）：盤の上下に44pxの余白。投げ棒は帯の左寄せ、出目（「出目 N ↻」）は棒の右横、帯の中央の行に Shippori Mincho（数字はライニング）・金色で置く（棒の下には置かない＝下のボックスに被る）。PCの盤には「上がり N」の文字を出さず、上がった駒を帯に並べるだけ（3Dビューと同じ。数は対局者欄に出る）。投げるボタンは棒の上。手番の案内（#boardTip）は盤の左右中央、手番側の余白に出す。長い言語で投げ棒に届くときだけ右へずらす。案内・棒・出目・ボックスが重ならないことを 1280×720・1440×900・1920×1080 と英語・ドイツ語などの長い言語で計測する。
- `mini(state, opts)`：チュートリアル・カード用の同じ絵。

## 3. エンジン（`senet/engine.js` → `window.SenetEngine`。Node でも require 可）
- API：`RULES, PROB, AGAIN(n), newGame(rule, first), legalMoves(s, n), apply(s, m, n) → {state, again}, rollDice(rng), key, moveText, winProb, evaluate, think(s, n, level, {rng,timeLimit}), hitRisk, raceCount, setNet` ほか。
- AI：expectiminimax ＋ TD(0) 学習の価値ネット（64入力・48隠れ、leaky ReLU。`tools/train_td.js` で15万局、`tools/embed_net.js` で engine.js に埋め込み）。
- レベル1〜20：ランダム手の混ぜ率で強さを作る（L1 100% … L17以上 0%）、深さ 1（L1–12）／2（L13–18）／3（L19–20、L20 は時間を長く）。温度式（softmax）は弱くなったので不採用。深さ4は3より強くならなかった。
- 投了寸前（最善でも勝率 3% 未満、L4以上）は「粘る手」（評価の logit 最大）を選ぶ。
- マルチスレッド（2026-11-08、`shared/mtworkers.js`、ウルと同じ方式）：`splitEval(s, n, depth)` が `evaluate` を「手 × 次の投げ」の仕事に分け、`worker.js` の `'roll'`（`rollTask`、時間の上限 `until` つき）をプールで読み、`combine` で同じ数値に戻す（Node で照合）。使う所：Lv.19・20 の AI の手（3投先、上限 0.7／1.5 秒 = `timeLimitOf`）、ヒント（スレッドがあると3投先、なしは2投先）、振り返り（局面ごと）。最上位の追加はしない（深さ4は3より強くならない・Lv.17〜20 の差は 1段階 約4 Elo）。計測：`senet/bench.html`。
  - ユーザーの Mac（M4 Pro 14コア＝高性能10＋高効率4、Chrome、2026-11-09）の実測（深さ4）：×1.90／×3.24／×4.97／×5.45（2・4・8・14スレッド）。ウルと同じく仕事が1局面 約15 個しかないのが原因（`claude/ur-spec.md`）。2026-11-09：4投先以上は「その投げの手」ごとにも分ける（`E.fineFor`、同じ数値）、Worker は PC の全論理コア（最大16）。見積もり 8 ×5.8 → ×6.8、14 ×8.0 → ×10.5。実際に使う3投先（Lv.19・20・ヒント）は1局面 約3ミリ秒で、分けても速くならないので今まで通り（もともと一瞬）。
  - 見落としの修正（2026-11-09）：`worker.js` の `'roll'` が `until` を `rollTask` に渡しておらず、スレッドで読む Lv.19・20 の時間の上限（0.7／1.5 秒）が効いていなかった（遅い端末で上限を超えうる）。渡すようにした。
  - 2026-11-15 の見直し（C の engine.c の仕事ごとの時間で見積もり、`claude/ur-spec.md` と同じ方法）：深さ4 で1スレッド 1局面 約31 ミリ秒、14スレッド ×11.2（細かく分けない場合 ×9.5）。AI はいちばん上でも深さ3（数ミリ秒）なので、8スレッドを超えた伸びは体感に関係しない。これ以上の改善はしない。
- レート表 `RT_LV`（app.js）は `tools/ladder.js` で L10 相手に測った値から。強さ・探索を変えたら自己対局で確認してから。

## 5. 学ぶ
- ルールツアー `senet/tour.js`（10言語、本物の盤で投げて動かす）：紹介 → 盤と道 → 投げ棒 → 進む → 自分の駒 → 入れ替え → ペア → 壁 → もう一度 → 美の家 → 水の家 → 出口 → パス → 勝ち。
- 紹介の史実（確実なものだけ）：名前は「通過」の意。第1王朝（前3100年頃）の断片、確実な最古の絵はサッカラのヘシラー墓（前2600年頃）、ネフェルタリ墓の壁画、ツタンカーメンの副葬品の盤、『死者の書』第17章。
- レッスン9（`lessons.json`）／パズル178問（`puzzles.json`）：`tools/gen_learn.js` が `tools/learn_themes.js`・`learn_text.js` から生成（テーマ：確率・入れ替え・ペア・逃げる・安全・美の家・水・出口・レース）。

## 6. 3D（ポータル・`?skin=atlas`）
- `atlas/models/senet.js`：ツタンカーメン風の黒檀の箱（金の縁、引き出し、ライオン脚の台とそり）。天板は board2d の絵をテクスチャに（board2d が未読込なら `../senet/board2d.js` を自分で読む）。
- `atlas/skin/senet.js`：全画面スキン（縦向きは盤を −90°）。`window.SenetSkin3D = {sync, animateMove, animateRoll}`。
- `atlas/games/senet.js`＋`senet-kit.js`：ポータルの卓上対局（AI／二人）。斜めから見る向きでは、奥側（相手）の投げ棒と上がった駒を箱から離して置く（箱の陰に隠れないように、`FAR`）。`atlas/rules/senet.js`：3Dルールコース（案内役 セティ）。セティの台詞（`VOICE`・`HELLO`）は全ページ・全14言語で、ちょっとふざけたラクダの口調（コブ・まつげ・泳げない・オアシス待ちなどのボケ）で書く（ルールツアーの文言は代替）。話すときに「ピッ」という声の効果音、課題の行（👆）は黄色の札で目立たせる。
- 手番フォーカス（スマホ縦、2026-11-09、ルドーと同じ考え方）：盤は横置きのまま、寄って盤に沿ってスライドする。2D・フル機能版（`senet/app.js` の Z2：枠を縦に伸ばし盤を横に広げて左右にずらす、3Dスキンは盤要素 `#board` に追従）と卓上対局（`atlas/games/senet.js`：真上から、カメラを左右にパン）。対象は、2D・フル機能版＝投げる前は手番側の駒、投げた後は動かせる駒と行き先、動いている間は出発点と行き先（水の家は戻り先も）。卓上対局は投げる前は投げ棒（相手の番は奥側の投げ棒が上のバーに隠れないよう、視点を奥へ寄せる）。駒を選んだときは速めに寄る。寄り具合はタップしやすい程度に抑える（前後の駒の関係が見えるように：卓上は最小でも約8マス分、2Dは最大1.3倍＝1マス約48px。2026-11-09、それまでは約5マス・1.8倍で寄りすぎだった）。範囲が広いと引く（最大で盤全体）、なめらかに移動。2D・フル機能版は、フォーカス中は枠の高さを最大拡大時の高さで固定し（下の欄が手番ごとに動かない）、盤は最大拡大の大きさで1回だけレイアウトし、寄り・引き・スワイプはすべて盤と3Dキャンバスの CSS transform（縮小方向のみ＝くっきり）で表す。レイアウトし直さないので3Dキャンバス・カメラ・床は変わらない（毎フレームの伸び縮みは重く・ガクガク、止まってからのレイアウトし直しは画面がガクッとなったため。0.36秒の ease-out）。左右のスワイプで盤をずらせる（次のフォーカスまで維持、スワイプ終わりのタップは無視）。盤の右上（卓上は「やめる」の下）のボタンで盤全体と切り替え（`aicoding-senet-zoom`／`atlas-senet-zoom`）。横画面・PC・振り返り・レッスン・パズル・終局は盤全体。

## AIの探索の C 化（2026-11-11、`engine.c`）
- **移したもの**：手の生成（壁・守り・美の家・水の家）・移動、評価ネットとレースの表 `T`（`engine.js` が渡す）、期待値の探索 `V`／`bestAfter`／`wpAfter`（時間を過ぎたら静的評価に戻すのも同じ）。`engine.js` は C があれば `V`・`bestAfter` を C に回す（`evaluate`・`think`・`splitEval`／`rollTask`・`winProb` がそのまま C で読む）。`worker.js` が `engine_simd.wasm`／`engine.wasm` を `WebAssembly.validate` で選び、読めないとき・`?nowasm` は今までの JavaScript。マルチスレッド（`shared/mtworkers.js`）はそのまま。ビルド `tools/build.sh`。
- **一致の確認**（`node tools/cmatch.js`）：2ルール × 20局面、深さ3（Lv.19・20）の全部の手の勝率・`winProb`・`rollTask` が JavaScript と差 **1.1e-16 以下**、**最善手 40/40 一致**、SIMD 版となし版はビット単位で同じ。
- **速さ**（作業機）：深さ3の1局面 JavaScript 43.0 → C 15.0 ミリ秒（**×2.9**）。
- **強さ（レベルは変えていない）**：Lv.20 を深さ4にした版と今の Lv.20（深さ3）を対局（C、同じ投げで先後入れ替え、各ルール100組＝200局）：標準 97-103（48.5%）、ロング 95-105（47.5%）。前の記録（深さ4は3より強くならない）と同じく差がないので、Lv.19・20 は深さ3のまま、`RT_LV` もそのまま。
- headless Chrome（作業機）：対局ページ（PC・スマホ幅）の Worker・大百科の Worker が `wasm-simd`、Lv.20 の手とスレッドの仕事が返る。ページのエラーなし。
