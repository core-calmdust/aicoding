# Model Card: Hnefatafl AI (`engine.c` → `engine.wasm`)

ネファタフル（Hnefatafl）のAIは、C で書いた探索エンジン `engine.c` を WebAssembly にしたもの（約39KB、ブラウザの Web Worker で実行）。
コペンハーゲン・ルールでは、自己対局から学習した評価関数（ネット、2026-11 追加、下記）で指す。ほかのルール（フェトラー・トールブリド・タブルット・ブランドゥブ・アード・リー）と 15級相当の下位レベル（Lv.1〜7）は、手作りの形勢評価（18項目、自己対局で調整）を使う。

- **ゲーム**: https://core-calmdust.github.io/aicoding/tafl/
- **バージョン**: v1（2026-10-25）
- **ルール**: コペンハーゲン 11×11（メイン）、フェトラー 11×11、トールブリド 11×11、タブルット 9×9、ブランドゥブ 7×7、アード・リー 7×7（2026-11-06 に3つ追加）。ルールは `engine.c` と `engine.js` に同じものを実装し、
  ランダム対局で両者の合法手・取り・勝敗が一致することを確認（`tools/wasmtest.js`、不一致0）。個別の規則は `tools/ruletest.js`。
  王は武器を持つ（はさみに加われる）、王は4方向（玉座のとなりは3方向＋玉座）で捕獲、端の王は捕獲されない、シールドウォール、
  エッジフォート（崩せないことを保守的に判定）、全包囲、同一局面3回で守り手の負け、取りのない200手で引き分け。
  ルールの違いは `engine.c` の `Rules`（盤の大きさ・端で脱出・王は4方向・シールドウォール・砦・包囲）の組み合わせだけで表す。

|---|---|---|---|---|---|
| コペンハーゲン | 11×11 | 24 / 12＋王 | 四隅 | 4方向（端では捕まらない） | あり |

### 探索 v2（2026-11-07）：1スレッドの効率化
コペンハーゲンは1局面に合法手が約100あり、深さを1つ増やすのに数倍の時間がかかる（1手0.3秒では2スレッドにしても次の深さに届かなかった）。
そこで並列化の前に、同じ時間で深く読めるように探索そのものを見直した（`engine.c` の `search()`、切り替えは `SP[]`／`set_sp`）。

| 追加・変更 | 内容 |
|---|---|
| 置換表を先に | 合法手の生成の前に置換表を引き、打ち切れるときは生成しない |
| LMR（対数式） | 減らす深さ = ⌊ln(深さ)·ln(手の順番)/2.25⌋（PV と脅しの下では1少なく）。旧版は1〜2手だけ |
| 逆フューティリティ | 深さ3以下で、静的評価 − 150×深さ ≥ β ならその値で打ち切る |
| ヌルムーブ | 深さ3以上で静的評価 ≥ β のとき、パスして深さ −(4+深さ/4) で読み、まだ β 以上なら打ち切る（連続パスなし、駒が3つ以上） |
| フューティリティ | 深さ2以下で 静的評価 + 200×深さ ≤ α なら静かな手を読まない |
| 遅い手の枝刈り（LMP） | 深さ3以下で、並べた順の 10×(2+深さ²)/2 番目より後の静かな手を読まない |
| 使わない場面 | PV ノード、王に脱出路がある（攻め手番）、王が次に捕獲される（守り手番）、勝ち負けの値の近く。攻め手番で王が1手で脱出路のあるマスへ行けるときは逆フューティリティも使わない |
| 手の並べ方 | 「静かな手」= 置換表の手・取り・キラー・王の脱出がらみ・王のとなりへの攻め手の手 **以外**。王の道をふさいでいる守り手の駒（王から見て最初の駒）を動かす手も静かな手から外した（脱出路を開く手） |
| その他 | 評価関数の `kingCapNow` 前の局面コピーをなくした（結果は同じ）。`-DNATIVE` のビルドで `TLS` が未定義だったのを修正 |

マージンはネット（1ロジット=1000）ではそのまま、手作り評価（攻め手1枚=100）では半分にして使う（`SP_HUNIT`=50：そのままだとフェトラーで −9、半分で +89）。

- 同じ局面数（1手10万局面、40局）：新 +34 =5 −1（+407 Elo）。平均の深さ 4.7 → 7.0
- 同じ時間（1手0.1秒、40局）：+33 =1 −6（+285 Elo）

### レベルも探索 v2 に（2026-11-08）：同じ強さで速く
局面数で区切るレベル（Lv.8〜18）を新しい探索にし、旧版と同じ強さになる局面数に減らした（`engine.c` の `NN_NODES`・`LEVELS`・`VAR_NODES`、単位は100局面）。

## 形勢評価（18項目）
駒の数（攻め手・守り手）、王の動ける範囲、2手で脱出できる筋の数、王のとなりの攻め手／守り手、隅の前を固める攻め手、王から隅までの距離、
隅への道をふさぐ攻め手、王の危険度、攻め手の連結、端の守り手、手番、序盤の偏り補正、隅の危険・隅の守り。
重みはルールごとに SPSA（同時摂動による確率的勾配法）で自己対局から調整した（`tools/native.c tune`）。

| ルール | 調整 | 調整前の重みとの対戦 |
|---|---|---|
| コペンハーゲン | 410回 × 4局（1手4千局面） | 100局（1手1万5千局面）で 約+70 Elo |
| ブランドゥブ | 480回 | 300局で +9 Elo（ほぼ同等） |
| タブルット | 300回 × 6局（1手6千局面） | 200局で 約+131 Elo |
| フェトラー | コペンハーゲンの重みをそのまま使用（盤・四隅・王の捕獲が同じ） | — |
| トールブリド | タブルットの重みを使用。250回 × 6局の調整を試したが差なし（200局で −3 Elo）のため不採用 | — |
| アード・リー | ブランドゥブの重みを使用。160回 × 6局の調整は +38 Elo（200局、誤差±50）だったが、初期局面の評価値が深さで大きく揺れたため不採用 | — |

新しい3ルールの攻守バランス（Lv.8 同士・両手番、序盤ランダム4手）：フェトラー 攻め手80%（コペンハーゲンも同じ80%）、
トールブリド 攻め手90%（1手6千局面同士では56%）、アード・リー 攻め手46〜48%。強さの段階は他のルールと同じ（Lv.5 は Lv.12 に24局で0〜1勝）。
評価値の表示の基準（`D0`）は、トールブリド・フェトラーは初期局面の静的評価、アード・リーは初期局面の探索値（初期配置で駒が接していて静的評価が当てにならないため）。

## 学習した評価関数（コペンハーゲン、2026-11）
| 項目 | 内容 |
|---|---|
| 形 | 入力：攻め手・守り手・王の3面 × 121マス（363）→ 隠れ層256（clamp(x,0,1)²）→ 手番ごとの出力。手作り評価の16項目（脱出路の数など読みに近い量）も出力層に直接入れる。値は守り手から見た期待得点のロジット（×1000 で探索の評価値）。ファイル `nnue-copenhagen.bin.gz`（約340KB） |

| データ | 強化学習の8周（1周目は手作り評価、以降は前の周のネットで自己対局、1手1万局面、4分の1の対局は守り手の読みを2千局面にして攻め手の勝ちを増やす）、計 約2,500万局面。8周目のネットは直近4周分（約1,060万局面）と初期データで学習 |
| 伸び | 手作り評価との役割別比較（攻め手2万・守り手2千局面、`nrole`）：1周目 攻め手 −545 / 守り手 +293 → 8周目 攻め手 +1130 / 守り手 +545（上限付近）。ネット同士：8周目は6周目に +58、4周目に +156 |
| 速さ | 1層目は差分更新（1手で動いた駒の分だけ足し引き、探索の手数ごとに遅延計算）、出力層は SIMD。ブラウザで30万局面 約0.37秒（差分更新前の約1.9倍、手作り評価とほぼ同じ）。包囲判定は「取りがあったか、動いた攻め手のまわり8マスに攻め手が2つ以上」のときだけ行う（結果は同じ）。高速化の前後で自己対局の棋譜が完全に一致することを確認 |

## 攻め手と守り手の差（非対称なゲーム）
ネファタフルは攻め手24枚・守り手12枚＋王の非対称なゲームで、どちらが有利かは腕前で変わる。
- **弱いレベル**：1手読みの攻め手は王の道をふさげないので、何もしないと守り手がほぼ必ず勝つ（調整前の15級〜13級では守り手の勝率85〜98%）。
  そこで弱いレベルは攻守で設定を変える：攻め手を持つAIは必ず2手読み（相手の脱出の脅しが見える）、守り手を持つAIは「1手で脱出」をときどき見逃す。
  調整後は15級〜13級の攻め手の勝率 32〜57%（上の表の2-3、3-4でほぼ互角）。
- **中位〜上位**：エンジン同士では守り手がかなり有利（同じ強さで 約+300〜450 Elo、攻め手の勝ちは1割以下）。コペンハーゲン・ルールは
  人間の熟練者どうしでは守り手がやや有利と言われるが、エンジンの読みの範囲では包囲の長期計画が届かず、差がさらに大きく出ている。
- **レーティング戦**：期待勝率に、守り手を持った側の得 `RT_SIDE_LV`（レベルごと：15級〜12級 +30、11級〜7級 +70、6級 +200、5級から上 +350）を入れる。

## パズルとレッスン
- パズル 390問はすべてエンジンの厳密解（`tools/native.c pzgen` の `classify`：N手以内に必ず脱出／王を捕獲でき、初手がただ1つ）。
  `tools/check_puzzles.js` で JS のルールと WASM の解答を全問再検証（不正解0）。
- レッスンの問題は、ルール系はランダムに作った局面の合法手を全部調べて正解を決め、作戦系（隅の守り・王の道・包囲）は自己対局の局面を
  エンジンの評価（1.5秒）で採点する。作戦（定跡）の手順はエンジンの解析で確かめた互角の手順。

## 限界
- 学習データや人間の棋譜は使っていない。評価は手作りで、深い戦略（長期の包囲計画など）はエンジンの読みの範囲に限られる。
- エッジフォートの判定は保守的（崩せる可能性が少しでもある形は砦と認めない）。人間なら砦と見なす形を見逃すことがある。
- 上位レベルは対局数が少なく、強さの差には誤差がある。四段・五段と Lv.21〜25 は時間で区切るので端末の速さ（とコア数）に左右される。

## 対局設定の Pro モード（2026-11-08）
対局設定の「AIの強さ」の PRO ボタン（`shared/proset.js`、addendum「対局設定の Pro モード」）。項目：思考の制限（時間 0.1〜30 秒／深さ 1〜30／局面数 1千〜5千万）、スレッド数（時間制限のとき、マルチスレッドがオンのとき）。レベルの中身は engine.c にあるので、PRO のときは `WX.best(深さ, 時間, 千局面)` で読む（評価関数はそのルールの既定）。表示する既定値はページの `PRO_TN`（engine.c NN_NODES の写し）。レート戦では使わない。戦績のキーは `ai:pro…`、相手名に「PRO」。
- 先読み（2026-11-11、既定オフ、`shared/ponder.js`）：AI が指した直後から人の手番中もスレッドのプールで読む。読み筋を返さない（engine.c は触らない）ので人の局面そのものを読み、置換表を温める（どの応手でも効く）。AI 自身の手も同じプール（置換表）で読む。着手・待った・新規対局・終局・タブ非表示で即停止。

## 最上位レベル Lv.21〜25（2026-11-08）
五段（Lv.20、1手2.5秒）の上に、時間で考える5段階を追加（`engine.c` の `LEVELS[21..25]`、レベル名は他と同じ「Lv.N」）。

| レベル | 1手の時間（上限） | レーティング戦の基準値 `RT_LV` | 守り手の得 `RT_SIDE_LV` |
|---|---|---|---|
| Lv.20（参考） | 2.5秒 | 2650 | 350 |
| Lv.21 | 4秒 | 2695 | 350 |
| Lv.22 | 6秒 | 2735 | 350 |
| Lv.23 | 9秒 | 2765 | 350 |
| Lv.24 | 13.5秒 | 2795 | 350 |
| Lv.25 | 20秒 | 2825 | 350 |

- 時間は上限（探索は「上限の45%を過ぎたら次の深さに入らない」ので、平均はその半分程度）。対局ページでは本編のマルチスレッドで全スレッドを使う（Lv.19 以上、レート戦も）。スレッドがないときは1スレッド。
- PRO モードの既定値（ページの `PRO_TS`）も同じ秒数。既存の Lv.1〜20 の設定・保存済みのレベル・基準値は変更なし。

### 強さの推定（方法と結果）
1手数秒〜20秒の対局を数十局こなすのはこの作業環境（2コアを他の作業と共用）では無理なので、**局面数で区切った短い対局**（端末の速さによらない）で「読む量を2倍にしたときの差」を測り、時間比から外挿した。ブラウザは約0.75k局面/ms（`NODES_FOR_MS` の換算）なので、Lv.20 ≈ 190万局面、Lv.25 ≈ 1,500万局面に当たる。
- 計測：`tools/native.c match`（`NETBOTH=1` で両者とも学習した評価関数、`NNLV` で Lv.19・20 の局面数を指定）、コペンハーゲン、序盤3手ランダム、同じ序盤で攻守を入れ替え。
  - 20万局面 対 10万局面：40局、攻め手で +11 −9、守り手で +16 =1 −3、得点 0.688（**+137 Elo**、誤差 ±100 程度）
  - 40万局面 対 20万局面も始めたが、高負荷で1局が長く（1組に15分以上）、時間内に結果が出なかったため未計測。
- 2倍あたりの伸びは読む量が増えるほど小さくなる見込み（チェス等の経験則）なので、Lv.20〜25 の範囲では **2倍あたり約 +80 Elo** と見て、1段階（時間 1.5〜1.6倍＝0.58〜0.68倍分の2倍）あたり **約 +45〜55 Elo**、Lv.25 は Lv.20 より **約 +240 Elo**（誤差は大きく、+120〜+350 程度）と推定した。目標の「1段階 +100〜150」には、1手20秒の上限の中では届かない（時間比 1.5 倍では足りない）。
- レーティング戦の基準値はこれを 0.75 倍（既存の換算と同じ）して Lv.20 の 2650 に足した。
- 確認（headless Chromium、2コアの共用機・高負荷、主＋補助1スレッド、初期局面）：Lv.21 3.6秒（深さ6）、Lv.25 11.5秒（深さ8）、どちらも2スレッドで読んだ。
