# Model Card: Hnefatafl AI (`engine.c` → `engine.wasm`)

ネファタフル（Hnefatafl）のAIは、C で書いた探索エンジン `engine.c` を WebAssembly にしたもの（約39KB、ブラウザの Web Worker で実行）。
学習済みのネットや外部データは使わず、手作りの形勢評価（18項目）の重みを自己対局で調整している。

- **ゲーム**: https://core-calmdust.github.io/aicoding/tafl/
- **バージョン**: v1（2026-10-25）
- **ルール**: コペンハーゲン 11×11（メイン）、ブランドゥブ 7×7、タブルット 9×9。ルールは `engine.c` と `engine.js` に同じものを実装し、
  ランダム対局で両者の合法手・取り・勝敗が一致することを確認（`tools/wasmtest.js`、不一致0）。個別の規則は `tools/ruletest.js`。
  王は武器を持つ（はさみに加われる）、王は4方向（玉座のとなりは3方向＋玉座）で捕獲、端の王は捕獲されない、シールドウォール、
  エッジフォート（崩せないことを保守的に判定）、全包囲、同一局面3回で守り手の負け、取りのない200手で引き分け。

## 探索
| 項目 | 内容 |
|---|---|
| 盤 | 13×13 のメールボックス（番兵つき）、コピーメイク、Zobrist ハッシュ |
| 探索 | ネガマックス PVS、置換表、キラー手・ヒストリー、LMR、アスピレーション窓、反復深化 |
| 戦術の地平 | 末端で「王の脱出路（1手で隅へ）」「王の即捕獲」を厳密に解決。王が2本の脱出路を同時に作れる局面（tuichi）は2手勝ちとして扱う。静止探索は脱出路をふさぐ手だけを読む |
| 千日手 | 探索中の繰り返しは攻め手のわずかな得（+40）として扱う（3回目は守り手の負けというルールに合わせつつ、攻め手が繰り返しを狙いすぎないように） |
| 速さ | ブラウザで毎秒 約40万局面（端末による） |

## 形勢評価（18項目）
駒の数（攻め手・守り手）、王の動ける範囲、2手で脱出できる筋の数、王のとなりの攻め手／守り手、隅の前を固める攻め手、王から隅までの距離、
隅への道をふさぐ攻め手、王の危険度、攻め手の連結、端の守り手、手番、序盤の偏り補正、隅の危険・隅の守り。
重みはルールごとに SPSA（同時摂動による確率的勾配法）で自己対局から調整した（`tools/native.c tune`）。

| ルール | 調整 | 調整前の重みとの対戦 |
|---|---|---|
| コペンハーゲン | 410回 × 4局（1手4千局面） | 100局（1手1万5千局面）で 約+70 Elo |
| ブランドゥブ | 480回 | 300局で +9 Elo（ほぼ同等） |
| タブルット | 300回 × 6局（1手6千局面） | 200局で 約+131 Elo |

## AIの強さ（20段階）
| レベル | 設定 |
|---|---|
| 15級〜9級（1〜7） | 全部の手を固定の深さ（1〜2手）で評価し、ノイズ（±320〜85）を加えて選ぶ。一定の確率（30%〜4%）で悪手、70%〜6%の確率で戦術の地平なし（脱出路の先読みをしない）。守り手を持ったときは50%〜3%の確率で「1手で脱出」を見逃す。攻め手を持ったときは必ず2手読み、地平なしの確率は1/3（下の非対称の項） |
| 8級〜1級（8〜15） | 通常の探索・1手あたり 2千 / 3千 / 4千 / 8千 / 1万5千 / 3万 / 6万 / 12万 局面まで。評価に小さなノイズ（±60〜6） |
| 初段〜三段（16〜18） | 1手あたり 25万 / 50万 / 100万 局面まで（最大3秒） |
| 四段・五段（19・20） | 1手 1.2秒 / 2.5秒 |

## 攻め手と守り手の差（非対称なゲーム）
ネファタフルは攻め手24枚・守り手12枚＋王の非対称なゲームで、どちらが有利かは腕前で変わる。
- **弱いレベル**：1手読みの攻め手は王の道をふさげないので、何もしないと守り手がほぼ必ず勝つ（調整前の15級〜13級では守り手の勝率85〜98%）。
  そこで弱いレベルは攻守で設定を変える：攻め手を持つAIは必ず2手読み（相手の脱出の脅しが見える）、守り手を持つAIは「1手で脱出」をときどき見逃す。
  調整後は15級〜13級の攻め手の勝率 32〜57%（上の表の2-3、3-4でほぼ互角）。
- **中位〜上位**：エンジン同士では守り手がかなり有利（同じ強さで 約+300〜450 Elo、攻め手の勝ちは1割以下）。コペンハーゲン・ルールは
  人間の熟練者どうしでは守り手がやや有利と言われるが、エンジンの読みの範囲では包囲の長期計画が届かず、差がさらに大きく出ている。
- **レーティング戦**：期待勝率に、守り手を持った側の得 `RT_SIDE_LV`（レベルごと：15級〜12級 +30、11級〜7級 +70、6級 +200、5級から上 +350）を入れる。
  守り手で勝っても上がりにくく、攻め手で勝つと大きく上がる。
- 対局の初期設定は「あなた＝守り手」。

## パズルとレッスン
- パズル 390問はすべてエンジンの厳密解（`tools/native.c pzgen` の `classify`：N手以内に必ず脱出／王を捕獲でき、初手がただ1つ）。
  `tools/check_puzzles.js` で JS のルールと WASM の解答を全問再検証（不正解0）。
- レッスンの問題は、ルール系はランダムに作った局面の合法手を全部調べて正解を決め、作戦系（隅の守り・王の道・包囲）は自己対局の局面を
  エンジンの評価（1.5秒）で採点する。作戦（定跡）の手順はエンジンの解析で確かめた互角の手順。

## 限界
- 学習データや人間の棋譜は使っていない。評価は手作りで、深い戦略（長期の包囲計画など）はエンジンの読みの範囲に限られる。
- エッジフォートの判定は保守的（崩せる可能性が少しでもある形は砦と認めない）。人間なら砦と見なす形を見逃すことがある。
- 上位レベルは対局数が少なく、強さの差には誤差がある。四段・五段は時間で区切るので端末の速さに左右される。
