# ラトルンクロルム NNUE 学習ツール（Mac）

ラトルンクロルム（latrunculi/）のAIの評価関数を、学習した小さなネット（NNUE）にするための一式です。
**先生はこのサイトのエンジン自身**（core.c の探索と手作りの評価）で、外部のエンジンやデータは使いません（サイトのコンセプト「自力で作る」）。
自己対局でデータを作り → 学習し → 確認して → 採用できるファイルを作るところまで、コマンド1つで進みます。

## 使い方

```bash
cd ~/Documents/GitHub/aicoding
bash latrunculi/tools/nnue/run.sh
```

自動で次の順に進みます（**途中で止めても（Ctrl-C）、もう一度同じコマンドで続きから**）。

1. ツールのビルド（`ltn`＝エンジンの C をそのまま Mac 用に、`train`＝学習器）
2. 自己対局で学習データ作り（既定：3つのルール合わせて **約2,000万局面**、全コア）。最初の数手はランダムに置く／動かすので毎局ちがう対局になり、そのあとは両者が1手1万2千局面ずつ読んで指します。20局ずつのまとまりで保存されます
3. 学習（ルールごとに1つのネット、12周）
4. 確認：差分更新の一致検査（`nncheck`：1手ごとに更新した中間層と、作り直した中間層が一致するか）と、今の手作り評価との対局（局面数を同じにして200局、1手0.1秒で200局）
5. 両方の対局で **55% 以上**勝ち越したネットを `~/latrunculi-nnue-work/adopt/lt-<ルール>-<日付>-r<周>.nnue` に書き出して完了

必要なもの：Xcode Command Line Tools（`xcode-select --install`）。追加のライブラリは不要です（学習器も C）。

## 時間の目安（Mac mini、全コア）

- 自己対局がほとんどの時間を占めます。進み具合は `pos/s`（1秒あたりの局面数）と「あと何分」で表示されます。
- 作業機（共用の遅い2コア）での実測は、1手8千局面で1コアあたり約360局面/秒（CPU 時間）。Mac mini（M4 Pro）はコアが速く数も多いので、既定（1手1万2千局面）で**全体で毎秒3,000〜6,000局面 → 2,000万局面で1〜2時間**が目安です（最初の数分の表示で見積もってください。2周目はネットを使う先生なので2〜3割遅くなります）。
- 学習はルールごとに 10〜20分ほど、確認の対局（400局×3ルール）は合わせて 30〜60分ほど。
- 長すぎるときは止めて `POSITIONS` を減らして再実行すれば、それまでのデータで学習以降に進みます。

## 設定（任意）

```bash
POSITIONS=10000000 NODES=8 bash latrunculi/tools/nnue/run.sh
DATA="/Volumes/Orico A 8TB/latrunculi-nnue-data" bash latrunculi/tools/nnue/run.sh   # 大きなデータを外付けに
ROUNDS=2 bash latrunculi/tools/nnue/run.sh                                         # 周回：できたネットを先生にして2周目
RULES=seneca bash latrunculi/tools/nnue/run.sh                                     # シェードラー式だけ
```

| 変数 | 既定 | 内容 |
|---|---|---|
| `WORK` | `~/latrunculi-nnue-work` | 作業フォルダ（ネット・記録・採用ファイル） |
| `DATA` | `$WORK` | 自己対局データの置き場（1局面48バイト：2,000万局面で約1GB／周） |
| `RULES` | `seneca piso quintana` | 学習するルール（ルールごとに別のネット） |
| `POSITIONS` | 20000000 | 1周で作る局面数（全ルールの合計。増やして再実行すると追加で作る） |
| `NODES` | 12 | 先生が1手に読む局面数（千）。多いほど教師が正確で、時間がかかる |
| `ROUNDS` | 1 | 周回数。2周目以降は前の周で**採用された**ネットを先生にしてデータを作り、そのネットから学習を始める |
| `JOBS` | 全コア | 自己対局のプロセス数 |
| `HIDDEN` | 128 | 中間層の大きさ（8の倍数、256まで） |
| `EPOCHS` | 12 | 学習の周回数 |
| `LAMBDA` | 0.7 | 教師値の配分（先生の評価の勝率換算 × λ ＋ 実際の勝敗 × (1−λ)） |
| `SCALE` | 0 | 評価値と勝率の換算（0＝データの勝敗に合わせて自動） |
| `MATCH_GAMES` `MATCH_NODES` `MATCH_MS` | 200, 20, 100 | 確認の対局：局数、1手の局面数（千）、1手のミリ秒 |
| `ADOPT` | 55 | 採用の基準（両方の対局での得点率 %） |
| `EXTRA` | なし | 学習器への追加オプション（例 `EXTRA="--lr 0.0005"`） |

## 終わったら

`~/latrunculi-nnue-work/adopt/` にできた `.nnue` ファイルと `~/latrunculi-nnue-work/run.log` を Claude に渡してください。
エンジン側（`latrunculi/engine.js` の `NETS`）は**ファイル名が空の間は今の手作り評価のまま**です。ファイルを `latrunculi/nets/` に置いて `NETS.<ルール>` にファイル名を書くだけで、そのルールの評価がネットに切り替わります（WebAssembly でも JavaScript の予備でも同じ値）。切り替えたらレベル表（`app.js` の `RT_LV`・大百科の `RATING`）を対局で測り直します。

## ファイル

| ファイル | 内容 |
|---|---|
| `run.sh` | 全部まとめて実行（再開・周回・採用ファイルの生成） |
| `ltn.c` | エンジン（`../../core.c`）を Mac 用にビルドした道具：`datagen`（自己対局データ）・`nncheck`（差分更新の一致と値の分布）・`nmatch`（ネット対 手作り評価）・`smatch`（探索の設定どうしの対局）・`bench` |
| `train.c` | 学習器（(366→H)×2視点→1、SCReLU、Adam。左右反転でデータを2倍に使う。xiangqi/tools/nnue/train.c がもと） |
| `rec.h` | 記録の形式（1局面48バイト）と入力特徴 |

## ネットの形

- 入力（各手番の側から見て366）：64マス×4状態（自分の動ける駒・自分の裏返った駒・相手の動ける駒・相手の裏返った駒。白の視点は上下反転）、自分の手持ち 0〜24、相手の手持ち、自分の取った数 0〜24、相手の取った数、取り合いなしの手数÷6（0〜9）。
- 中間層 H（既定128）を手番側・相手側の2つ → 0〜127 に切って2乗（SCReLU）→ 出力1（勝率のロジット × SCALE ＝ エンジンの評価値。100 ≒ 駒1個）。
- 量子化：W1・B1 は ×127 の int16、W2 は ×64 の int16。エンジン（core.c）は中間層を手ごとに差分で更新し（WebAssembly SIMD）、JavaScript の予備は毎回作り直して同じ整数を計算します。
- ファイル形式：`"LTN1"`, H, 入力数(366), SCALE（int32 ×3）, W1, B1, W2（int16）, B2（int32）。
