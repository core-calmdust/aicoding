# アマゾンズ 学習した評価の道具（Mac）

アマゾンズAIの評価関数を、自己対局で学習した小さなネットワークにするための一式です。
先生は**サイトのアマゾンズAI自身**（MCTS＋評価 v3）です。外部のエンジンは使いません。
自己対局の各局面について「探索した値」と「その対局の勝敗」を記録し、読まなくても同じ判断ができるように学習させます。
ネットの形・入力は `amazons/MODEL_CARD.md`「学習した評価」を見てください。

## 使い方

```bash
cd ~/Documents/GitHub/aicoding
bash amazons/tools/nnue/run.sh
```

データを外付けディスクに置くとき（パスに空白があっても大丈夫）:

```bash
WORK="/Volumes/Orico A 8TB/amazons-nnue" bash amazons/tools/nnue/run.sh
```

自動で次の順に進みます。途中で止めても（Ctrl+C）、もう一度同じコマンドを実行すれば続きから進みます。

1. ツールのビルド（`nn`＝自己対局・学習・確認、`match`＝対局）
2. 自己対局で学習データ作り（既定 約2000万局面。全コアを使用）。コア数×25局ごとに保存
3. 学習（8エポック。2%の局面は学習に使わず確認用）
4. 確認：今の評価（v3）との対局。① 1手の評価数をそろえて（3万評価）400局 ② 1手の CPU 時間をそろえて（0.1秒）400局
5. **採用の基準**（②で 52% 以上、かつ①で 50% 以上）を満たしたら `作業フォルダ/adopt/net.js` ができて完了

必要なもの: Xcode Command Line Tools（`xcode-select --install`）、空き容量 1GB ほど（2000万局面で 640MB）。

## 時間の目安（Mac mini M4 Pro、14コア）

| 段階 | 目安 |
|---|---|
| 自己対局 2000万局面（1手2万評価） | 3〜6時間（進み具合と残り時間を表示します） |
| 学習 8エポック | 10〜30分 |
| 確認の対局（400局×2） | 10〜20分 |

見積もりの元：作業機（ほかの作業と共用の2コア）では1手5千評価で毎秒約70局面。M4 Pro の性能コアは評価が毎秒300万前後と見込み、1手2万評価で1コア毎秒約150局面 × 10コア＋効率コア。実際の速さは自己対局の途中に表示します。CPU を空けたいときは `JOBS=8` のようにコア数を絞れます。

## 設定（任意）

```bash
POS=10000000 NK=30 JOBS=10 bash amazons/tools/nnue/run.sh
```

| 変数 | 既定 | 内容 |
|---|---|---|
| `WORK` | `~/amazons-nnue-work` | 作業フォルダ（データ・ネット・ログ） |
| `POS` | 20000000 | 1周の自己対局の局面数（増やして再実行すると追加で作る） |
| `NK` | 20 | 先生が1手に評価する局面数（千単位。多いほど教師が正確で、時間がかかる） |
| `JOBS` | 全コア | 同時に動かす数（自己対局・学習・対局） |
| `EPOCHS` | 8 | 学習の周回数 |
| `LAMBDA` | 0.5 | 教師値の配分（探索の値 × λ ＋ 実際の勝敗 × (1−λ)） |
| `ROUNDS` | 1 | 周回数。2以上にすると、2周目からは前の周で採用されたネットを先生にして自己対局し、前のネットから学習を続けます |
| `PAIRS` | 200 | 確認の対局の組（1組＝先後を入れ替えた2局） |
| `MS` | 100 | 時間をそろえた対局の1手の CPU 時間（ミリ秒） |
| `NET` | なし | 1周目の先生に使うネット（例：前回の `adopt/net.bin`） |
| `FORCE` | 0 | 1 にすると基準を満たさなくても `net.js` を書き出す（試すとき用。採用はしない） |

周回の例（2周）:

```bash
ROUNDS=2 WORK="/Volumes/Orico A 8TB/amazons-nnue" bash amazons/tools/nnue/run.sh
```

## 終わったら

`作業フォルダ/adopt/net.js` ができていたら、それを `amazons/net.js` に置き換えるだけでAIが学習した評価に切り替わります
（`amazons/engine.js` が `net.js` を読み、空でなければ MCTS のレベル（Lv.16 以上・レート戦・PRO の MCTS）の評価になります）。
置き換えたら `amazons/engine.js` の `importScripts('net.js?v=N')` の N を1つ上げてください（ブラウザのキャッシュ）。

Claude に頼む場合は、`adopt/net.js`・`adopt/check.log`・`r*/train.log` の最後の数行を渡してください。
レベル表（特に評価数で決める Lv.16〜18 と時間の Lv.19〜23）を測り直して調整します。

## ファイル

| ファイル | 内容 |
|---|---|
| `run.sh` | 全部まとめて実行 |
| `nn.c` | `nn selfplay`（自己対局と記録：序盤2〜8手は上位10候補からランダム、その後12手までは時々ほかのよく読まれた手、盤が分かれて数え上げで勝敗が決まったら終局）、`nn train`（学習）、`nn check`（固定局面の値：`check_net.js` で WebAssembly と照合）、`nn speed`（評価の速さ）、`nn tojs`（`net.js` の書き出し） |
| `check_net.js` | `node amazons/tools/nnue/check_net.js net.bin vals.txt`：ネイティブと wasm（SIMD・SIMD なし・core_mt.wasm）で値が全部同じか |
| `../native_match.c` | 対局（`AMZ_NET=net.bin`、`ev=3` が学習した評価） |
| `../../core.c` | 評価（`EVM 3`）・ネットの読み込み（`nn_load`）・盤が分かれた後の数え上げ |

記録の形式（1局面 32バイト）：盤 25バイト（1マス2ビット：0 空き・1 白・2 黒・3 矢）、手番 1バイト、探索の値 int16（手番から、100＝1マス）、勝敗 int8（手番から +1／−1）、手数 1バイト、予備 2バイト。
