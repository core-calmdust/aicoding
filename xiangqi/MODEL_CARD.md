# Model Card: Xiangqi engine (`engine.wasm`) and its evaluation weights (`tools/evalw.h`)

シャンチー（中国象棋）のAIは、アルファベータ探索エンジン `engine.c`（WebAssembly、ブラウザの Web Worker で実行）と、
自己対局から学習した線形の形勢評価で動いています。WebAssembly が使えない環境では `engine.js` の JavaScript 版
（同じルール、浅い探索）に切り替わります。

- **ゲーム**: https://core-calmdust.github.io/aicoding/xiangqi/
- **ライセンス**: Apache License 2.0（リポジトリの `LICENSE`）
- **バージョン**: v1（2026-10-25）

## ルール（エンジンと画面で共通）
- アジア象棋連盟（AXF）/ 世界象棋連盟（WXF）式。手番側に指せる手がなければ負け（詰みもステイルメイトも負け）。
- 帥と將の対面（間に駒のない同じ筋）は禁止。
- 同一局面3回：一方だけが王手を続けていれば（長将）その側の負け。一方だけが「追い」を続けていれば（長捉：守られていない駒、
  または価値の高い駒を、馬・車・炮・仕・相で新たにねらい続ける）その側の負け。それ以外は引き分け。
- 取りのない120手（60往復）で引き分け。双方に攻め駒（馬・車・炮・兵）がなければ引き分け。
- 探索中は「王手の繰り返しは王手をかけた側の負け、それ以外の繰り返しは引き分け」と簡略化し、画面側（`engine.js` の `judge`）が
  長捉まで含めて判定する。根の手では、繰り返しで負けになる手を除外してから探索する（`losingRepMoves`）。
- 手の生成は perft で検証済み（初期局面 深さ1〜5: 44 / 1,920 / 79,666 / 3,290,240 / 133,312,995）。

## 探索
| 項目 | 内容 |
|---|---|
| 方式 | 反復深化 PVS（principal variation search）、アスピレーション窓、置換表 2^20 エントリ |
| 枝刈り・延長 | 王手延長、ヌルムーブ枝刈り、LMR、フューチリティ／リバースフューチリティ、キラー手・ヒストリー、静止探索（取り＋王手回避） |
| 速さ | ネイティブ版 約100万局面／秒（1コア）、ブラウザ（WebAssembly）でも初期局面を1秒で深さ8前後 |
| 詰み探索 | 詰将棋用の厳密なソルバー（攻め方・受け方を交互に全幅で読む、専用置換表付き、「王手のみ」モードあり）。問題の検証と画面での答え合わせに使う |

## 形勢評価（`tools/evalw.h`）
| 項目 | 内容 |
|---|---|
| 形 | 線形モデル。駒の位置表（7種 × 左右を折りたたんだ50点）と、追加特徴15個（車・馬・炮の動ける数、空頭炮、炮台、仕・相の欠け、兵の連携、過河兵の数、帥の位置など）を、中盤用・終盤用の2組と手番ボーナスで持つ（731個の整数、単位は兵の1/8） |
| 中盤と終盤 | 盤上の車・馬・炮の量（0〜16）で2組の重みを混ぜる |
| 初期値 | 手作り（`tools/hand_evalw.py`） |
| 学習データ | このエンジン自身の自己対局 約8,200局（1手4千局面、序盤6〜9手はランダム）から取った、王手のない静かな局面 753,255 |
| 学習 | Texel 法（勝敗を sigmoid(K×評価値) で予測する二乗誤差を最小化、K = 0.0025）。numpy、Adam、`tools/tune.py`。検証用に5%を分けた。誤差 0.1051 → 0.1033 |
| 学習後の駒の価値（中盤/終盤、兵≒100） | 車 908/956、炮 426/381、馬 388/428、仕 121/138、相 124/128、兵 85/109（川を渡ると位置表で加算） |

## 詰め問題・レッスン・定跡のデータ
- **詰め問題（`puzzles.json`）**: エンジン同士の自己対局（弱いレベル同士で、詰みが生まれやすい）に現れた局面から、
  「N手以内に詰む最初の手がちょうど1つ」の局面をネイティブ版の詰みソルバーで集め（`xq mates`）、
  ページと同じ WebAssembly ソルバーでもう一度検証した（`tools/build_puzzles.js`）。同じ対局の続きの局面は1つにまとめ、
  黒番の局面は盤を180°回して赤番にそろえた。最終局面の形から「馬後炮」「重炮」「臥槽馬・掛角馬」「対面笑」「双車」に分類。
  「連将」は王手だけで詰む（王手でない手ではもっと早く詰まない）問題。PUZZLES
- **レッスン（`lessons.json`）**: 自己対局の局面のうち、最善手が他のどの手よりも兵1.5枚以上良く、しかもその手がステップの種類
  （車で取る、両取り、守る…）に当てはまる局面を自動で選んだ（`tools/gen_lessons.js`）。詰みのステップは上の検証済みの詰み
  （問題集に使っていないもの）、終盤のステップはランダムに作った終盤（車対士2つ、兵2つ）でただ1つの手だけが詰みに向かう局面。
  各問題には全部の手のエンジン評価値を入れてあり、最善に近い手には部分点が出る。
- **定跡（`openings.json`）**: 名前の付いた定跡の手順（中炮対屏風馬、飛相局、仙人指路など13種）の続きを、このエンジンが1手2秒で
  読んで20手まで伸ばした（`tools/gen_openings.js`）。続きの手は「定跡書の本手順」ではなく、このエンジンの読み。

## 限界
- 評価は線形モデルで、ニューラルネットは使っていない。学習データは自分自身の対局だけで、人間の棋譜・プロの定跡書・
  終盤データベースは使っていない。
- 長捉の判定は代表的な場合（守られていない駒、または価値の高い駒を新たにねらう手の繰り返し）だけを扱う。
  公式規則の細かい例外（兵・帥による追い、複数の駒が交互に追う場合の細目など）は完全には再現していない。
- 探索中の繰り返しは簡略化している（長捉は画面側の判定のみ）。
- 上位レベルの強さは端末の速さにも少し左右される（局面数で区切る 4級〜三段 は端末によらない。四段・五段は時間で区切る）。
