# アルケルケ 学習した評価関数（NNUE 風）の学習ツール（Mac）

アルケルケ AI（ベルのルール `alq`）の評価関数を、自己対局から学習した小さなネットワークにするための一式です。
探索はファノロナと共通の `fanorona/engine.c`（サイトの WebAssembly と同じコード）をネイティブでビルドして使います。
先生は**サイトのアルケルケ AI 自身**（手作りの評価 `alqHand()`＋取りの読み切り＋終盤DB）で、外部のエンジンは使いません。
自己対局の各局面について「読んだ評価値」と「その対局の勝敗」を記録し、読まなくても同じ判断ができるように学習させます。

## 使い方

```bash
cd ~/Documents/GitHub/aicoding
bash alquerque/tools/nnue/run.sh
```

自動で次の順に進みます（途中で止めても、もう一度同じコマンドを実行すれば続きから）。

1. ツールのビルド（`aq`：自己対局・確認・対局、`train`：学習器。どちらも C、追加のインストール不要）
2. 自己対局で学習データ作り（既定 約2000万局面、1手 1万6千局面読み。全コアを使用）。200局×コア数ごとに保存
3. 学習（10エポック、全コアで勾配を分担）
4. 確認：エンジンが学習器と同じ値を出すか（チェックサム）、今の評価関数（手作り）との対局を2通り
   （1手 2万局面固定、1手 0.1秒固定。どちらも 300開局 × 先後 = 600局）
5. 時間固定の対局で勝ち越したら採用ファイルを作って完了：`~/alquerque-nnue-work/r1/adopt/alqnet.bin.gz` と `RESULT.txt`

必要なもの：Xcode Command Line Tools（`xcode-select --install`）、空き容量 1GB ほど（2000万局面で約 480MB）。

## データを外付けディスクに置く

```bash
WORK="/Volumes/Orico A 8TB/alquerque-nnue" bash alquerque/tools/nnue/run.sh
```

途中から再開するときも同じ `WORK` を指定してください。

## 時間の目安（Mac mini M4 Pro・14コア）

| 段階 | 目安 |
|---|---|
| 自己対局（2000万局面、1手 1万6千局面読み） | 約 1〜1.5 時間 |
| 学習（約1800万局面 × 左右反転 × 10エポック、14スレッド） | 約 10〜20 分 |
| 確認の対局（局面数固定 600局＋時間固定 600局） | 約 5〜10 分 |

作業機（共用の2コア）での実測：自己対局は1コアで毎秒 約300局面（1手1万6千局面）・約570局面（8千局面）、
学習は1スレッドで1局面あたり 約30マイクロ秒（左右反転を含む）。

ほかの作業で CPU を使うときは `JOBS=8` のように同時に動かす数を絞れます。急ぐときは `POSITIONS=8000000` など。

## 設定（任意）

```bash
POSITIONS=40000000 NODES=24 JOBS=10 bash alquerque/tools/nnue/run.sh
```

| 変数 | 既定 | 内容 |
|---|---|---|
| `WORK` | `~/alquerque-nnue-work` | 作業フォルダ（データ・ネット・ログ） |
| `POSITIONS` | 20000000 | 自己対局の局面数（増やして再実行すると追加で作る） |
| `NODES` | 16 | 1手に読む局面数（千単位。多いほど教師が正確で、時間がかかる） |
| `JOBS` | 全コア | 同時に動かす数（学習のスレッド数も） |
| `EPOCHS` | 10 | 学習の周回数 |
| `LAMBDA` | 0.7 | 教師値の配分（読んだ評価値 × λ ＋ 実際の勝敗 × (1−λ)） |
| `ROUNDS` | 1 | 周回の数。2 以上にすると、前の周の採用ネットを先生にして次のデータを作り（全周のデータで学習）、前の周のネットに勝ったら採用 |
| `MATCH_PAIRS` / `MATCH_MS` / `MATCH_NODES` | 300 / 100 / 20 | 確認の対局の開局数（各2局）、時間固定の1手の時間（ミリ秒）、局面数固定の1手の局面数（千） |
| `OPENV` | 300 | 確認の対局の開局（2〜10手ランダム）の偏りの上限（手作り評価で駒3枚分）。平らな開局からは、同じくらいの強さのエンジン同士はほぼ全部引き分けになるため、少し偏った開局を先後入れ替えで2回指す |
| `BASE_AQV` | 11 | 両者の探索の設定（`engine.c` の AQV。11 がサイトの今のエンジン。ネットの側は +16） |
| `EXTRA` | なし | 学習器への追加オプション（例 `EXTRA="--lr 0.0005 --batch 2048"`） |

周回（ネットで次のデータを作る）の例：1周目が終わったあとで

```bash
ROUNDS=2 bash alquerque/tools/nnue/run.sh
```

1周目はそのまま（終わっていれば飛ばして）、`r2/` に2周目のデータ・ネット・採用ファイルを作ります。

## 終わったら

`$WORK/r<最後の周>/adopt/` の `alqnet.bin.gz` と `RESULT.txt` を Claude に渡してください。
`fanorona/alqnet.bin.gz` に置き、`fanorona/engine.js` の `ALQ_NETV` に版（例 `'1'`）を入れるだけで有効になります
（空の間は今まで通りの手作り評価）。使うのは時間で考えるレベル（四段・五段）、局面数の制限のない PRO、分析・ヒント・コーチです。
局面数で決まるレベル（4級〜三段）と深さで決まるレベル（15級〜5級）は今まで通り（下のレベルが強くならない）。

## 採用の基準

- エンジンがネットを学習器と同じ値で読む（`RESULT.txt` の「the same values as the trainer」）。
- 同じ持ち時間（1手 0.1秒）の対局で相手（1周目は手作り評価、2周目以降は前の周の採用ネット）に勝ち越し、
  勝率の片側 95% の下限が 50% を超える（`RESULT.txt` の `-> adopt`）。局面数固定の結果は参考。
- サイトに入れる前に、Claude が WebAssembly（`engine.wasm`・`engine_simd.wasm`・`engine_mt.wasm`）で同じ値になることを
  `node alquerque/tools/nnue/wasmcheck.js <net> <data>` で確かめ、ブラウザで対局・分析を確認し、レベル表（四段・五段の目安）を測り直す。

## ファイル

| ファイル | 内容 |
|---|---|
| `run.sh` | 全部まとめて実行 |
| `aq.c` | `aq datagen`（自己対局と記録：序盤 2〜9手はランダム、途中 2% もランダムな手）、`aq match`（対局）、`aq check`（ネットの値のチェックサム）、`aq stat`（静的評価が勝敗をどれだけ当てるか）、`aq probe`（決まった局面の読み）、`aq bench`（速さ） |
| `train.c` | 学習器（入力は2視点 × 100：自駒25＋相手駒25＋相手に跳ばれうる自駒25＋自分が跳べる相手駒25。各視点で盤を「自分が上へ進む」向きにそろえる → 64 ×2 → 16 → 1、clipped ReLU。左右反転の局面も学習） |
| `wasmcheck.js` | WebAssembly の3つのビルドでネットの値・読みがネイティブと一致するかの確認（Node） |

記録の形式（1局面 24バイト）：白の駒 u64、黒の駒 u64（点は r×9+c）、読んだ評価値 i16（手番側から）、取りのない手数 u8、予備 u8、
結果 i8（手番側から +1/0/−1）、手番 u8、印 u8（1 = 評価値が勝ち負けの確定値、2 = 手番側に取りがない）、予備 u8。

ネットのファイル（`AQN1`、17,140 バイト、gzip 後 約10KB）：`AQN1`、u16 入力数 100・隠れ層 64・16・0、i32 K（評価の尺度：手作り評価と同じ単位に戻す係数）、
続いて int16 W1・B1・W2、int32 B2、int16 W3、int32 B3（すべて整数・リトルエンディアン。WebAssembly とネイティブで同じ値になる）。
