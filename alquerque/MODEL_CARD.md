# Model Card: アルケルケ AI（探索と学習した評価関数 `alqnet.bin.gz`）

アルケルケの AI は、ファノロナと共通の探索エンジン `fanorona/engine.c`（WebAssembly：`engine.wasm`・`engine_simd.wasm`、
複数スレッドの `engine_mt.wasm`＝Praline の YBW）をルール `alq`（ベル式）／`alqf`（アルフォンソ式）で動かしています。
評価は今は**手作りの評価 `alqHand()`**（駒数・点の強さ・動ける数・跳ばれうる駒）で、
**学習した評価関数（小さな整数ネット）の仕組み**を 2026-11-20 に入れました（ネットの学習本番はこれから。下の「Mac での学習」）。

- **ゲーム**: https://core-calmdust.github.io/aicoding/alquerque/
- **バージョン**: 2026-11-20。学習した評価：ネット未配置（`fanorona/engine.js` の `ALQ_NETV` が空＝手作り評価）
- 仕様の詳細：`claude/alquerque-spec.md`「学習した評価関数と探索の検討」、ファノロナ側は `claude/fanorona-spec.md`

## 探索（ファノロナと共通）
αβ（PVS・アスピレーション窓・置換表・キラー手・ヒストリー・パイカ＝取りのない手の LMR）。アルケルケ固有：
- 取りは義務で、跳べる限り続ける（生成するのは最後まで跳んだ連続取りだけ）。
- 取りの静止探索は立ち止まり（stand pat）なしで読み切る（取りが義務なので、取ることで負ける局面がある。深さ −14 まで）。
- 合法手が1つの局面は1手延長。終盤DB（`alqeg.bin.gz`、駒6枚まで・片側4枚まで、手数つきの勝ち負け）。
- 同一局面の繰り返し・取りのない80手は引き分け。

## 使う所
| レベル・機能 | 評価 |
|---|---|
| 15級〜5級（深さで決まる、`values()`） | 2026-10 の簡単な評価（`AQV` 0、変えない） |
| 4級〜三段（局面数で決まる） | 手作り `alqHand()`（`AQV` 11、変えない） |
| 四段・五段（1.2秒・3秒）、PRO（局面数の制限なし）、分析・ヒント・コーチ・検討 | **学習した評価（ネットがあれば、`AQV` 27）**、なければ手作り |

下のレベルの強さは変えません（ネットを入れても 4級〜三段は同じ手・同じ局面数）。
ネットのない今は全レベル・全機能で前と同じ手を指します（下の「ファノロナと今のアルケルケが変わらないこと」）。

## 学習した評価関数（仕組み）
| 項目 | 内容 |
|---|---|
| 入力 | 2視点 × 100：自分の駒25＋相手の駒25＋相手が今跳べる自分の駒25＋自分が今跳べる相手の駒25。各視点で盤を「その側が上へ進む」向きにそろえる（ベル式は前と横にしか進めず、白黒で対称でないため） |
| 構造 | 100 → 64（2視点、手番側が先）→ clipped ReLU → 16 → clipped ReLU → 1 |
| 数値 | すべて整数（int16 の1層目、int32 の和）。WebAssembly（SIMD あり・なし・マルチスレッド）とネイティブで同じ値。葉ごとに全体を計算（差分更新なし：この探索の葉は取りのない局面だけで、全体を計算しても手作り評価の約9割の速さ） |
| 出力 | ロジット × K（K はデータから求める評価の尺度。手作り評価と同じ単位＝駒1枚 約100 になり、探索の窓・幅がそのまま使える） |
| ファイル | `AQN1`（17,140 バイト、gzip 後 約9KB）。`fanorona/alqnet.bin.gz` に置き、`fanorona/engine.js` の `ALQ_NETV` に版を入れると有効（アルケルケのページ・3D・ちゃぶ台の AI。ファノロナのページは読まない） |
| 学習データ | このエンジン自身の自己対局（手作り評価、序盤 2〜9手ランダム・途中 2% ランダム）。外部のエンジンは使わない。使うのは手番側に取りのない局面（探索の葉と同じ種類） |
| 教師 | 0.7 × σ(探索値 / K) ＋ 0.3 × 勝敗（終盤DBの確定値は勝ち＝1・負け＝0）。左右反転の局面も学習 |
| 学習器 | `tools/nnue/train.c`（C、Adam、全コアで勾配を分担、検証用 3%） |

### Texel 調整が負けた理由（考察）とネットの設計
2026-11-14 の Texel 調整（`alqHand` の14項目の重みを勝敗に合わせる）は同じ時間で −37 Elo だった（`claude/fanorona-spec.md`）。
- **速さではない**：Texel の評価は前と同じ項目・同じ速さ。ネットも手作りの約9割の速さで勝ち越すので、速さは決め手ではない。
- **特徴の不足と、合わせる目標**：勝敗だけ（λ=0）に線形の重みを合わせると、「勝った側は前へ進んでいる」のような**結果と一緒に起きること**
  （端からの行 2 → 24、最後の行 +33）を学んでしまう。アルケルケは後ろへ戻れないので、前へ進むほど後で動ける手（待ちの手）が減り、むしろ損になる。
  引き分けが約半分で勝敗の信号が弱いことも重なる。
- 作業機での比較（ネットの学習に使っていない約8万局面、勝敗の交差エントロピー、小さいほど良い）：手作り `alqHand` 0.619、
  仮ネット（読まずに）0.580、先生の探索値（8千局面読み）0.557。駒の配置の組み合わせ（どの駒がどこから跳ばれるか）を
  非線形に扱えるネットは、読まない値でも探索値に近づく。
- そこで：教師は**探索値が主**（λ=0.7）、入力に**今跳ばれうる駒**（手作り評価の「跳ばれうる駒」に当たる、取りが義務のゲームで最も大事な形）を足し、
  盤の向きを手番側にそろえて前後の非対称を素直に表す。

### 作業機での仮ネットの確認（採用しない）
作業機（共用の2コア、他の作業と同時）で自己対局（1手8千局面）の小さなデータから作った仮ネット。**サイトには置いていません**（学習本番は Mac）。
対局は `tools/nnue/aq match`（ネイティブ、同じエンジンでネットのあり・なしだけが違う、手作り評価の側も同じ探索）。
開局は 2〜10手ランダムで偏り 駒3枚分まで、先後入れ替えで2局ずつ（平らな開局からは同じくらいの強さのエンジン同士がほぼ全部引き分けになるため）。

| 仮ネット（学習局面） | 条件 | 結果（ネット側） | Elo（95%区間） |
|---|---|---|---|
| A（約18万） | 1手 50ミリ秒、120局 | +42 −25 =53 | +50（+4〜+97） |
| A（約18万） | 1手 2万局面、120局 | +44 −22 =54 | +64（+19〜+112） |
| B（約26万） | 1手 50ミリ秒、200局 | +74 −45 =81 | +51（+14〜+89） |
| C（約38万） | 1手 100ミリ秒、200局 | +79 −52 =69 | +47（+8〜+87） |

| 確認 | 結果 |
|---|---|
| 学習器の整数ネットとエンジン（ネイティブ）の値 | 10万局面のチェックサムが一致 |
| WebAssembly（`engine.wasm`・`engine_simd.wasm`・`engine_mt.wasm` の1スレッド）の値 | 10万局面のチェックサムがネイティブと一致（`tools/nnue/wasmcheck.js`） |
| 2万局面の読み（20局面、表は空から） | `engine.wasm` と `engine_simd.wasm` がネイティブ（同じ表の大きさ）と手・値・深さまで一致、`engine_mt.wasm` は手が 20/20 一致 |
| `engine_mt.wasm` の2スレッド（Node の worker_threads、YBW の補助） | ネットありで 8/8 局面を読んで手を返す |
| ブラウザ（headless Chrome、仮ネットを一時的に置いて） | 1スレッドのワーカー（四段で深さ10、五段で深さ14）・ページの組（`engine_mt.wasm`、補助つき）ともネットを読んで対局、エラーなし |
| 速さ（ネイティブ、30万局面×24局面） | 手作り 約94万／ネット 約82万〜89万 局面毎秒（約9割） |

小さなデータでも +50 Elo 前後なので、Mac の本番（約2000万局面、1手1万6千局面読み）のネットは四段・五段と分析を強くする見込み。

## 探索の検討（採用せず）
四段・五段・分析にだけ効く形で試し、どれも勝ち越さなかったので入れていない（`engine.c` からも外した）。
| 試したもの | 結果 |
|---|---|
| 取りのない葉で自分の駒が跳ばれうるときに1手読み足す（取りが義務なので脅しが本物） | 1手 50ミリ秒 120局 +32 −39 =49（−20、−69〜+27） |
| 相手に取りを与えないパイカを先に、取りを与える手（相手に跳ばせる手）は LMR で減らさない | 1手 2万局面 400局 +1 −10 =189（平らな開局） |
| LMR なし | 1手 50ミリ秒 120局 +40 −38 =42（+6、−45〜+56） |
| LMR を強める（2手目から、深さ5以上で2） | 1手 50ミリ秒 120局 +37 −37 =46（±0） |
| 取りの静止探索の結果も置換表へ | 30万局面で読める深さ 7.12 → 7.17 だけ |

ファノロナの探索 v2・Texel と同じく、取りが義務で連続取りの読みがほとんどを決めるゲームでは、読む手の選び方を変えても強さはほとんど変わらない。
強くなるのは評価（上の仮ネットで +50）。

## 終盤DBの拡張（見送り）
今の `alqeg.bin.gz` は駒6枚まで（片側4枚まで）、展開 1.8MB・ダウンロード 0.47MB。
7枚（片側4枚まで）を足すと展開 約34MB・gzip で 約9MB と見込まれ、ダウンロードが約20倍になる。
自己対局の局面では、6枚までの DB で探索がすでに 7〜8枚の局面の約5割を確定値で読み切っていて、7枚の DB で増える分は小さい。
片側5枚以上を含めるとさらに大きい。今は入れない（入れるなら勝敗だけの2ビットの表を分析・強いレベルだけ遅れて読む形を検討）。

## ファノロナと今のアルケルケが変わらないこと
`engine.c` の変更はアルケルケのネット（`AQV & 16` のときだけ）と `set_aqv`・`aqn_*` の追加だけ。
- ネイティブ：前の `engine.c` と新しい `engine.c` で、ツィヴィ（学習評価・終盤DBあり）・ディミ・アルケルケ（AQV 11）・アルフォンソ式の
  各25局面の `best()`（3万局面）・`values()`・`analyze()` の出力が全部一致。
- WebAssembly：前の配信版と新しい `engine.wasm`・`engine_simd.wasm`・`engine_mt.wasm`（1スレッド）で、4ルールの102局面の
  `best()`（4万局面）・`values()` の手・値・深さ・局面数が全部一致。

## 推論の高速化（2026-11-20、値は同じ）

- **wasm SIMD の `aqnEval`**（`fanorona/engine.c`）：1層目の和を i16x8 のレーンで（前の int16 の足し算と同じ折り返し）、0〜127 に切り、2層目の 16 個の和を `i32x4.dot_i16x8` で（整数なので同じ）。`engine.wasm`（SIMD なし）とネイティブは前のまま（バイナリも同じ）。ファノロナの評価には触れていない。
- **確認**：`tools/nnue/wasmcheck.js`（仮ネット：engine.wasm・engine_simd.wasm・engine_mt.wasm のネットの値のチェックサムがネイティブ `aq check` と一致、2万局面の探索が一致、engine_mt.wasm 2スレッドがネットで動作）、旧版と新版の engine_simd.wasm の探索（20局面×3、20万局面）がネットあり・なしで一致、ブラウザ（headless Chrome、仮ネットを置いて）で1スレッド・マルチスレッドとも四段がネットで動作。
- **速さ**（engine_simd.wasm、同じ探索を旧・新交互に同じプロセスで、CPU 時間）：ネットあり **約+27〜31%**（ネットなしの約 0.68 倍 → 0.88 倍）。ネットなし・SIMD なしは同じ。時間固定の対局は今回は測っていない。

## Mac での学習（`alquerque/tools/nnue/`）
```bash
bash alquerque/tools/nnue/run.sh                                         # 既定：約2000万局面、1手1万6千局面読み
WORK="/Volumes/Orico A 8TB/alquerque-nnue" bash alquerque/tools/nnue/run.sh   # データを外付けに
ROUNDS=2 bash alquerque/tools/nnue/run.sh                                # 2周目（1周目のネットを先生に）
```
ビルド → 全コアで自己対局 → 学習 → 確認（エンジンが同じ値で読むか、手作り評価との対局：1手2万局面と1手0.1秒の各600局）→ 採用ファイル（`$WORK/r1/adopt/`）。
途中で止めても続きから。時間の目安（M4 Pro 14コア）：自己対局 約1〜1.5時間、学習 約10〜20分、確認 約5〜10分。手順の詳細は `tools/nnue/README.md`。

## 採用の基準
1. エンジンがネットを学習器と同じ値で読む（`RESULT.txt`）。
2. 同じ持ち時間（1手 0.1秒）で今の評価（1周目は手作り、2周目以降は前のネット）に 600局で勝ち越し、勝率の片側95%の下限が 50% を超える（`-> adopt`）。
3. サイトに入れる前に `node alquerque/tools/nnue/wasmcheck.js <net> <data>` で WebAssembly の値の一致を確かめ、ブラウザで対局・分析を確認する。
   四段・五段の強さが変わるので、大百科のレベルの目安（`atlas/app.js` の RATING の alquerque、四段＝2355・五段＝2500）を対局で測り直し、
   三段との間が開きすぎるなら四段・五段の時間で調整する（4級〜三段は変わらない）。トップページの紹介文に「NNUE搭載」と学習量を書く（共通ルール）。
