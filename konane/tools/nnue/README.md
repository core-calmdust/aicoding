# コナネの学習した評価関数（NNUE）を Mac で作る

コナネの AI（`konane/core.c`）に、盤の大きさごとの小さなネット（`net-s8.bin.gz`・`net-s10.bin.gz`・`net-s6.bin.gz`）を学習させる道具です。
先生はこのエンジン自身（探索 v3・手作り評価）だけで、外部のエンジンや棋譜は使いません。仕組みと採用の基準は `konane/MODEL_CARD.md`、
仕様は `claude/konane-spec.md`「学習した評価」。

## 1. いちばん簡単な使い方

ターミナルでリポジトリのフォルダに移って、1行だけ実行します（Xcode のコマンドラインツールの `cc` があれば動きます）。

```bash
bash konane/tools/nnue/run.sh
```

ビルド → 全コアで自己対局（既定 約2000万局面）→ 学習（3つの盤を同時に）→ 確認 → 採用ファイルの作成、まで自動で進みます。
途中で止めても（Ctrl-C、Mac の再起動）、同じコマンドでもう一度実行すれば続きから進みます（自己対局は40局ずつの区切りで保存、学習済み・確認済みの盤は飛ばす）。

### データを外付けディスクに置く

```bash
WORK="/Volumes/Orico A 8TB/konane-nnue" bash konane/tools/nnue/run.sh
```

置き場所（`WORK`）の既定は `~/konane-nnue-work`。1局面 40バイトなので、2000万局面で約 0.8GB です。

### 2周目（1周目のネットを先生にする）

```bash
ROUNDS=2 bash konane/tools/nnue/run.sh
```

1周目が済んでいれば2周目だけ進みます。2周目の先生は1周目に採用されたネット、比べる相手も1周目のネットです（データは1周目の分も合わせて学習）。

## 2. 設定（環境変数）

| 変数 | 既定 | 意味 |
|---|---|---|
| `WORK` | `~/konane-nnue-work` | すべての置き場所 |
| `POSITIONS` | 20000000 | 自己対局の局面数の合計 |
| `SHARE` | `"s8:50 s10:30 s6:20"` | 盤ごとの割合（%）。8×8 だけなら `SHARE="s8:100"` |
| `NODES` | 8 | 自己対局の1手の読み（千局面） |
| `JOBS` | 全コア | 同時に動かすプロセスの数 |
| `EPOCHS` | 10 | 学習の回数（データ全体を何回なめるか） |
| `LAMBDA` | 0.7 | 教師 = 探索値 × λ ＋ 勝敗 × (1 − λ) |
| `ROUNDS` | 1 | 周回 |
| `MATCH_GAMES` / `MATCH_MS` | 200 / 100 | 確認の対局数（盤ごと）と1手の時間（ミリ秒） |

## 3. 時間の目安（Mac mini M4 Pro 14コア・64GB の見積もり）

| 段階 | 目安 |
|---|---|
| 自己対局（2000万局面、1手8千局面） | 約2〜4時間 |
| 学習（3つの盤を同時に、10エポック） | 約30〜60分（いちばん大きい 8×8 の 1000万局面しだい） |
| 確認（差分更新の検査＋盤ごとに200局、1手0.1秒） | 約15〜25分 |

作業機（共用2コア）での実測：自己対局は1プロセス 約120局面／秒（1手5千局面）。Mac は1コアがこの2〜3倍、14プロセスで動くので上の見当です。
2周目の自己対局はネットの評価の分だけ遅くなります（1.3〜2倍）。

## 4. 終わったら

最後に次のように出ます。

```
done. The nets to adopt: …/r1/adopt/net-<rule>.bin.gz, the results: …/r1/adopt/RESULT.txt
```

`adopt` フォルダ（`net-*.bin.gz` と `RESULT.txt`）と、`r1/train-*.log` の最後の数行を Claude に渡してください。
`RESULT.txt` の各行の末尾が `-> adopt` の盤だけが採用候補です（`-> not adopted` は今の評価に勝ち越せなかった盤）。

サイトに入れるとき（Claude の作業）：`konane/net-<rule>.bin.gz` に置き、`konane/engine.js` の `NETV` にその盤の版を書く → WebAssembly（1スレッド・core_mt.wasm）で読み込みと対局を確認 →
Lv.21〜23 の基準値（app.js の `RT_LV`、大百科の RATING）を測り直す → トップページの紹介文に「NNUE搭載」と学習量（14言語）。

## 5. ファイル

| ファイル | 役目 |
|---|---|
| `run.sh` | 全部を順に動かす |
| `kn.c` ＋ `eng.c` | ネイティブの道具（`../../core.c` をそのままネイティブにビルド）。`kn datagen`（自己対局）・`kn match`（対局）・`kn nncheck`（差分更新と学習器の値の一致）・`kn bench`（速さ） |
| `train.c` | 学習器（C、1スレッド、Adam）。整数のネット `KNN1` を書き出す |
| `nnfeat.h` | 入力の作り方と整数のネットの計算（学習器と `kn nncheck` で共通、core.c と同じ値） |

手で動かす例（`$WORK/bin` に `kn` と `train` ができています）：

```bash
kn match s8 100 1 2/0/100/net-s8.bin 2/0/100/-     # ネット 対 手作り評価、1手0.1秒、100局
kn bench s8 2/0/1000/-                              # 探索 v3 の速さ
```
